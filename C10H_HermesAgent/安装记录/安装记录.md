## 2. 安装路线：先官方，后手动

### 2.1 尝试 A：官方 Windows 安装器（失败，但保留了大部分成果）

官方命令是：

```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

我先把脚本落盘再执行，便于审计：

```powershell
(Invoke-WebRequest -Uri https://hermes-agent.nousresearch.com/install.ps1 -UseBasicParsing).Content |
  Out-File -FilePath E:\我的挑战\_install_hermes.ps1 -Encoding utf8
```

**失败 1：执行策略禁止运行脚本**

```
无法加载文件 E:\我的挑战\_install_hermes.ps1，因为在此系统上禁止运行脚本。
```

修复：不落地执行，直接在当前进程用脚本块运行（等价于官方 `iex`）：

```powershell
$code = Get-Content -Raw -LiteralPath 'E:\我的挑战\_install_hermes.ps1'
& ([scriptblock]::Create($code)) -InstallDir 'E:\hermes\hermes-agent' -HermesHome 'E:\hermes' -NonInteractive
```

这一次安装器成功完成了：

- 下载并解压 **pinned Git 2.56.1**（`E:\hermes\tools\git-2.56.1+1-win32-x64`）；
- 下载 **uv 0.13.5**（`E:\hermes\tools\uv-0.13.5-win32-x64`）；
- 以 `--filter=blob:none` 克隆 `NousResearch/hermes-agent`；
- 检出稳定版 **v0.23.1**。

然后卡在：

```
-> Downloading Python 3.14
```

**失败 2：`uv python install` 卡死（GitHub API 403）**

观察到的证据：

- `uv.exe` 进程已建立 TCP 连接但 12 分钟无下载字节；
- `uv python install --no-bin --no-registry cpython-3.14-windows-x86_64-none` 手工重试同样卡住；
- 随后 `hermes --version` 直接报 `Could not resolve the stable source release: HTTP Error 403: rate limit exceeded`，说明本机出口 IP 的 GitHub API 配额已耗尽；
- 临时目录里没有出现任何 Python 压缩包，说明不是「下载慢」，而是**解析阶段就失败了**。

> 这不是 Hermes 的 bug，而是网络环境问题。官方脚本没有为「GitHub API 403」设计降级路径。

### 2.2 尝试 B：手动 venv + 镜像（成功）

既然源码已经在本地，就按官方「Manual / Developer Installation」思路走，但用系统 Python 3.14：

```powershell
$py = 'C:\Users\Administrator\AppData\Local\Programs\Python\Python314\python.exe'
& E:\hermes\tools\uv-0.13.5-win32-x64\uv.exe venv --python $py E:\hermes\hermes-agent\.venv
```

**失败 3：`uv pip install -e .` 依赖冲突**

```
Because browser-harness>=0.1.13 depends on pillow==12.3.0 and hermes-agent==0.0.0
depends on browser-harness==0.1.13, we can conclude that hermes-agent==0.0.0 and
pillow==13.0.0 are incompatible.
```

根因：`pyproject.toml` 里 `pillow==13.0.0`，而 `browser-harness==0.1.13` 声明 `pillow==12.3.0`。上游锁文件能解，重新解析就冲突。

**失败 4：`uv sync --frozen` 卡在 files.pythonhosted.org**

锁文件里的 wheel URL 被固定到 `files.pythonhosted.org`，国内直连几乎不动（TCP 已建立但长期 0 字节）。设置 `UV_DEFAULT_INDEX` 对锁文件中的绝对 URL 无效。

最终解：**镜像重新解析 + 只覆盖冲突的 pillow**：

```powershell
$env:UV_INDEX_URL='https://pypi.tuna.tsinghua.edu.cn/simple'
$env:UV_HTTP_TIMEOUT='120'
"pillow==12.3.0" | Set-Content E:\我的挑战\_overrides.txt -Encoding ascii

& E:\hermes\tools\uv-0.13.5-win32-x64\uv.exe pip install `
    --python E:\hermes\hermes-agent\.venv\Scripts\python.exe `
    -e E:\hermes\hermes-agent `
    --override E:\我的挑战\_overrides.txt `
    --index-strategy unsafe-best-match
```

结果：`Resolved 76 packages`，约 1 分钟装完，`hermes.exe` / `hermes-agent.exe` / `hermes-acp.exe` 三个入口生成。

```powershell
$env:HERMES_HOME='E:\hermes'
E:\hermes\hermes-agent\.venv\Scripts\hermes.exe --version
# Hermes Agent v0.23.1 (2026.9.24) · stable · local 3b4215785882
```

### 2.3 运行时自举：Hermes 自己补齐了剩下的部分

第一次执行 `hermes chat` 时，Hermes 检测到「源码安装 + 依赖已更新」，自动做了一次 source-update：

- 用 PM 安装 **Python 3.14.9** 独立运行时（`E:\hermes\installs\9249f73cb9b5d199\...\venv`）；
- 安装 **Node 26.12.1**、ripgrep、FFmpeg；
- 构建 TUI 与 Web UI；
- 同步 **44 个 bundled skills**；
- 把 config 从 v0 迁移到 **v53**；
- 安装 **Chromium 1208** 与 cua-driver。

这一步把「手动 venv」升级成了官方 PM 运行时，后续 `hermes` 实际跑在 `E:\hermes\installs\...\venv` 里（`hermes doctor` 会显示）。

## 4. 九次真实故障与修复

| # | 症状 | 根因 | 修复 | 验证 |
| --- | --- | --- | --- | --- |
| 1 | `.ps1` 无法加载 | PowerShell 执行策略 | `[scriptblock]::Create()` 在当前进程执行 | 安装器正常启动 |
| 2 | `uv python install` 12 分钟无进度 | GitHub API 403（IP 配额） | 放弃托管 Python，改用系统 3.14.2 | `hermes --version` 可运行 |
| 3 | pillow 版本冲突 | 上游 pin 不一致 | `--override pillow==12.3.0` | 76 包解析成功 |
| 4 | `uv sync --frozen` 0 字节 | 锁文件固定 pythonhosted URL | 清华镜像 + 重新解析 | 1 分钟装完 |
| 5 | `Gateway inaccessible: windows_breakaway_unavailable` | DSH/终端把子进程放进禁止 breakaway 的 Job Object | 前台另起 `hermes gateway run`，CLI 连接已有网关 | `hermes gateway status` ✓ |
| 6 | `read_file` 报 `No shell found` | PM 未登记 Git Bash，系统 bash 不在 PATH | `.env` 设 `HERMES_GIT_BASH_PATH` 指向 pinned Git 的 `usr\bin\bash.exe`，重启网关 | `read_file` 返回文件内容 |
| 7 | `execute_code` 被拒绝 | 单查询模式无人批准任意 Python | 显式 `-t file,terminal`，prompt 禁止 execute_code | demo 01 成功 |
| 8 | 模型声称「已写入」但文件不存在 | 小模型幻觉，没有真正调用 `write_file` | prompt 强制「写完必须 read_file 回读并引用一行」 | demo 01 真实写盘 |
| 9 | `hermes config set` 无输出挂起 | CLI 在等网关/更新检查（非交互环境） | 直接写 `config.yaml`，用 `doctor` 校验 v53 | `doctor` 配置项全绿 |

> 故障 5 的细节值得单独说：Hermes 的 CLI 把每个交互会话当作「网关会话」，需要启动一个能脱离父 Job 的守护进程。DSH 的执行环境禁止 `CREATE_BREAKAWAY_FROM_JOB`，所以 `chat` 直接拒绝。**前台 `gateway run` + 客户端连接**是官方文档里的等价路径，不需要改代码。

## 7. 回滚 / 卸载

```powershell
# 停网关
E:\hermes\bin\hermes.exe gateway stop
# 可选：卸载 PM 工具与运行时
E:\hermes\bin\hermes.exe uninstall --yes
```

如果只想回滚到「干净源码」：删除 `E:\hermes\hermes-agent\.venv`，重新按 2.2 节建 venv 即可；`E:\hermes` 下的 `memories/`、`skills/`、`state.db` 是用户数据，不与程序版本绑定。

## 8. 可复现性声明

- 本记录中的每条命令都在本机实际执行过，输出保留在 `证据/` 与 `demo/transcripts/`。
- 依赖 GitHub API 的步骤（官方安装器的 Python 下载、`hermes update`）在受限网络下不可复现，替代路径已在 2.2 节给出。
- 镜像版本会变化；如果清华镜像失效，把 `UV_INDEX_URL` 换成阿里云 `https://mirrors.aliyun.com/pypi/simple/` 即可，其余步骤不变。
- 模型可替换：任何支持 tool calling 的 Ollama 模型都能复用本配置，只需改 `model.default` 与 Modelfile 的 `num_ctx`。
