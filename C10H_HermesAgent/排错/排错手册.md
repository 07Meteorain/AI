# 排错手册：Hermes Agent on Windows

> 收录本次安装/配置/运行中真实遇到的 10 个故障。每条形如：
> **症状 → 诊断 → 根因 → 修复 → 预防**。
> 所有命令都在本机验证过；路径按 `HERMES_HOME=E:\hermes` 书写。

---

## 速查表

| # | 症状关键词 | 一句话修复 |
| --- | --- | --- |
| 1 | `禁止运行脚本` | 用 scriptblock 跑，不改执行策略 |
| 2 | `uv python install` 卡住 / 403 | 用系统 Python 建 venv |

## 1. 执行策略禁止运行安装脚本

**症状**

```
无法加载文件 ...\install.ps1，因为在此系统上禁止运行脚本。
```

**诊断**

```powershell
Get-ExecutionPolicy -List
```

**根因**：Windows 默认 `Restricted`/`AllSigned`，`.ps1` 不能直接运行。

**修复**（不改系统策略）：

```powershell
$code = Get-Content -Raw -LiteralPath '.\install.ps1'
& ([scriptblock]::Create($code)) -InstallDir 'E:\hermes\hermes-agent' -HermesHome 'E:\hermes' -NonInteractive
```

**预防**：优先用官方 `iex (irm ...)` 形式；落盘脚本只用于审计，不直接 `&`。

## 2. `uv python install` 长时间无进度

**症状**

- `uv.exe` 有 TCP 连接，但 10+ 分钟无下载字节；
- 临时目录没有 `.tar.gz`；
- `hermes --version` 报 `HTTP Error 403: rate limit exceeded`。

**诊断**

```powershell
Get-CimInstance Win32_Process -Filter "Name='uv.exe'" | Select-Object CommandLine
# 看到 python install --no-bin --no-registry cpython-3.14-windows-x86_64-none
```

**根因**：uv 需要通过 GitHub API 解析 python-build-standalone 的最新 release；出口 IP 配额耗尽 → 403 → 重试循环。

**修复**：放弃托管 Python，用系统 Python 3.14 建 venv（见安装记录 2.2）。

**预防**：安装前跑一次 `Invoke-WebRequest https://api.github.com/rate_limit`；403 就直接走手动路径。

---

## 3. 依赖解析冲突（pillow）

**症状**

```
Because browser-harness>=0.1.13 depends on pillow==12.3.0 and hermes-agent==0.0.0
depends on browser-harness==0.1.13 ... pillow==13.0.0 ... incompatible
```

**根因**：上游两个包对 pillow 的精确 pin 不一致；锁文件能解，重新解析就冲突。

**修复**

```powershell
"pillow==12.3.0" | Set-Content .\overrides.txt -Encoding ascii
uv pip install -e . --override .\overrides.txt --index-strategy unsafe-best-match
```

**预防**：优先 `uv sync --frozen`；只有锁文件不可用时才重新解析，并准备 override。

## 4. `uv sync --frozen` 卡在 files.pythonhosted.org

**症状**：进程有连接、CPU 几乎为 0、venv 一直是 0.5 MB。

**根因**：`uv.lock` 把每个 wheel 的 URL 固定到 `files.pythonhosted.org`；设 `UV_DEFAULT_INDEX` 对绝对 URL 无效。

**修复**

```powershell
$env:UV_INDEX_URL='https://pypi.tuna.tsinghua.edu.cn/simple'
uv pip install -e . --override .\overrides.txt
```

**预防**：受限网络下不要用 `--frozen`；用镜像重新解析，并记录 override。

## 5. `Gateway inaccessible: windows_breakaway_unavailable`

**症状**

```
Hermes couldn't start the model connection: Gateway inaccessible:
windows_breakaway_unavailable. Your message was not sent.
```

**诊断**

```powershell
hermes gateway status          # ✗ Gateway is not running
```

**根因**：Hermes CLI 把会话当作网关会话，需要启动一个能脱离父 Job Object 的守护进程；DSH/终端把子进程放进禁止 `CREATE_BREAKAWAY_FROM_JOB` 的 Job，`Popen` 被拒绝。

**修复**：在**另一个前台进程**里启动网关，CLI 会自动连接：

```powershell
$env:HERMES_HOME='E:\hermes'
hermes gateway run          # 保持这个窗口
# 另开窗口
hermes gateway status       # ✓ running
hermes chat -q "..."
```

长期方案：

```powershell
hermes gateway install      # 安装成 Windows 计划任务
```

**预防**：在受限终端里，不要依赖 CLI 自动拉起网关；先 `gateway status`，没有就手动 `run`。

## 6. `read_file` 报 `No shell found`

**症状**

```json
{"error": "No shell found. Hermes needs bash (Git for Windows on Windows). Run `hermes pm install` or reinstall the bundle."}
```

**根因**：Hermes 的 file 工具通过 bash 执行；PM 没把 Git 登记进 store，系统 PATH 里也没有可用的 `bash.exe`（System32 的 `bash.exe` 是 WSL 存根，会被排除）。

**修复**：在 `.env` 指定 pinned Git 的 bash，然后**重启网关**：

```dotenv
HERMES_GIT_BASH_PATH=E:\hermes\tools\git-2.56.1+1-win32-x64\usr\bin\bash.exe
```

```powershell
hermes gateway stop
hermes gateway run
```

验证：

```powershell
& 'E:\hermes\tools\git-2.56.1+1-win32-x64\usr\bin\bash.exe' -c "echo ok"
```

**预防**：Windows 原生安装后，第一件事就是验证 `read_file` 能读一个文本文件。

## 7. 单查询模式禁止 `execute_code`

**症状**

```json
{"status":"error","error":"BLOCKED: execute_code runs arbitrary local Python ... Single-query mode (-q) runs without a user present to approve it."}
```

**根因**：Hermes 的安全设计——无人值守时不允许任意 Python 绕过命令审批。

**修复**：

```powershell
hermes chat --query-file prompt.md -t file,terminal --format stream-json
```

并在 prompt 里写明「禁止 execute_code；写文件用 write_file」。

**预防**：脚本化调用时始终显式 `-t`，把工具面收敛到任务需要的最小集。

## 8. 模型声称「已写入」但文件不存在

**症状**：回复说「已写入 out/summary.md」，磁盘上没有 `out/` 目录；JSONL 里只有 `execute_code` 失败的记录，没有 `write_file`。

**根因**：小模型（<30B）常见幻觉；它把「计划」当成「已完成」。

**修复**：prompt 加三条硬约束：

1. 必须真实调用 `write_file`；
2. 写完后必须 `read_file` 回读，并引用其中一行；
3. 没有 `tool_use` 记录时不允许声称成功。

**预防**：任何写操作都配一次回读；把回读结果作为交付证据。

---

## 9. `hermes config set` 无输出挂起

**症状**：命令 3 分钟没有任何输出，也不退出。

**诊断**：非交互终端里 CLI 可能等待网关/更新检查；先 `hermes gateway status`。

**修复**：直接编辑 `E:\hermes\config.yaml`，然后：

```powershell
hermes config check
hermes doctor
```

**预防**：批量配置用文件 + `doctor` 校验；交互命令只在 TTY 里用。

---

## 10. 中文乱码 / JSONL 编码不一致

**症状**：PowerShell 重定向出的 `.jsonl` 用 Python 读不到事件；中文显示为 `锟斤拷`。

**根因**：PowerShell 5.1 的 `>` / `*>` 默认写 UTF-16LE；Python 按 UTF-8 读就全是空字符。

**修复**：

```powershell
# 统一转 UTF-8（无 BOM）
$enc = New-Object System.Text.UTF8Encoding($false)
$t = [IO.File]::ReadAllText($path)
[IO.File]::WriteAllText($path, $t, $enc)
```

或在渲染器里自动识别 BOM/UTF-16（本项目 `demo/tools/render_transcript.py` 已实现）。

**预防**：采集轨迹优先用 `Start-Process -RedirectStandardOutput`（写原始字节），少用 PowerShell 重定向。
