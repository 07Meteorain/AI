# 配置说明：把 Hermes 调成「能干活」的状态

> 对应文件：`E:\hermes\config.yaml`（主配置）、`E:\hermes\.env`（密钥/环境变量）、`E:\hermes\SOUL.md`（人格）。
> 配置版本：v53（由 Hermes 自动迁移）。所有键都经过 `hermes doctor` 校验。

---

## 1. 配置分层（先搞清谁覆盖谁）

Hermes 的解析优先级，从高到低：

1. 命令行参数（`hermes chat -m ...`）
2. `config.yaml`
3. `.env`（密钥必须放这里）
4. 内置默认值

两条硬规则：

- **密钥只进 `.env`**，不要写进 `config.yaml`（`hermes config set` 遇到 `UPPER_SNAKE` 也会自动路由到 `.env`）。
- 记忆、技能、会话都按 **profile** 隔离；默认 profile 就是 `HERMES_HOME` 本身。

## 2. 本机最终配置（逐项解释）

```yaml
model:
  default: "gemma4-e2b-64k"
  provider: "custom"
  base_url: "http://127.0.0.1:11434/v1"
  api_key: "no-key"

terminal:
  backend: local
  timeout: 300

updates:
  auto_update_check_hours: 0

_config_version: 53
```

| 键 | 值 | 为什么这么配 |
| --- | --- | --- |
| `model.default` | `gemma4-e2b-64k` | Ollama 里的自定义模型名，带 64k 上下文 |
| `model.provider` | `custom` | 走任意 OpenAI 兼容端点，不绑定云厂商 |
| `model.base_url` | `http://127.0.0.1:11434/v1` | Ollama 的 OpenAI 兼容接口 |
| `model.api_key` | `no-key` | Ollama 不校验；填占位符是为了让客户端带上 Authorization 头 |
| `terminal.backend` | `local` | 本机直接执行；风险见第 7 节 |
| `terminal.timeout` | `300` | 本地模型 prefill 慢，命令超时放宽到 5 分钟 |
| `updates.auto_update_check_hours` | `0` | 本机 GitHub API 403，关掉被动检查，避免每次启动都重试 |

### 2.1 为什么不用 `provider: ollama`

Hermes 有 `providers.ollama.base_url` 的写法，也有 `--provider ollama` 的别名。但本机 Ollama 同时暴露 `/v1`，用 `custom` 更通用：以后把 `base_url` 换成 vLLM / LM Studio / llama.cpp 都不用改 provider 名。

### 2.2 `.env`

```dotenv
HERMES_API_TIMEOUT=1800
OLLAMA_KEEP_ALIVE=24h
HERMES_GIT_BASH_PATH=E:\hermes\tools\git-2.56.1+1-win32-x64\usr\bin\bash.exe
```

| 变量 | 作用 |
| --- | --- |
| `HERMES_API_TIMEOUT` | 本地 4.6B 模型 prefill 可能 1–3 分钟，默认超时不够 |
| `OLLAMA_KEEP_ALIVE` | 让 Ollama 别 5 分钟就卸载模型（减少冷启动） |
| `HERMES_GIT_BASH_PATH` | **关键**：Hermes 的 file 工具依赖 bash；不指路就报 `No shell found` |

> `HERMES_GIT_BASH_PATH` 是这台机器的核心排错点。PM 还没把 Git 登记进 store 时，最稳的办法就是直接指向 pinned Git 的 `usr\bin\bash.exe`。

## 3. 模型侧：Ollama 必须改上下文

Ollama 默认 `num_ctx=2048`，而 Hermes 的系统提示 + 工具 schema 起步就是 2–4 万 token。不改会出现「模型看不见工具说明」或直接截断。

```text
# Modelfile
FROM gemma4:e2b
PARAMETER num_ctx 65536
PARAMETER temperature 0.6
```

```powershell
ollama create gemma4-e2b-64k -f Modelfile
ollama ps
# NAME                     SIZE      PROCESSOR    CONTEXT
# gemma4-e2b-64k:latest    408 MB    100% GPU     65536
```

选择 `gemma4:e2b` 的原因：

- 4.6B、Q4_K_M，4 GB 显存能全量放下；
- `ollama show` 的 capabilities 含 `tools`，实测能产生结构化 tool_call；
- 中英文都可用，回答质量足够跑通 demo。

代价：每轮 prefill 约 1–3 分钟，长任务要有耐心。这不是 Hermes 的调度问题，是 4 GB 显存的物理限制。

### 3.1 换成云端模型

只改三行即可（以 OpenRouter 为例）：

```yaml
model:
  default: "anthropic/claude-sonnet-4.6"
  provider: "openrouter"
```

然后在 `.env` 加 `OPENROUTER_API_KEY=...`。Hermes 会自动切到云端，工具、记忆、技能全部不变。

## 4. 人格：SOUL.md

`E:\hermes\SOUL.md` 是系统提示里的第一优先级人格槽位。本机在官方模板后追加了「阿赫」：

```markdown
## 身份：阿赫（A-He）

- 默认用简体中文回答；技术名词保留英文。
- 先给结论，再给证据和步骤。
- 涉及状态变更时必须真实调用工具，并附命令、路径或退出码；
  禁止声称"已保存/已执行"而没有工具调用记录。
- 不确定就直说，并给出验证方法；不编造版本号、路径或结果。
- 不把 API Key、token、密码写进回复或文件。
```

设计意图：**把小模型最容易犯的错（幻觉写入）写成硬约束**。这条在 demo 01 的失败后又被 prompt 强化了一次。

## 5. 记忆系统

| 文件 | 存什么 | 上限 | 本机现状 |
| --- | --- | --- | --- |
| `E:\hermes\memories\MEMORY.md` | 环境事实、经验、约定 | 2200 字符 | 尚未写入 |
| `E:\hermes\memories\USER.md` | 用户画像、偏好 | 1375 字符 | 已写入 57 字符 |

实测写入（demo 02）：

```json
{"success": true, "target": "user", "usage": "4% — 57/1,375 chars", "entry_count": 1}
```

关键认知：

- 记忆是**会话开始时冻结注入**的，写完必须新开会话才能看到（demo 03 验证）；
- 只有模型真的调用 `memory` 工具才会落盘，「我记住了」这句话不算；
- 小模型容易口头声称保存，必须用 `read_file` / `terminal cat` 回读验证。

## 7. 安全配置（本机取舍）

| 项 | 本机设置 | 风险与建议 |
| --- | --- | --- |
| `terminal.backend` | `local` | agent 拥有当前用户全部文件权限；生产环境应换 `docker` |
| 单查询 `execute_code` | 默认禁止 | 无人值守时不允许任意 Python，这是 Hermes 的保护 |
| 危险命令审批 | 单查询模式无交互审批 | 所以 demo 只给 `file` / `terminal`，且工作目录限定在 `demo/workspace` |
| 密钥 | 仅 `.env` | 交付仓库里只放 `.env.example` |
| `updates.auto_update_check_hours` | `0` | 减少无谓外联 |

如果要更安全：

```yaml
terminal:
  backend: docker
  docker_image: "nousresearch/hermes-sandbox:desktop"
```

## 8. 网关（Gateway）

Hermes 的交互会话由本地网关承载。两种用法：

```powershell
# 前台运行（推荐，日志直接可见）
hermes gateway run

# 安装成 Windows 计划任务（开机自启）
hermes gateway install
```

本机为什么用前台：DSH 的父进程 Job Object 禁止 `CREATE_BREAKAWAY_FROM_JOB`，`hermes chat` 想拉起的后台网关会被拒绝（`windows_breakaway_unavailable`）。前台 `gateway run` 不受影响，CLI 会自动连上已有网关。

验证：

```powershell
hermes gateway status
# ✓ Gateway is running (PID: 18868)
```

消息平台（Telegram / Discord / 飞书等）本次未接入：没有可用 token，也不应该把别人的 bot 凭据写进作业。配置方法已写在 `扩展/` 里，留作可复现的下一步。
