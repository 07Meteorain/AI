## 3. 失败经验（F1–F8，全部真实）

### F1 · 环境：PowerShell 进程创建失败 `0xC0000142`

- **现象**：第一次调用 `pwsh -Command "Get-ChildItem"` 连续两次返回 `0xC0000142`（DLL 初始化失败），第三次正常。
- **影响**：如果当时的反应是"环境坏了，放弃命令行验证"，后面所有"可运行"的声明都会变成空话。
- **处理**：重试一次 + 换成不依赖命令行的工具（`glob`/`read`）先读材料，再回来跑命令。
- **教训**：**"跑不起来"和"跑错了"是两件事**。前者要区分环境故障与代码故障，否则很容易把环境问题误记成自己的 bug（或反之）。

### F2 · 生成的技能代码用 JSON 字面量，`import` 直接失败

- **现象**：`auto-review-c264` 运行报 `NameError: name 'false' is not defined`。
- **根因**：`scaffold.py` 用 `json.dumps(steps)` 生成 Python 源码，`{"apply": false}` 在 Python 里应为 `False`。
- **发现方式**：演示时该步 `ok=False`，但当时回执显示"执行完成"（见 F5），差点被掩盖。
- **修法**：改用 `repr(steps)`；并补一条测试 `compile(handler, "handler.py", "exec")`。
- **教训**：**代码生成器必须验证生成物能被解析**。语法正确的字符串和可执行的源码是两件事。

### F3 · `evolve` 说"只看不改"，却真的写了文件

- **现象**：`test_dry_run_changes_nothing` 失败：技能数 3 → 4。
- **根因**：`cycle.py` 无条件调用 `draft_skill()`，只在统计时判断 `apply`。
- **修法**：`draft_skill(..., write=False)` 只计算不落盘；返回 `planned=True` 供报告展示。
- **教训**：**dry-run 必须是真正的只读**，不能"写了再假装没写"。这条和 `--no-write` 的设计原则是同一条。

### F4 · `tags: auto, draft, review` 被解析成空列表

- **现象**：草稿技能已生成，但"同一意图自动接管"始终不生效。
- **根因**：loader 只接受 YAML 列表，标量字符串被静默丢弃；而 `_preferred_skill` 依赖 `tags`。
- **修法**：`_as_list()` 同时接受列表与逗号串；顺手给 `tools` 也加上。
- **教训**：**静默丢弃字段是最坏的容错**。解析器遇到不认识的形状应当报错或兼容，而不是当作空值。

### F5 · 技能内部失败，`skill.run` 却返回成功

- **现象**：`brain review` 打印"技能 weekly-review 执行完成"，但输出里没有报告路径；trace 状态 `ok`。
- **根因**：`skill_run` 工具把 `SkillResult(ok=False)` 塞进 `data` 返回，registry 只看"有没有抛异常"。
- **连带发现**：review 把整句用户输入 `"回忆 复盘 周末"` 当 `week` 传给技能，导致技能抛"周编号格式不对"——这个错误被 F5 吞掉了。
- **修法**：工具内 `if not result.ok: raise ToolError(...)`；planner 增加 `_week_of()` 只接受形如 `2026-W46` 的输入。
- **教训**：**"失败"必须在边界上变成失败**。把错误打包成正常返回值，等于让熔断、降级、复盘三个机制同时失效。

### F6 · 问句回声：同一句话问两遍，第二遍"命中"自己

- **现象**：演示里 `recall 打分规则` 第一次 0 命中，`evolve` 之后"命中"的却是**上一次的问句存档**，而不是知识。
- **连带影响**：同义词学习完全失效——因为提问本身被写进 S 层，"没问到的词"立刻变成"索引里有的词"。
- **修法**：`recall/chat` 写入的 AR/S 打 `meta.echo=True`，检索默认跳过；同义词挖掘改用 **K 层（人工沉淀）** 当"学过没有"的标尺。
- **教训**：**日志与知识的混写会污染检索**。同一个存储里放两种语义的东西，迟早要用一个字段把它们分开——不如一开始就分开。

### F7 · 用混合意图的平均步数判断"进化"

- **现象**：`trend` 输出"平均步数 1.0 → 1.86，步数上升（可能过拟合）"，而真实情况是 review 从 3 步降到 1 步。
- **根因**：`capture` 本来 1 步、`review` 本来 3 步；前后半段的任务构成不同，平均值没有可比性。
- **修法**：改为**按意图分组**前后对比；整体平均值降级为"仅参考"并加注说明。
- **教训**：**混算的平均值可以证明任何结论，所以它不能证明任何结论。**

### F8 · 全局 `--json` 只能写在子命令前面

- **现象**：`brain recall x --json` 报 `unrecognized arguments: --json`。
- **根因**：argparse 的全局选项挂在顶层 parser 上，子命令解析时不认。
- **修法**：用 `parents=[common]` 把同一组开关挂到每个子命令（`default=SUPPRESS` 防止覆盖全局值）。
- **教训**：**"能跑"和"顺手"是两件事**。评审者第一次用就会踩的坑，就是设计缺陷。

### 附：首轮测试的失败清单（原始输出）

```text

FAILED (failures=9, errors=1)
```

九条失败里，**五条是真 bug**（F2、F3、F4、F5、F6），两条是测试本身写错（星期几的措辞、行数不够），
一条是分类顺序问题（"回忆 复盘 周末"被判成 review），一条是 `skill.run` 语义问题。

## 4. 做对了什么（可复用的做法）

| 做法 | 为什么有效 | 证据 |
| --- | --- | --- |
| **先定不变量，再写实现** | "删除只能归档""降级必须留痕"写成红线后，实现时每个岔路口都有答案 | AGENT.md 第 7 节 ↔ 代码逐条对应 |
| **每个失败都要有一条测试** | F2–F8 每条都补了回归测试，之后重构没有回退 | 196 项测试 |
| **演示脚本可重跑** | `demo/run_demo.py` 每次都清库重放，结论不依赖"上次跑出来的状态" | 14 场景 0 失败 |
| **诚实边界写进产物** | 离线只做抽取式、不生成；`LLM 模式` 明确标注"未人工改写" | 回执末尾的固定声明 |
| **度量与功能同批交付** | `trend` 按意图对比，才让"3 步变 1 步"变成可验证结论 | review 3.0 → 1.0 |

## 5. 如果重来，会改的三件事

### ① 先画 trace schema，再写循环

现在 `RunTrace.meta` 是开放字典，`trend` 只能靠约定字段名（`intent`/`steps`/`recall_hits`）去猜。
后果：加一个分析维度就要翻三个文件确认字段名。

改法：先写一份 `trace.schema.json` + 一个 `validate()`，循环层只允许往里填已知字段，
分析层用同一份 schema 生成表格。

### ② 先想清楚"什么不该进索引"，再写写入

F6 的根因不是"忘了过滤"，而是**写入时没有区分"事件日志"和"知识"两种语义**。
如果一开始就问"这条记录参与检索吗"，`echo` 字段会在第一版就存在，而不是等到演示时才被发现。

改法：任何写入都强制回答一件事——`searchable: true/false`。默认 `true`，日志类显式 `false`。

### ③ 度量先于功能

`trend` 是在技能固化做完之后才写的。结果是：我**先有了一个"看起来能进化"的系统**，
再去想办法证明它进化了——这个顺序天然倾向于"挑一个能证明的指标"。

改法：先写"同类任务步数"这个指标并让它跑在空系统上（全是 0），再实现固化功能，
每次改动后用同一张表验证。**指标定义在使用之前，才不容易被使用方式塑造。**

## 6. 未解决 / 已知局限

| # | 局限 | 影响 | 下一步 |
| --- | --- | --- | --- |
| 1 | 只有 14 条 trace，趋势只能当示意 | "进化"的统计意义不足 | 连续使用 4 周后重跑 `brain trend`，用真实数据替换 |
| 2 | 无向量检索 | 换个说法经常找不到，只能靠同义词 | 加一个**可选** embedding 后端，默认路径仍零依赖 |
| 3 | 单进程写 | 两个进程同时更新会互相覆盖 | 加文件锁（`msvcrt`/`fcntl`）或改成单实例守护 |
| 4 | 草稿技能不会自动回滚 | 一个坏草稿会一直接管 | 连续失败 2 次自动降级为"不接管" |
| 5 | 同义词没有置信度 | 学错的映射会一直生效 | 记录命中次数，长期 0 命中的映射自动失效 |
| 6 | 无 `--explain` | 用户看到分数不知道为什么 | 输出 BM25 各分量与四因子乘子 |
| 7 | 自动生成的技能没有测试 | 生成即"未验证" | 生成时同时生成一条 smoke test |

## 7. 一句话总结

**这套系统最值钱的不是它记住了什么，而是它每次都在留下"这次为什么这么做"的证据。**
没有那些证据，`3 步 → 1 步` 只是一个数字；有了证据，它才是一次可以被复述、被质疑、被改进的进化。
