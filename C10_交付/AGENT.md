# AGENT.md

> **这是给「人」看的运行手册，不是给模型的 system prompt。**
>
> 它规定这个智能体怎么想、能做什么、记什么、什么时候必须被拦住。
> 每一条规矩后面都写着它在代码里的位置——手册和实现对不上时，以代码为准，
> 然后回来改手册（`tests/test_*.py` 会拦住不一致）。
>
> 版本 `1.0.0` ｜ 自检：`python -m brain doctor`

## 0. 一句话

**把「重复」变成「能力」，把「经历」变成「记忆」，并且每次使用都比上一次少走一步。**

这不是文学表达，是三条可被 `brain metrics` 验证的指标：

| 主张 | 被什么验证 | 当前实测 |
| --- | --- | --- |
| 重复的任务会被固化 | `brain evolve` 生成 `skills/_drafts/auto-*` | 复盘 3 次后自动生成技能 |
| 同类任务变快 | `brain trend` 的「按意图」表 | review：**3.0 步 → 1.0 步** |
| 检索越用越准 | 同义词表 + 命中率 | 检索命中率 **67% → 100%** |

## 1. 我是谁

我是一个**本地优先、跨会话持续、可审计**的个人智能体。我的主人是一位学生，
我不是通用助手：我的价值在于**记得住他做过什么**，并让下一次更快。

### 三条硬边界（不可通过配置打开）

| 边界 | 为什么 | 代码位置 |
| --- | --- | --- |
| **不执行任意命令** | 一个 `shell.run` 会让所有权限设计变成装饰品 | `brain/tools/builtin.py` 只注册只读 `git.status` |
| **不删除记忆** | 记忆的删除必须可撤销；误判一次就永久丢掉一段经历 | `brain/memory/promote.py` 只 `archived` 不 `remove` |
| **不静默降级** | 用户以为在用模型、实际在用 if-else，是最坏的一种"能用" | `brain/loop/engine.py` 写 `meta.fallback`，`brain/llm/provider.py` 记 `degraded_reasons` |

### 我服务的对象只有一个

单用户、本地文件、无服务端。所以我不做多租户隔离、不做权限组、不做配额——
**为不存在的需求写代码，是让真正重要的部分变脆的最快方式**。

## 2. 五层结构：每层只做一件事

| 层 | 目录 | 一句话职责 | 输入 → 输出 | 不该做的事 |
| --- | --- | --- | --- | --- |
| **L1 接口** | `brain/interface/` | 人和我说话的地方 | 命令行参数 → 回执 | 不写业务逻辑 |
| **L2 工具** | `brain/tools/` | 我对外部世界的动作 | 参数 → `ToolResult` | 不自己找全局状态 |
| **L3 循环** | `brain/loop/` | 把一件事拆成几步做完 | 一句话 → `RunTrace` + 回答 | 不直接读写文件 |
| **L4 技能** | `brain/skills/` + `skills/` | 把重复动作固化成可调用单元 | `(ctx, args)` → `dict` | 不偷偷改自己的代码 |
| **L5 记忆** | `brain/memory/` | 记得什么、记得多牢、怎么找回 | 记录 → 检索结果 | 不解释语义、不做推理 |

**依赖方向严格单向**：L1 → L3 → (L2, L4, L5)。L5 不知道 L3 存在，L2 不知道 L4 存在。
`brain/app.py` 是唯一的组合根——**看完 `App.__init__` 就看完全部接线**。

任何"跨层调用"都必须经过 `ToolContext`。这是我唯一允许的全局状态，而且它是显式传参的。

## 3. 一次运行：七个固定步骤

```text
classify → plan → act → observe → compose → reflect → trace
```

| 步骤 | 我在做什么 | 失败时怎么办 | 代码位置 |
| --- | --- | --- | --- |
| 1 classify | 把一句话判成 6 类意图之一 | 判不出来就 `chat`，并降置信度 | `loop/planner.py::classify` |
| 2 plan | 选出"要调哪些工具、传什么参数" | 规则规划器永远给得出计划；LLM 规划器失败则回落 | `planner.plan` / `llm/provider.py::LLMPlanner` |
| 3 act | 逐个调用工具（有预算、有权限闸门） | 单步失败**不中断**，记进 trace | `tools/registry.py::call` |
| 4 observe | 收集工具结果 | 失败结果也是观察结果 | `loop/engine.py` |
| 5 compose | 把结果拼成人话 | 没命中就直说没命中 | `loop/compose.py` |
| 6 reflect | 写 AR（我做过什么）+ S（当时是什么场景） | 只读模式跳过，并在回执里说明 | `engine._reflect` |
| 7 trace | 落一条可复盘的运行记录 | trace 失败不影响回答 | `loop/trace.py` |

### 三条循环纪律

1. **步数上限**（默认 8，`BRAIN_MAX_STEPS`）。没有上限的循环，会在一棵错的树上走到底。
2. **反思先于返回**。先写 AR 再返回，否则程序崩在半路时这段经历就丢了。
3. **只读模式真的只读**。`--no-write` 时 `ctx.allow_write=False`，工具层直接拒写，
   不是"写了再回滚"——回滚在进程被杀时不会发生。

## 4. 记忆：KSTAR 四层

详见 [`docs/KSTAR记忆规范.md`](docs/KSTAR记忆规范.md)。这里只写**我必须遵守的写入规矩**：

| 层 | 存什么 | 谁写 | 衰减 | 典型误区 |
| --- | --- | --- | --- | --- |
| **K** 知识 | 验证过的结论、决策、方法论、已知坑 | 人 / 技能 / 沉淀 | **不衰减** | 把"当时怎么想"当知识存进来 |
| **S** 情境 | 某时某地发生了什么（会话、事件） | 每次运行自动 | 半衰期 30 天 | 把 S 当知识用，于是永远找不到 |
| **T** 任务 | 目标、承诺、状态机（open/done） | 人 / 循环 | 弱衰减 | 任务和知识混写，导致 T 层变成垃圾场 |
| **AR** 行动-反思 | 做过什么、结果如何、学到什么 | 每次运行自动 | 半衰期 30 天 | 只记动作不记结果，于是无法复用 |

### 检索：排序而不是布尔

```text
final = BM25(query, doc) × 层先验 × (0.85 + 0.3×重要度) × 新近度 × (1 + min(0.25, 0.03×命中次数))
```

四个因子**相乘**，因为"完全没命中"必须得 0 分；用加法会让一条高重要度的无关记录胜出。

### 两条用血换来的规矩

- **问句回声不参与检索**（`meta.echo`）。一句问话在库里躺两天不会变成答案，
  但它会让同一句话第二次提问时"命中"自己，制造虚假的成功率。演示里真的撞上过。
- **沉淀是归档不是删除**。`promote.py` 只把冷掉的情境标 `archived`，原文永远保留。

## 5. 技能协议

一个技能 = 一个目录 = 一份契约 + 一段能跑的代码：

```text
skills/weekly-review/
├── SKILL.md      # front matter 元数据 + 人读的说明（何时用、失败场景）
└── handler.py    # def run(ctx, args) -> dict，必须返回 summary
```

| 字段 | 必填 | 作用 |
| --- | --- | --- |
| `name` / `description` | 是 | 清单里唯一的常驻成本（约 30 字/技能） |
| `when` | 建议 | 什么情况下该用它 |
| `inputs` | 否 | 参数说明（键 → 说明） |
| `tags` | 否 | 用于 `auto-*` 技能的自动接管匹配 |
| `tools` | 否 | 依赖的工具（用于进化去重） |
| `handler` | 否 | 缺省则它是"说明型技能"，不会假装执行 |

**渐进披露**：`list` 只读 front matter → `show` 才读正文 → `run` 才 import handler。
把 10 个技能全文塞进上下文，等于每轮都付一遍不需要的钱，还会稀释真正相关的信息。

**草稿规则**：`brain evolve` 只能写 `skills/_drafts/`，`version=0.1`，`status=draft`。
草稿技能可以被**自动接管**（省掉重新规划），但绝不能覆盖人工技能。

## 6. 进化协议

一次 `brain evolve` 做四件事，**默认全部只看不改**：

| 路径 | 触发条件 | 产出 | 风险控制 |
| --- | --- | --- | --- |
| ① 技能固化 | 同一工具序列成功重复 ≥ 3 次 | `skills/_drafts/auto-*/` | 只写草稿；工具白名单；人工启用 |
| ② 同义词 | 同一 session 内"先问不到、换个说法问到了" | `memory/db/aliases.json` | 每条候选带原文证据；可删 |
| ③ 沉淀 | 工作流重复 ≥3 / 同一错误 ≥2 / 情境变冷 | K 记录 / `archived` 标记 | 归档非删除；只提议不自动写 |
| ④ 度量 | 每次 | `metrics` + `trend` | 少于 4 条不给趋势结论 |

**每一次落盘都进 `memory/db/evolution.jsonl`**。系统改了自己什么，必须留一笔——
否则它就是一个无法审计的自修改程序。

## 7. 我绝对不能做的事（红线）

| 红线 | 反例 | 我怎么保证 |
| --- | --- | --- |
| 编造证据 | 检索不到却生成一段"根据记忆…" | 离线模式只做抽取式回答，末尾写明"未调用大模型" |
| 静默降级 | 模型超时后无声回退 | `trace.meta.fallback` + 回执里打印降级原因 |
| 把失败记成成功 | 技能内部报错，`skill.run` 却返回 ok | `skill_run` 失败即抛 `ToolError`（F5 就是这么发现的） |
| 越权访问文件 | `fs.read("../../etc/passwd")` | `_safe_path` 把路径钉死在项目根内 |
| 无限循环 | 规划器反复挑同一个必败工具 | 熔断：连续失败 3 次临时禁用 |
| 偷偷改代码 | evolve 直接覆盖人工技能 | 只写 `_drafts/`，且 `status=draft` |

## 8. 怎么用我

```bash
# 0) 自检（不需要装任何依赖）
python -m brain doctor

# 1) 记一条（默认进 S；加 --layer K 进知识层）
python -m brain capture "结论：检索排序必须相乘不能相加" --layer K

# 2) 问一句（走完整循环：分类 → 检索 → 回答 → 反思 → 留痕）
python -m brain ask "上次那个检索排序是怎么定的？"

# 3) 只看检索（带分数与命中词）
python -m brain recall "检索排序" -k 5

# 4) 任务
python -m brain task add "给 C10 写 AAR"
python -m brain task done "给 C10 写"        # 关闭任务并自动生成 AR

# 5) 技能
python -m brain skill list
python -m brain review                        # 周复盘
python -m brain skill run decision-log '{"query": "用纯 Python 实现索引", "reason": "零依赖"}'

# 6) 进化
python -m brain evolve                        # 只看
python -m brain evolve --apply                # 落盘（进 evolution.jsonl）

# 7) 看自己过得怎么样
python -m brain metrics
python -m brain trend
python -m brain trace -n 8
```

## 9. 我不确定的时候（诚实边界）

1. **离线模式下我不"理解"**。规则规划器只认显式说法；"帮我想想上次那个事"会被判成 `chat`。
   这是设计上的天花板，不是 bug——接模型才有语义理解（见 README「三种运行模式」）。
2. **检索是词面匹配，不是语义匹配**。换个说法找不到是常态，所以我需要同义词表，
   而同义词表靠"失败后重述"这种笨办法学。
3. **我的记忆是单机的、无并发的**。两个进程同时写会互相覆盖（追加安全，更新不安全）。
4. **我度量的是效率，不是价值**。"3 步变 1 步"证明的是固化生效，不证明这件事值得做。
5. **自动生成的技能可能过度拟合某次输入**。所以它们只能当草稿，且必须人工 review 才能升版。

## 10. 自检清单（`python -m brain doctor` 对应项）

| 检查 | 通过标准 |
| --- | --- |
| Python 版本 | ≥ 3.9 |
| 记忆目录可写 | 能建临时文件并删除 |
| KSTAR 索引一致 | 索引条数 == 记录条数 |
| 工具可调用 | 12 个工具注册成功，`time.now` 返回 ISO 时间 |
| 技能可加载 | 无 `broken`、无解析警告 |
| 循环可运行 | 只读模式下跑完一遍且状态 `ok` |
| trace 可读 | 能列出历史运行 |

七项全绿 = 五层真的接上了。**任何一项红，先修它，不要写文档。**
