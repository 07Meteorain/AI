# 技能规范

> 技能是"重复动作"的固化形态。它必须有契约、能被测试、能被度量——
> 否则它只是存在某个 prompt 里的字符串，删了也没人知道。

---

## 1. 一个技能就是一个目录

```text
skills/weekly-review/
├── SKILL.md      # 契约：front matter 元数据 + 人读的正文
└── handler.py    # 可选：def run(ctx, args) -> dict
```

- 目录名建议与 `name` 一致（不强制，`name` 才是唯一键）；
- 没有 `handler.py` 的技能是**说明型技能**：`run` 会返回使用说明，不会假装执行；
- `skills/_drafts/` 下的技能一律视为草稿（`status=draft`）。

---

## 2. SKILL.md 的 front matter

```yaml
---
name: weekly-review
description: 生成某一周的复盘报告：跑了多少次、哪些意图重复、失败在哪、沉淀了什么
version: 1.0
when: 每周结束时，或想看清"这周系统/我到底在干什么"
inputs:
  week: ISO 周，如 2026-W46；留空表示本周
  out: 输出路径；留空则写到 memory/reviews/
tags: review, 复盘
tools: memory.search, memory.write
handler: handler.py
---
```

| 字段 | 必填 | 类型 | 缺省行为 |
| --- | --- | --- | --- |
| `name` | ✅ | str | —（缺了整条技能被跳过并记 warning） |
| `description` | ✅ | str | —（同上） |
| `version` | | str | `"1.0"` |
| `when` | | str | `""` |
| `inputs` | | map | `{}` |
| `tags` | | list 或逗号串 | `[]`（`auto-*` 技能靠它匹配"自动接管"） |
| `tools` | | list 或逗号串 | `[]`（进化层用它去重） |
| `handler` | | str | 若目录下存在 `handler.py` 则自动采用 |

### 解析器只认 YAML 的 5%

`brain/skills/model.py::parse_front_matter` 支持三种形状：

```yaml
key: 值                  # 标量（自动转 bool/int/float）
key:
  - 甲
  - 乙                    # 列表
key:
  a: 说明
  b: 说明                # 一层字典
```

**不支持**多行字符串（`|`、`>`）、嵌套列表、锚点、注释块。
遇到不认识的形状，解析器**抛错而不是猜**——猜错的后果是字段静默丢失，
而"技能在清单里但没有标签"这种 bug 极难查（F4 就是这么来的）。

## 3. handler 契约

```python
def run(ctx, args: dict | None = None) -> dict:
    ...
    return {"summary": "一句话结果", ...}
```

| 约定 | 说明 |
| --- | --- |
| 位置参数 | 第一个是 `ctx`，第二个是 `args`（可为空 dict） |
| 返回值 | 必须是 `dict`，且**应该**含 `summary`（回执与 compose 都读它） |
| 失败 | 直接抛异常。运行时会捕获、记 `ok=False`、写 usage 日志、把错误交给循环层 |
| 不要 `sys.exit` | 会杀掉整个进程，绕过所有反思与 trace |

### `ctx` 能给你什么

| 属性 | 用途 |
| --- | --- |
| `ctx.memory` | KSTAR 记忆的读写与检索（`write` / `search` / `all` / `update`） |
| `ctx.tools` | 调其它工具：`ctx.tools.call("memory.search", {...}, ctx)` |
| `ctx.config` | 路径（`home` / `knowledge_dir` / `skills_dir` / `rel()`） |
| `ctx.run_id` | 本次运行 id，写进 `source` 用于溯源 |
| `ctx.skills` | 技能运行时（技能可以调另一个技能，注意别递归） |
| `ctx.allow_write` | 只读模式下为 `False`；**写操作要自己尊重它** |

## 4. 渐进披露：常驻成本

| 动作 | 读了多少 | 什么时候发生 |
| --- | --- | --- |
| `skill list` | 只读 front matter（≈ 30 字/技能） | 每次启动、每次回执 |
| `skill show` | 读正文（≈ 1–2 KB/技能） | 人主动查看 |
| `skill run` | import handler 并执行 | 真的要用 |

把 10 个技能全文塞进上下文，等于每轮都付一遍不需要的钱，还会稀释真正相关的信息。
`catalog()` 的输出就是"常驻成本"本身——它现在只有 4 行。

## 5. 随项目交付的技能

| 技能 | 类型 | 输入 | 输出 | 失败场景 |
| --- | --- | --- | --- | --- |
| `weekly-review` | handler | `week`（可空）、`out`（可空） | 报告路径 + 计数 | 周编号格式错 → 直接报错；该周无记录 → `empty=True` |
| `decision-log` | handler | `query`、`reason`、`options`、`revisit` | ADR 文件 + K 记录 id | 缺 `query` → 报错 |
| `note-to-knowledge` | handler | `query`、`title`（可空） | K 记录 id + 关联 id | 缺 `query` → 报错；重复内容 → 返回已有 id |
| `auto-review-*` | 草稿 | `query` | 回放 3 步的结果 | 由 `evolve` 生成，见 [进化机制](进化机制.md) |

## 6. 草稿技能的三条铁律

1. **只能写进 `skills/_drafts/`**，不能覆盖 `skills/` 下的任何东西；
2. `version` 从 `0.1` 开始，`status=draft`，清单里显式标注；
3. **必须能被 import**——生成的是 Python 源码，`compile()` 不过就是坏交付物
   （F2：用 `json.dumps` 生成 `false`/`null`，导致 `NameError`）。

草稿可以被自动接管（`RulePlanner._preferred_skill` 只认 `auto-*` 且 `status == draft`），
但升级到 1.0、移出 `_drafts/` 必须有人读过它的 handler。

## 7. 新增技能的自检清单

```bash
python -m brain skill new 我的技能 --desc "一句话说明"   # 生成骨架
python -m brain skill list                              # 能看到、状态 ready
python -m brain skill show 我的技能                      # 正文能读出来
python -m brain skill run 我的技能 "参数"                 # 能跑，且返回 summary
python -m unittest discover -s tests                    # 至少有一条测试覆盖它
```

**没有测试的技能等于没有技能**：它会在某次重构后静默失效，而没人会发现。

## 8. 常见错误对照表

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 技能不出现在 `list` 里 | front matter 未闭合 / 缺 `name` 或 `description` | 看 `loader.warnings`（`skill list` 会打印） |
| `status=broken` | 声明了 `handler` 但文件不存在 | 补文件或删掉 `handler` 字段 |
| 标签是空的 | `tags: a, b` 被当成标量 | 已支持逗号串；若是嵌套列表则不支持 |
| `run` 返回 `mode=prompt` | 没有 handler | 这是正常的"说明型技能" |
| 技能报 `NameError: false` | 生成代码用了 JSON 字面量 | 用 `repr()` 生成 Python 字面量 |
| 自动接管没生效 | 名字不是 `auto-*` / `status != draft` / `tags` 不含意图 | 检查 `SKILL.md` 的 tags |
