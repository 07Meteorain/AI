# 进化机制

> 挑战里最容易写成口号的一句是"让系统每次使用都在进化"。
> 这句话要成立，必须回答三个可验证的问题：
> **变的是什么？谁决定的？凭什么说变好了？**

---

## 1. 变的三样东西

| # | 变什么 | 触发条件 | 落在哪 | 可撤销吗 |
| --- | --- | --- | --- | --- |
| ① | 多一个**可调用技能** | 同一工具序列成功重复 ≥ 3 次 | `skills/_drafts/auto-*/` | 删目录即可 |
| ② | 多一组**同义词映射** | 同一 session 内"先问不到、换个说法问到了" | `memory/db/aliases.json` | 删键即可 |
| ③ | 多一条**知识 / 一次归档** | 流程重复 ≥3；同一错误 ≥2；情境变冷 | `memory/{k,s,ar}.jsonl` + `knowledge/*.md` | K 可改可删；归档保留原文 |

三样东西都不涉及"模型权重"。**这不是缺点，是选择**：权重级进化不可审计、不可回滚，
而一个学生要的是一套**他能看懂、能手动改**的基础设施。

## 2. ① 技能固化：怎么从"做过三遍"变成"一条命令"

### 挖矿

```python
# brain/evolve/miner.py
patterns = workflows(traces, min_runs=3, min_steps=2)
```

- 只看 `status == "ok"` 的运行（失败三次不代表它值得固化）；
- 工作流签名 = 工具调用序列，如 `memory.search>skill.run>memory.promote`；
- 至少 2 步（单步动作没有"编排"可言）；
- 全是 `skill.run` 的不算（已经在技能里了）。

### 为什么阈值是 3

| 阈值 | 后果 |
| --- | --- |
| 1 次 | 把偶发写成流程。**每一次偶然都会变成永久的基础设施** |
| 2 次 | 一次巧合就够了（比如连续两次都用了同一个临时文件） |
| **3 次** | 足够过滤掉偶然，又不至于让人等太久 |
| 5 次 | 太保守：一个人一周可能只做两次同类任务 |

3 是**成本与信号的折中**，不是理论最优。它写在 `--min-runs` 里，可以改。

### 生成

```python
info = draft_skill(config, workflow=..., label=..., count=..., runs=..., write=apply)
```

- 生成 `SKILL.md`（含证据：哪三次运行、每次的输入输出）与 `handler.py`；
- handler **只回放已记录的工具调用**，不含任何新逻辑；
- 工具白名单（`SAFE_STEP_TOOLS`）：出现 `shell.run` 之类直接拒绝生成；
- 原来那句话会被替换成 `{query}` 占位符，技能才有输入。

### 接管

```python
# brain/loop/planner.py::_preferred_skill
if skill.name.startswith("auto-") and kind in skill.tags and skill.status == "draft":
    return [PlannedStep("skill.run", {"name": skill.name, ...})]
```

只让 `auto-*` 草稿接管。**人工技能必须显式调用**——否则哪天有人加了一个 tag 相同的技能，
行为就被悄悄改掉了。

## 3. ② 同义词：从"问不到"里学

```text
第 1 次：  recall 打分规则      → 0 条命中
第 2 次：  recall 检索排序      → 3 条命中
           ↓ evolve
aliases.json: {"打分规则": ["检索", "索排", "排序"]}
           ↓
第 3 次：  recall 打分规则      → 命中（分数 ×0.5 叠加）
```

### 一个必须分开的两个词表

| 词表 | 内容 | 用途 |
| --- | --- | --- |
| `known_terms` | 全量索引词元 | 判断"换个说法后命中的词"是否真实存在 |
| `curated_terms` | **只取 K 层**的词元 | 判断"原话里的哪个词系统压根没学过" |

为什么不能都用全量索引：**每次提问本身都会被写进 S/AR 层**，于是"没问到的那个词"
立刻变成了"索引里有的词"。如果用它当"学过没有"的标尺，同义词学习永远学不到东西。
（这个 bug 在实现时真的出现过，见 AAR F6。）

### 候选长什么样

```json
{"key": "打分规则", "targets": ["检索", "索排", "排序"],
 "session": "cli", "miss": "打分规则", "hit": "检索排序"}
```

每条候选都带原文证据——**低级但可解释的学习，比高级但说不清的学习更敢用**。

## 4. ③ 沉淀：从"经历"到"知识"

见 [`docs/KSTAR记忆规范.md`](KSTAR记忆规范.md) 第 4 节。要点：

- 判据是**流程重复**而不是意图重复（可复用的是流程，不是说法）；
- 归档而非删除；
- 默认 dry-run，`--apply` 才落盘。

## 5. 凭什么说"变好了"：三张表

### 表 1 · 同类任务步数（唯一真正的进化指标）

```text
$ python -m brain trend
按意图看（同一类任务的前后对比，这一张才是进化的证据）
意图     运行数  前   后   变化
-------  ------  ---  ---  -----
capture  4       1.0  1.0  +0.00
recall   4       1.0  1.0  +0.00
review   6       3.0  1.0  -2.00

结论：review：3.0 步 → 1.0 步（固化生效）；检索命中率上升（同义词/沉淀生效）
```

### 表 2 · 检索命中率

`recall / chat` 意图里 `recall_hits > 0` 的比例。演示中 67% → 100%（同义词生效）。

### 表 3 · 成功率（退化告警）

如果步数下降但成功率也下降，那是**退化**不是进化。
`trend()` 里这条判断优先级最高：`成功率下降 —— 退化信号，优先处理`。

### 为什么必须按意图分组

一次 `capture` 是 1 步、一次 `review` 是 3 步。把不同意图混在一起算平均步数，
"步数下降"可能只是"最近问的问题变简单了"。**混算的平均值可以证明任何结论，所以它不能证明任何结论。**

## 6. 审计：系统改了自己什么

每次落盘都写 `memory/db/evolution.jsonl`：

```json
{"ts": "2026-11-15T16:09:24+08:00", "kind": "skill_draft", "name": "auto-review-c264", "workflow": "memory.search>skill.run>memory.promote", "steps": 3, "reason": "新草稿技能 auto-review-c264（3 步，来自 3 次重复）"}
{"ts": "...", "kind": "alias", "key": "打分规则", "targets": ["检索", "索排", "排序"], "source": "evolve"}
{"ts": "...", "kind": "promote", "proposal": "ar→k", "reason": "工作流「…」已成功重复 3 次"}
```

**一条不落。** 一个会悄悄给自己加代码的系统，迟早会长出没人能审计的行为。

## 7. 什么**不**该被固化

| 情况 | 为什么不能 |
| --- | --- |
| 只做过一次 | 那是偶发，不是模式 |
| 含临时状态（某个具体文件路径、某次的时间戳） | 固化的结果下次就错 |
| 含不可自动化工具（`shell.run` 之类） | 白名单直接拒绝 |
| 已经是一条技能 | 重复固化会套娃 |
| 失败的流程 | 失败三次不代表它值得变成技能（但值得变成"已知坑"） |

## 8. 已知风险与缓解

| 风险 | 现在怎么办 | 还不够好 |
| --- | --- | --- |
| 草稿技能过度拟合某次输入 | 只当草稿；`version=0.1`；人工升级 | 没有自动回滚：草稿连续失败不会自动禁用 |
| 同义词学错 | 每条带原文证据，可手工删 | 没有置信度，也没有"用错了自动撤销" |
| 归档误判 | 归档可逆（改 meta 即可） | 没有"反归档"命令，只能手改 JSONL |
| 度量被小样本误导 | <4 条直接拒绝给结论 | 演示只有 14 条 trace，趋势只能当示意 |
| 阈值 3 不合适 | `--min-runs` 可调 | 没有按任务类型自适应 |

这五条都写在 AAR 的"未解决"里，没有藏。
