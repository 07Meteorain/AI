### 文档站怎么用

- **中英对照**：默认双语显示，左中右英；工具栏可切「只看中文 / 只看原文」

- **覆盖率透明**：每篇顶部显示该篇覆盖率与一手来源链接，不藏着"未译"的部分

## 四、翻译流程（怎么保证质量）

四道工序，每道都有脚本和可复核的产物：

```
① 抽取  extract  → HTML/PDF 正文 → Block → Segment（按语义分段，含代码识别）
② 翻译  translate → 注入术语表 → 分段翻译 → 缓存落盘（sha1 为键）
③ 质检  qc       → 覆盖率 / 术语 / 漏译 / 格式 / 长度比，五项自动检查
④ 构建  build    → Markdown 资料包 + 静态文档站
```

### 关键设计：为什么质量能压住

1. **术语表是唯一标准，且进prompt**
   172 条术语，每条含：规范译法、别名、**禁用译法**、说明。翻译时只注入本段实际命中的术语——避免 172 条全量注入稀释模型注意力。

2. **禁用译法是可执行的检查，不是文档里的一句话**
   术语表里的 `forbidden` 字段被 QC 脚本全文扫描。本项目实测：靠这条规则抓出并修掉了「代码审查 / 提示词工程 / 模型上下文协议 / 大型语言模型」等实际出现的偏差。

3. **质检是脚本，不是感觉**
   覆盖率、术语违规数、残留英文比例、代码围栏配对、标题/列表数一致性、中英长度比——全部自动计算，报告在 `reports/02_qc.md`，任何人可复跑复核。

4. **翻译缓存让"复跑"是真的**
   译文按原文 sha1 落盘。重跑 QC、重建站点零成本；人工校对过的译文不会被覆盖；换新课程时只有新增内容产生成本。

## 六、已知缺口（诚实说明）

`config.json` 里配置了 **35 篇**，抽取成功 **33 篇**，另有 2 篇源文件本身没有可用正文。
在成功的 33 篇中，还有 2 篇只抽到标题级内容（几十词），实质是占位页。

**（1）完全抽不出正文——2 篇，未生成译文文件**

| 文档 | 原因 |
|---|---|
| `how-warp-uses-warp` | Notion 页面，正文由 JS 动态渲染，离线缓存里没有正文 |
| `vibe-coding-playbook` | PDF 是**扫描版**（14 页无文本层），需 OCR 才能抽取 |

**（2）只抽到标题级内容——2 篇，已生成文件但正文不完整**

| 文档 | 原文词数 | 原因 |
|---|---|---|
| `good-context-good-code` | 9 | 原文被付费墙拦截，只留标题和"Enter access code" |
| `peeking-under-the-hood-of-claude-code` | 44 | Medium 明确阻止自动化访问，只留标题 |

> 因此「33/33 = 100%覆盖」的口径是：**凡是抽得出正文的部分，都100% 译完了**，
> 不等于 35 篇配置全部拿到完整正文。若按"完整正文篇数"算，是 31/35（88.6%），
> 仍高于 ≥80% 的验收线。

另有两类已知质量问题，脚本能检出但不阻塞交付（详见 `reports/02_qc.md`）：

- **PDF 排版噪声**：PDF 抽取的文本存在字符间插空格、页眉页脚残留、内容重复。已按语义清理，但个别长段落的结构仍忠实于原文，因此译文里也保留了"内容出现两遍"的现象。
- **术语歧义提示 69 条**：像「背景」（= background）、「光标」（= cursor）、「秘密武器」（= secret weapon）这类常用词，脚本无法区分"术语误译"与"普通词义"，因此只报为提示，由人工抽检。

## 七、换一门课怎么复用

管线的所有课程特定信息都在`config.json` 里。换源只需三步：

```bash
# 1. 改 config.json 的 project.source_root 指向新的资料目录
# 2. 增删 sources 列表（每条：id / type / path / title / priority / category）
# 3. 跑管线
.venv/Scripts/python pipeline/run_pipeline.py
```

抽取、分段、术语注入、质检、建站全部自动适配，无需改任何脚本。

>唯一需要人工介入的是**术语表**：新领域必然有新术语，`terms.json` 的 schema 保持不变，补几条即可。

**批量翻译**（对接自己的模型 API）：

```bash
export OPENAI_API_KEY=sk-...
.venv/Scripts/python pipeline/run_pipeline.py --provider llm
```

`--provider llm` 会自动跳过已有缓存，只补齐缺失段落。
