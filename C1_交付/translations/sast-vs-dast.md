# SAST 与 DAST 与 RASP：应用安全测试方法对比

Learn 2024 年 12 月 18 日 Shanika Wickramasinghe 
 
 全球信息安全支出预计到 2025 年将达到 2120 亿美元，较 2024 年增长 15%。Gartner 分析机构指出，生成式 AI 的兴起与云上业务的普及是这一快速增长的主要原因。该机构进一步预测，到 2027 年，生成式 AI 将参与 17% 的网络攻击。

企业需要超越传统方法的高级安全策略，才能应对这些不断增长的威胁。这正是企业所有者需要了解 SAST、DAST 和 RASP 等安全方案的原因，它们能为应用提供多层次的防护。

（延伸阅读：应用安全解析与常见的软件测试方法。）

## 什么是 SAST？

静态应用安全测试（SAST）是一种白盒安全测试方法。SAST 通过应用程序的静态源代码或二进制文件来识别漏洞。这意味着 SAST 工具是在应用程序不运行的情况下对其代码进行分析的。

开发者用 SAST 检测各类安全风险，例如跨站脚本（XSS）、不安全反序列化、缓冲区溢出，以及代码中的其他 OWASP 漏洞。由于 SAST 单独无法识别只在运行时出现的漏洞，开发者往往要把 SAST 与其他测试方法结合起来，才能实现全面的安全防护。

SAST 是软件开发生命周期的重要组成部分，因为它能尽早发现漏洞。发现得越早，修复成本越低。由于 SAST 工具可以在开发阶段执行，如今开发者能够在产品发布上线前把代码写好、测上成千上万次（！！）。

SAST 可以集成到 CI/CD 流水线中，这样做的场景通常被称为“安全 DevOps”或“DevSecOps”。SAST 借助自动化得以大规模扩展。把覆盖 SAST 技术的检测做成自动化测试，让它成为快速应对代码级风险的高效方案。

## 什么是 DAST？

动态应用安全测试（DAST）是一种黑盒测试方法。DAST 中的“动态”意味着它在应用程序运行期间评估其安全性。与 SAST 不同，DAST 不需要访问应用程序的源代码。相反，它：

- 模拟外部攻击者的行为。

- 从外部对应用程序进行测试，找出只在运行时才会暴露的漏洞。

DAST 能够识别拒绝服务（DoS）漏洞、不安全的服务器配置等各种安全缺陷。通过模拟真实世界的攻击场景，DAST 工具评估应用程序面对这些模拟威胁时的响应。借助这种方式，开发者可以发现 SAST 这类静态测试方法可能遗漏的弱点。

通常，开发者会在软件开发生命周期的后期执行 DAST，往往就在部署之前。通过在类生产环境中测试应用程序，DAST 能清晰呈现运行时的安全状况，并帮助打造出更能扛住潜在攻击、性能更好的应用程序。

## SAST 是如何工作的？

开发者使用 SAST 工具应用预定义规则和其他检测方法——比如模式匹配和数据流分析——来识别编码错误与其他漏洞。他们把这些工具集成进 IDE 或 CI/CD 流水线，在编码和测试阶段自动执行扫描。

### SAST 常用方法

以下是 SAST 中常用的一些方法。

模式匹配扫描代码库，寻找已知的不安全编码实践模式，例如使用了弱加密算法或不安全的 API 调用。

数据流分析跟踪数据在应用中的流动路径。通过追踪不可信输入到敏感操作的路径，它可以识别 SQL 注入、缓冲区溢出这类漏洞。

控制流分析可以分析应用程序的控制结构，例如循环和条件分支，从而发现逻辑缺陷或竞态条件这类潜在漏洞。

自定义规则创建。许多工具允许开发者创建自定义规则，用来落实编码最佳实践。以下是一些自定义规则的示例：

- 标记 SQL 查询中任何未经净化的输入。

- 识别把用户提供的数据未经正确转义就输出到浏览器的代码。

- 高亮使用存在漏洞或已弃用函数的地方，例如 JavaScript 中的 eval() 或 C 中的 strcpy()。

- 检测源代码中硬编码的 API 密钥和密码，并标出用户提供的数据缺少输入校验的地方。

依赖扫描。部分 SAST 工具会分析应用程序用到的第三方库和框架，以发现依赖中的漏洞。

语义分析。通过理解代码的含义而非仅仅看结构，SAST 工具可以发现不安全的配置或 API 误用。

机器学习模型：先进的 SAST 工具会引入机器学习算法，通过分析大规模数据集中的模式来识别此前未知的漏洞。

### 使用 SAST 工具时的性能考量

SAST 工具通常要占用大量 CPU 和内存资源。在分析大型代码库时，这可能是个大问题。对一百万行代码做一次完整扫描，可能要消耗数 GB 内存。

SAST 扫描所需时间随代码库规模差异巨大，小项目可能几分钟，企业级应用则可能数小时。这会影响：

- 构建流水线的时间安排

- 开发者效率

可以考虑使用支持增量扫描的现代 SAST 工具，这样只分析变更的代码，而不必扫整个代码库。

此外，通过规则选择和范围定义来做性能调优也很关键。配置不当的 SAST 工具会去分析非关键代码路径，白白浪费时间和资源，却拿不到任何安全收益。

## DAST 是如何工作的？

DAST 工具模拟真实世界的攻击——例如把各种形式的恶意数据送进输入字段，观察应用程序如何处理它们——以识别应用程序行为与响应中的漏洞和弱点。

### DAST 的步骤

整个过程通常包括以下步骤。

第 1 步：扫描。扫描 Web 应用程序，发现入口点（例如 URL、表单和 API）。这一步梳理出应用程序的结构，并识别出潜在的攻击面。

第 2 步：攻击模拟。向应用程序发送精心构造的请求，以模拟恶意活动。这些请求通过尝试利用入口点，检验是否存在跨站脚本、跨站请求伪造这类漏洞。

第 3 步：漏洞检测。分析应用程序的响应，找出安全弱点。它评估应用程序在遭受攻击时的行为是否符合预期。例如，可以注入恶意数据来检测 SQL 注入缺陷。

第 4 步：报告。生成包含所发现漏洞和缓解措施建议的报告。开发者可以依据报告中的结果修复已识别的问题。

现代 DAST 方案可以融入 AI 驱动的分析、实时数据集成等高级能力。它们自动生成测试集，动态适配应用程序的结构，并用机器学习算法把误报降到最低。

### 使用 DAST 工具时的性能考量

使用 DAST 工具时，有几个性能瓶颈需要留意。

- DAST 工具会主动与运行中的应用程序交互，在应用程序和 Web 服务器两侧临时抬高 CPU 与内存占用。

- DAST 扫描期间产生的大量并发请求会占用可观的网络带宽。

- DAST 扫描器常通过生成唯一请求来绕过或让应用程序缓存失效，从而削弱缓存机制的效果。

- DAST 工具创建和管理多个测试会话，会增加应用程序服务器的内存占用。

要避免这些问题、或尽量减小它们的影响，请遵循以下做法。

- 把 DAST 扫描安排在应用使用量最低的非高峰时段。

- 在与生产环境配置一致的预发布或准生产环境中执行扫描。

- 使用 DAST 工具的限流功能来控制并发请求数量。

- 在扫描期间增大应用程序服务器的线程池。

- 为 DAST 扫描器的 IP 单独配置缓存策略。

- 实现性能阈值超限后自动暂停扫描。

## SAST 与 DAST 的优缺点

### SAST 的优点

- 能在软件开发生命周期的早期识别安全漏洞。

- 分析整个代码库，包括基础函数和复杂分支。

- 直接作用于源代码，无需应用程序运行。

- 提供实时反馈和全面的洞察，例如漏洞的确切位置。

- 生成可导出的报告，可以通过仪表盘追踪。

- 支持自动化，因此比人工代码评审更快、更高效。

### SAST 的缺点

- 常常产生大量误报，因此可能需要人工复核。

- 无法识别运行时或环境特有的漏洞，例如配置错误。

- 需要针对每种编程语言分别适配工具，维护起来比较复杂。

- 难以理解外部库、API 和 REST 端点。

### DAST 的优点

- 能识别只在应用程序执行期间才出现的漏洞。

- 从外部工作，无需访问源代码。这对测试第三方应用程序或已编译代码很有效。

- 模拟真实攻击场景，发现 SAST 漏掉的风险。

- 不依赖应用程序使用的编程语言。

- 评估整个应用和系统，包括内存消耗、资源占用和第三方接口。

### DAST 的缺点

- 只关注应用的外层，可能漏掉更深层的漏洞。

- 在 SDLC 后期才应用，因此修复成本更高、更耗时。

- 会漏掉一些 SAST 工具能通过源代码分析发现的漏洞。举个例子，某个 Web 应用程序用不安全的随机数生成器（例如 JavaScript 中的 Math.random()）生成会话 token。DAST 可能发现不了这个缺陷，因为它只测试运行时行为。（但 SAST 能检测出来。）

- 大型项目需要自定义基础设施来让应用多个实例并行运行，因此资源消耗大。

## 什么时候该用 SAST，什么时候该用 DAST？

SAST 和 DAST 在保障 SDLC 安全方面扮演互补角色。理解各自适用的时机，有助于获得全面的安全覆盖。

### 何时使用 SAST

在开发早期阶段。开发者用 SAST 在 SDLC 早期识别 SQL 注入、硬编码凭据这类漏洞。在部署前就把这些问题拦住，可以降低修复它们的成本和复杂度。

例如：SAST 工具扫描 Python 代码，标记出源码中嵌有硬编码 API 密钥的漏洞。开发者重构代码，改用环境变量来安全地存储和获取密钥。

用于代码评审。SAST 集成到版本控制系统后，可以让开发者在提交代码前先扫描一遍，确保进入仓库的只有安全代码。

示例：SAST 工具可以检测出这样一类漏洞——文件路径未经校验就直接由用户输入拼接而成，使应用暴露在路径遍历攻击之下。开发者通过对输入做净化处理、并使用安全的库函数处理文件路径来修复该问题。

在持续集成/持续部署流水线中。SAST 在 CI/CD 过程中执行自动化扫描，为开发者提供实时反馈。

### 何时使用 DAST

预生产测试。开发者在预发布或 QA 环境中用 DAST 识别运行时漏洞（例如不安全的配置、认证缺陷、访问控制不足）。

示例：DAST 工具可以检测出会暴露敏感数据的数据库配置错误。这样开发者就能在部署前把配置加固。

在部署后监控中。DAST 工具会持续扫描已部署的应用程序，找出由环境变化或新出现威胁导致的漏洞。这保证了应用程序随时间推移依然安全。

测试第三方集成。DAST 可以模拟外部攻击者的视角，找出第三方 API 或互联系统中的漏洞。

例如：DAST 工具测试某个 Web 应用程序，发现第三方支付 API 存在漏洞——信用卡信息正通过未加密的 HTTP 连接传输。开发者通过对所有 API 通信强制启用 HTTPS 来解决问题。

## 哪个更有效：SAST 还是 DAST？

SAST 或 DAST 的效果取决于：

- 所处的 SDLC 阶段

- 所针对的漏洞类型

SAST 最适合在开发早期使用，主要用于识别源代码中的漏洞、降低成本并推动安全编码实践。相比之下，DAST 关注预生产或已部署应用程序中的运行时漏洞，能就配置错误、集成不安全之类的问题提供洞察。

### 采用混合方式

与其二选一，不如把 SAST 和 DAST 结合起来，形成多层次的安全策略，同时覆盖静态代码和运行时环境中的漏洞。SAST 可以集成到开发早期阶段，在应用程序编译之前发现并修复代码级问题。待应用程序在测试环境中运行起来后，DAST 可以识别运行时漏洞，并评估应用程序在遭受攻击时的行为。

把 SAST 和 DAST 扫描都自动化到 CI/CD 流水线中，可以提供持续反馈，在不牺牲安全的前提下加快开发流程。

对于敏捷或 DevOps 环境，加入 IAST 或 RASP 之类的工具可以进一步增强安全。通过关联 SAST 与 DAST 的结果，组织能够实现更全面、更有效的漏洞管理。

### 用 RASP 作为 SAST 和 DAST 的补充

运行时应用自我保护（Runtime Application Self-Protection，RASP）是一种高级安全方案，直接安装在应用程序运行的服务器上。

RASP 会嵌入到应用程序的运行时环境中。这种集成方式让 RASP 能够分析应用的逻辑和数据。在分析过程中，它可以：

- 即时检测异常行为。

- 立即阻断恶意活动。

一个关键差别在于，RASP 不只是对潜在问题发出告警——它会主动防御，通过隔离和处置威胁来阻止攻击，不依赖外部工具。

RASP 为 SAST 和 DAST 提供了一种动态替代方案。SAST 分析静态代码，DAST 模拟外部攻击，而 RASP 实时运行。它在应用程序执行期间监控其行为，通过终止会话或向防御方告警来应对实时威胁。

RASP 在防护那些绕过网络防御、或在开发阶段被遗漏的漏洞方面尤其有效。

不过，对 RASP 过度自信会让组织忽视安全编码实践。此外，RASP 直接在应用程序的运行时环境中工作，可能影响应用性能。RASP 无法取代修复底层缺陷的必要性，但它能在缓解措施落实期间提供持续防护。

一位 RASP 用户的评论如下：

“是否采用 RASP 工具，应当基于对应用程序具体需求和风险画像的全面评估。”

## 未来是用 SAST、DAST 和 RASP 做应用安全测试

应用测试的未来在于把 SAST、DAST 和 RASP 结合起来，形成综合性的安全策略。随着安全挑战不断增加，把这些工具集成进 CI/CD 流水线并实现流程自动化将变得不可或缺。

AI 与机器学习领域的进步会让测试更高效，因为它有助于减少误报并提升威胁检测能力。

### 金融与金融服务业

在金融领域，AI 驱动的工具将改变漏洞检测与缓解的方式。SAST 和 DAST 会继续在开发和预生产阶段识别编码缺陷与运行时问题。

但这还没完：RASP 会更进一步，用 AI 监控实时交易。例如，RASP 可以检测出异常模式（比如攻击者正在实时尝试利用某个漏洞），在阻断这些行为的同时通知安全团队。

### IoT、边缘计算与联网设备

在 IoT 领域，这些工具的组合将在保护联网设备安全方面发挥重要作用。具体来说：

- SAST 可以确认固件在开发阶段不含漏洞。

- DAST 可以测试设备之间通信协议的安全性。

- RASP 则监控已部署的设备，检测并阻止未授权访问尝试，或由新出现威胁导致的数据泄露。

同样地，运用多种方法有助于让 IoT 生态保持韧性。正如我们在诸多示例中所说明的，SAST、DAST 与 RASP 组合在一起，预示着一个应用以更强健、更主动的安全措施来构建和部署的未来。

## 有韧性的安全始于主动测试

把 SAST、DAST 和 RASP 结合起来，可以覆盖整个软件开发生命周期，提供稳健的安全能力。

通过把这些方法集成进 CI/CD 流水线并利用 AI 领域的进展，组织可以主动应对新出现的威胁。这些方法合在一起，为守护现代应用免受漏洞侵害提供了全局性的方案。
