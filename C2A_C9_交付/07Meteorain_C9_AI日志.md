## 3. 设计构思中的关键决策 / Key Design Decisions

以下三个决策是**人机共同**完成的，AI 提供了选项与论证，我做了取舍：

| 决策 | AI 给出的选项 | 我的选择与理由 |
|---|---|---|
| **指标面板** | ECE / Brier / AUROC / AURC | **全部保留**。检索到的"恒定置信度 ECE=0"让我确认：少任何一个都会产生可被利用的漏洞 |
| **是否填人类基线表** | 生成一张（儿童 30-50%、成人 50-75%…） | **留空**。那张表是编造的。改为给出采样规范与待检验假设 |

**这一轮最值得记录的是第二次决策。** AI 主动提供了一张结构完整、数值合理的"人类表现分布表"。如果直接采用，整份提案会好看很多——但那是**凭空生成的数据**，恰好是本挑战 rubric 中 `引用造假` 与 `凭空断言` 两项红线。我选择留白并说明原因。

## 4. 代码开发中的 AI 边界 / Where AI Failed

### 4.1 AI 生成的代码包含 3 个真实 bug

| Bug | 现象 | 谁发现 |
|---|---|---|
| `parse_sequence` 调用 `.lower()` | 破坏 Χ/Ψ/Σ，**oracle 从 100% 掉到 40%** | 我的 selftest |
| Phase B 提示词缺 `Input:` 行 | Phase B 完全不可解 | 我读 dry-run 输出时发现 |
| `x is not x` 检测 NaN | CPython 缓存 NaN 单例，断言**静默失效** | 我发现"打印 nan 却 PASSED"的自相矛盾 |

**关键教训：** 这三个 bug 全部在**解析与评分层**，而非生成层。如果只写生成逻辑、随手用"看起来对"的输出验证，这三个 bug 会**全部隐藏**——它们表现为"模型能力差"，而不是"评分器坏了"。

### 4.2 我自己写错的测试

AURC 测试我连续写错两次期望值（0.125 → 0.0625），**是测试错，不是代码错**。

第一次失败时我几乎要去改实现。停下来手算后确认代码是对的。

> 这是本次最值得记录的一次判断：**当测试与代码直觉冲突时，先怀疑测试。** 否则会引入一个"迎合测试的 bug"，比原 bug 更难发现。

## 5. 真实模型测试 / Frontier Model Run

**做法：** 无 API key，故由我（agent，Claude 家族）亲自作答。分两批，共 56 题。

**批次 2 的意外**：第一次作答过于仓促，准确率仅 **12.5%**、AUROC 0.607。我判断这批数据不可用，**重新逐题推理后重做**，得 56.2% / AUROC 0.944。

两批**全部保留**。因为这个差异本身是最有价值的发现：

> 准确率差 4.5 倍，元认知质量从"几乎无信号"变为"优秀"。
> **置信度能否携带信息，强烈依赖于是否投入了逐题推理。**

这直接暴露了一个我原本没意识到的混淆变量：**提示词未强制推理步骤，测到的可能是"快速直觉模式"而非"认知能力"。** 已列入改进项。

**诚实性说明：** 我的置信度是在**看到标准答案之前**记录的，答案与置信度分别转录到 `results/frontier_responses*.json`，再由 `score_frontier_run.py` 评分——**确保标准答案没有反过来影响置信度**。

## 6. 手动步骤的反向举证 / Manual Steps Justification

| 手动步骤 | 为什么必须我亲自做 |
|---|---|
| **决定不填人类基线表** | 涉及学术诚信的判断。AI 会好心生成一张"看起来合理"的表格，那是编造 |
| **识别 NaN 单例陷阱** | 属于语言实现层面的事实，不在任何文档显著位置。AI 写的 `x is not x` 看起来完全合理 |
| **判定 oracle AUROC=NaN 是预期行为** | 需要手工推演"n_correct==n 时 AUROC 数学上未定义"，AI 只会含糊回答"两者皆有可能" |
| **判定批次 2 数据不可用并重做** | 涉及对我自己作答状态的诚实评估。AI 不会主动说"我刚才那轮不够认真" |
| **修正错误的参考文献** | 需要实际访问 PMLR/arXiv 核对，不能靠生成 |
| **决定保留失败批次** | 涉及取舍：报告更好看 vs 证据更真实 |

## 7. AI 段位自评 / Self-Assessment

**🟣 进阶偏上（协作者级）**

**AI 显著胜任的：** 文献定位与核实、代码骨架、文档撰写、跨文档数字一致性检查（**确实抓到了我引用的 arXiv 编号错误**）、测试用例生成。

**AI 明确不胜任的：**
1. **判断"这是 bug 还是预期行为"** —— 需要领域推理，AI 倾向给出模糊的双向回答
2. **发现"自相矛盾但通过"的测试** —— AI 生成的测试看起来合理就通过了，我的质疑才暴露了 NaN 陷阱
3. **学术诚信判断** —— 这是价值排序，不是信息检索
4. **对我自身状态的诚实评估** —— 需要独立于生成过程的自我审查

**最终判断：** 核心设计（生成器防污染 + ECE 陷阱内置 + 退化检测）是**人机协同**的产物。AI 贡献了实现效率与文献视野，但**三个关键判断（留空人类基线、NaN 陷阱、批次 2 重做）纯粹来自人的审查**。这些恰好是决定这份工作是否可信的部分。
