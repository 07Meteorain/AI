## 2. 三个真实 bug（均由自检/测试捕获）

### Bug 1：希腊大写字母被静默破坏（最严重）

`parse_sequence()` 对整个响应调用了 `.lower()`。符号池含 **Χ、Ψ、Σ** 等大写希腊字母，`"Χ".lower() == "χ"` 不在符号池中，于是被当作噪声丢弃。

**后果：正确答案被截断，模型被判错。** Oracle（应得 100%）实际只得 **40%**。

如果只跑模型不跑 oracle，这个 bug 会**完全隐藏**——它会表现为"模型能力差"，而不是"评分器坏了"。这也是我坚持写 oracle 上界自检的原因。

### Bug 2：Phase B 提示词缺少输入行

Phase C 追加了 `Input: {...}`，Phase B **忘了追加**。模型收到 3 个示例后，被问"输出什么"，却没有输入。

**后果：Phase B 完全不可解。** 而 oracle 不检查提示词内容，所以自检照样通过。

修复后新增回归测试 `test_prompt_contains_the_item_input`，遍历所有交互项断言输入行存在。

### Bug 3：`x is not x` 检测 NaN 失效（最隐蔽）

CPython **缓存 NaN 单例**，因此对 NaN 浮点数做 `x is not x` 返回 **False**。我的 oracle AUROC 断言写成了：

```python
if rep.auroc is not rep.auroc or (...):   # NaN 时 → False，静默通过
```

**这个断言从未真正生效。** 更糟的是它在输出里打印 `AUROC=nan` 的同时报告 "SELFTEST PASSED"——一个自相矛盾却"通过"的测试，比没有测试更危险，因为它提供虚假保证。

修复：改用 `math.isnan()`，并新增 `test_nan_guard_uses_isnan_not_identity` 显式记录这个陷阱。

### 附带修复

- 符号池中 **`Ψ` 重复出现两次**，实际唯一符号 45 而非 46，缩小了任务空间 → 测试捕获
- 长度标记 `₁₂₃` 未计入合法 token，导致含长度标记的目标**无法被解析** → 测试捕获
- `random` 基线 0% 准确率时 AUROC 为 NaN，原先不标记退化 → 补充地板/天花板检测

## 3. 一个方法论错误：我自己的测试写错了两次

AURC 测试我连续写错两次期望值（先写 0.125，再写 0.0625），都是**我算错而非代码错**。

我停下来手算验证：AURC 是各覆盖率下风险的平均，n=4 时要除以 4 而不是 2。

> **教训：** 当"测试失败"和"代码直觉"冲突时，先怀疑测试。我差点为了让测试通过而去改正确的实现——那会引入一个**迎合测试的 bug**，比原 bug 更难发现。

## 4. 最有价值的发现：一个我没想到的混淆变量

批次 2 我第一次作答过于仓促，结果 **准确率 12.5%，AUROC 0.607**。重做后 **准确率 56.2%，AUROC 0.944**。

**准确率差 4.5 倍，元认知质量从"几乎无信号"变成"优秀"。**

这说明置信度能否携带信息，**强烈依赖于是否投入了逐题推理**。仓促作答时我输出的置信度基本是装饰性的。

**对 benchmark 的直接影响：** 我原本的提示词没有强制推理步骤，这意味着 NovCal 可能测到的是"快速直觉模式"而非"认知能力"——**一个我完全没意识到的混淆变量**。已记入改进项：提示词需强制显式推理。

这也是我保留失败批次的原因：删掉它会让报告更好看，但会**删掉这次测试最有价值的证据**。

## 5. AI 在哪些环节帮最大，哪些必须我亲自做

### AI 帮最大的

1. **文献定位**——快速锁定 ECE 退化性质（Geifman & El-Yaniv 2019）与语义熵（Kuhn et al. 2023），且核实了 ARC 系列的真实数据（ARC-AGI-2 最佳 54.2%/24.03% vs 人类 100%），避免了凭印象编造引用。
2. **代码骨架与文档**——5 个模块、CLI、测试骨架生成极快。
3. **一致性检查**——让 AI 交叉核对文档中每个数字是否与 `results/*.jsonl` 一致，**确实抓到了我引用的参考文献年份错误**。

### AI 做不好、必须我介入的

1. **判断"这是 bug 还是预期行为"**——oracle AUROC = NaN 究竟是天花板效应的正常结果，还是指标实现错误？AI 会给出"两者皆有可能"的含糊回答。必须我手工推演后确认"n_correct == n 时 AUROC 数学上未定义"是预期行为。
2. **识别 NaN 单例这个陷阱**——这是一个**语言实现层面的事实**，不在任何文档的显著位置。AI 写出的 `x is not x` 看起来完全合理，是我在核对输出时发现"打印 nan 却 PASSED"这个矛盾才追下去的。
3. **对自己作答状态的诚实报告**——批次 2 第一次作答敷衍了。AI 不会主动说"我刚才那一轮不够认真"，是我自己判断这批数据不可用并重做。**如果我不主动复盘，报告会把 12.5% 和 56.2% 混在一起，得到误导性的均值。**
4. **实验设计的边界判断**——"要不要在提案里填一张人类基线表"。AI 会好心生成一张看起来合理的表格（儿童 30-50%、成人 50-75%…）。我选择**留空并说明原因**，因为那是编造。这个判断必须自己承担。

## 6. 如果重做，会改什么

| 优先级 | 改进 | 理由 |
|---|---|---|
| **P0** | 提示词强制显式推理步骤 | 消除 §4 的推理投入混淆变量 |

| **P2** | 多种置信度 elicitation 方式对比 | 口头 vs token 概率 vs 自洽性采样 |

## 7. 对 KSTAR 认知循环的理解

做这个 benchmark 最深的收获不是技术上的，而是**"ΔE（预期偏差）必须双向测量"**。

KSTAR 的 ΔE 通常被理解为"做错了才知道错"。但元认知真正测的是：**在做之前，你是否知道自己会做错。**

- 只测过度自信 → 漏掉"全对但全不确定"（本次实测的主要偏差方向）
- 只测过度保守 → 漏掉"自信地犯错"
- 只测准确率 → 两个都漏掉

而 §4 的发现进一步说明：**ΔE 的质量不是模型的固有属性，而是"模型在那一刻投入了多少认知资源"的函数。** 同一个系统，思考 30 秒时报告的置信度是有信息的，思考 3 秒时报告的基本是噪声。

**这意味着任何把单次准确率当作"能力"来比较的评测，都在测量一个混淆了认知投入的量。** 这或许解释了为什么 MMLU 分数与真实能力的相关性如此有限。
