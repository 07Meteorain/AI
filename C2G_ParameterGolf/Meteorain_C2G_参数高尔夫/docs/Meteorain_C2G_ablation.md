## 0. 实验条件（读表前必看）

**七个实验的唯一差异是那一个被测开关。** 其余全部固定。

| 条件 | 值 |
|------|-----|
| 硬件 | 1× NVIDIA GeForce RTX 3050 Laptop GPU（4GB，sm_86） |
| 模型 | 6 层 × 256 维，8 heads / 4 KV heads，MLP 2×，tied embedding |
| 参数量 | 3,021,616 |
| 序列长度 / batch tokens | 512 / 32,768 |
| 训练量 | **固定 1,000 步** = 32,768,000 tokens |
| 优化器 | Muon（Newton-Schulz 5 步）+ AdamW，bf16 autocast，eager |
| 验证集 | 官方冻结 FineWeb val 的前 1,000,000 tokens（`MAX_VAL_TOKENS`）|
| seed | 1337 |
| 单实验耗时 | 约 24 分钟（训练 ~23.5 min + 评估）|

### 为什么用「固定步数」而不是「固定 wallclock」

如果按 wallclock 截断，eager 模式下每个实验只跑约 500 步，而编译模式能跑 1000 步——**计算量不同，所有比较立即失效**。固定步数保证「唯一变量是那个开关」，且换硬件/换编译模式后结论依然成立。

### 这些数字不能与官方榜单比较

我的 BPB 绝对值必然显著高于官方 baseline（1.2244），因为**我少训练了约 220 倍的 token**。**唯一可比的是同一张表内的差值。**

## 2. ✅ 改动 A：滑窗评估（主要贡献，−0.01786）

### 这是本次最干净的一个结论

我做了一个**教科书级的对照实验**：

E0 和 E1 的训练配置、seed 完全相同 → **产生的是同一份权重**。证据有三条：

| 证据 | E0 | E1 |
|------|-----|-----|
| 训练结束时 chunked 分数 | `val_loss:2.94739878  val_bpb:1.76659933` | `reference_chunked_eval val_loss:2.94739878 val_bpb:1.76659933` |
| artifact 大小 | 3,727,789 | 3,727,789 |
| 最终步 train_loss | 2.8710 | 2.8710 |

**逐位相同到小数点后 8 位。** 所以 E1 与 E0 的分数差（1.74874 vs 1.76660 = **0.01786**）**100% 来自评估方式**，与模型能力无关。

这是我在方案草案里设计这个对照实验的原因——如果用两个不同训练的模型对比，「模型差异」会污染「评估差异」的结论。

### 增益的来源

baseline 把验证集切成互不重叠的 512-token 块，块内第一个 token 上文为 0，平均每 token 只有约 256 个上文。
滑窗（stride=64）让每个 token 至少拿到 512−64 = 448 个上文。

**收益 0.01786 < 上游的 0.0319**，原因很明确：我的模型训练量小得多（32.8M vs 7.2B tokens），**模型利用长上下文的能力本身更弱**。上下文给得更多、但模型用不好的话，收益自然打折。

> **一个诚实的修正**：我原以为「上下文增益」是评估方式的固有属性，现在看来它**依赖模型已经学会用长上下文**。这比我原来的理解更精确。

### 代价

评估耗时从 20.8s 涨到 154.1s（**7.4×**）。因为窗口数是 `total_tokens / stride`。

在官方口径下这完全可接受（评估有独立的 600s 预算，实测约 500s）。但如果继续调小 stride，耗时会成比例上升——**这是可交换的，不是免费的**。

## 3. ⚠️ 改动 C：并行残差 —— 我犯的一个实验设计错误

### 现象

E3 的分数与 E0 **完全相同**（1.76660），artifact 也完全相同（3,727,789）。第一反应是「并行残差无影响」。

### 但真正的原因是：**它根本没有生效**

我检查了代码：

```
num_layers=6, start=7 -> 各层 parallel 标记: [False,False,False,False,False,False]  实际启用层数=0
num_layers=9, start=7 -> 各层 parallel 标记: [False,...,False,True,True]             实际启用层数=2
```

上游 SOTA 的 `PARALLEL_RESIDUAL_START=7` 是在 **11 层**模型上调的。我的模型只有 **6 层**，所以 `layer_idx >= 7` 永远不成立——**0 层启用**。

**E3 是一次 no-op 实验，不是「并行残差无效」的证据。**

这是我方案设计里的一个真实漏洞：我在方案草案里把并行残差标为「待实测决定」，但**没有检查它在本地配置下是否真的有层被启用**。我把「照搬上游超参数」当成了「沿用上游技术」，而这两者在模型规模不同时完全不同。

### 修正

1. 在训练脚本里加了**显式自检**，今后这类静默失效不可能再无声发生：
   ```
   parallel_residual_enabled_layers:0/6 start:7
   WARNING: PARALLEL_RESIDUAL=1 but start=7 >= num_layers=6; NO layer actually uses parallel residual.
   ```
2. 新增 **E3b**：`PARALLEL_RESIDUAL_START=3`（6 层模型下有 3 层真正启用），结果见 §7。

> **教训**：照搬别人超参数时，必须验证它在**你的**规模下是否有意义。超参数不是技术的组成部分，它只是特定规模下的产物。

## 4. ❌ 改动 D：QK-gain = 5.25 实测有害（+0.00832）

### 结果

| 指标 | E0 (gain=1.5) | E4 (gain=5.25) | 变化 |
|------|--------------|---------------|------|
| val_bpb | 1.76660 | 1.77492 | **+0.00832（更差）** |
| 最终 train_loss | 2.8710 | 2.8786 | +0.0076（更差） |
| artifact | 3,727,789 | 3,724,638 | −3,151 |

**训练 loss 和验证 BPB 同时变差** → 这不是评估噪声，是真实的训练退化。

### 为什么会这样

上游记录说「QK-Gain 5.25 —— 从 4.0 到 5.25 单调改进」。但那是**在 11 层 + SP8192 + 8×H100 + 13,780 步**上调出来的。

`q_gain` 缩放 attention logits → 控制 softmax 锐度。增益大小取决于：
- **q/k 的实际范数**（深层模型里 QK-Norm 后的范数分布不同）
- **需要多大的锐度才能维持长程依赖**

我的模型只有 6 层、训练 32.8M tokens，远欠拟合。**在欠拟合状态下强行把注意力锐度提高 3.5 倍，只会加剧注意力过早收敛（over-sharpening）**，损害信息聚合。

### 我的决策

**把 QK-gain 从最终组合中剔除，保留 1.5（baseline 值）。**

我不打算扫 1.5/3.0/5.25 三档来找最优——那需要另外 2 次 24 分钟实验，而我已经有明确证据表明「照搬 5.25 有害」。**更重要的是：这恰好证明了超参不可移植。**

> 如果我不做这个实验、直接采用 SOTA 的 5.25，我的方案会**比 baseline 更差 0.008**。这就是「照搬 vs 验证」的实际代价。

## 5. ⚠️ 组合实验 E6：全开反而比单项更差

| 配置 | val_bpb | Δ vs E0 |
|------|--------:|--------:|
| E6 全开（A+B+C+D+E） | 1.77404 | +0.00744 |
| **E1 仅滑窗（最佳单项）** | **1.74874** | **−0.01786** |

**E6 比 E1 差了 0.0253 BPB。** 而 E6 = E1 + B + C + D + E，其中：
- B = −0.00066（有益）
- C = 0（no-op）
- D = +0.00832（有害）
- E = −0.00072（有益）

**简单相加预测**：−0.01786 − 0.00066 + 0 + 0.00832 − 0.00072 = **−0.01092**
**实际 E6 相对 E0**：+0.00744

**实测比加法预测差了 0.0184** → 存在**明显的负向交互**。

### 我的归因（诚实标注置信度）

| 解释 | 置信度 | 说明 |
|------|-------|------|
| D 拖累 + 交互放大 | **中** | D 单独 +0.0083，组合中可能因 LR 调度变化而更糟 |
| 改动的组合改变了有效学习率 | **中** | E（MLP_LR 0.04→0.06）与 D（锐度↑）叠加，可能导致等效步长过大 |
| 单seed 噪声 | **低但非零** | 各实验差值量级 0.0007~0.0179，噪声不太可能造出 0.0184 的偏差 |

**但我没有做 3 seed 验证来确认这一点**——这是一个**未闭合的归因**，我如实标注。

### 决策

**E6 不是一个可用的配置。** 我基于 E0~E5 的**单项结果**重新组合，只保留实测有效的三项（A + B + E），得到 **E7_best_validated**，并对它跑 3 个 seed 验证稳定性。

这正是消融实验的价值所在：**如果我只测「全开 vs baseline」，我会得出「我的方案有害」的结论；但逐项拆解后发现真正的问题只是其中一个组件。**

## 6. ✅ 改动 B：fp16 嵌入直传（−0.00066，代价 +157KB）

E0 与 E2 训练配置相同 → 同一份权重，唯一差异是**量化时嵌入层的处理方式**。

| | E0 (int8) | E2 (fp16) |
|---|-----------|-----------|
| val_bpb（均为 chunked） | 1.76660 | **1.76594** |
| `fp16_passthrough_bytes` | 0 | 524,288 |
| int8 payload | 4,233,408 | 4,493,504 |
| artifact 总计 | 3,727,789 | 3,884,985（**+157,196**）|
| 16MB 余量 | 12,272,211 | 12,115,015 |

**差值 0.00066 就是量化损失被削减的量。**

上游在 9×512 配置上报告「量化退化从 0.007 降到 0.0005」。我的绝对量级小（0.00066），因为我的模型小得多——**嵌入层占总参数的比例在 3M 参数模型中远低于 20M 参数模型**，所以量化误差的绝对影响也更小。

**这个 0.00066 值不值得多花 157KB？** 在我的配置里 artifact 只用了 3.88MB / 16MB，**空间完全不是瓶颈**，所以值得。**但在官方 9×512 配置下，多花约 512KB 就会逼近上限**，那里必须做权衡（缩 MLP hidden）。详见 `方案设计.md` §2-B。

## 7. ✅ 改动 E：LR/warmdown 调优（−0.00072，且 artifact 最小）

| 指标 | E0 | E5 |
|------|-----|-----|
| val_bpb | 1.76660 | **1.76588** |
| 最终 train_loss | 2.8710 | **2.8699** |
| artifact | 3,727,789 | **3,562,006（最小，−165,783）** |

**唯一同时做到「分数更好」和「artifact 更小」的改动。**

原因：`MATRIX_LR` 0.04→0.06 让权重在有限步数内探索得更充分，最终权重分布「更整齐」→ zlib 压缩率更高。这是个**意外的正向副作用**，我原本只预期它改善 BPB。

**注意**：`warmdown_iters` 从 1200→3600 在我的实验里影响有限，因为 `MAX_WALLCLOCK_SECONDS=0`（不按时间截断），`lr_mul` 走的是**按步数**分支。这与官方 8×H100（按时间截断）的行为**不同**。所以 E5 的收益主要来自 `MATRIX_LR` 而非 warmdown 窗口——**这是我的实验条件与官方口径的一个具体差异，必须标注。**

## 8. ⚠️ 一个我必须承认的局限：没有对照实验的组合项

我的消融矩阵测了 **E0→E5 的所有单项**和 **E6 全组合**，但**没有测 A+B、A+E、B+E 等两两组合**。

**后果**：E7（A+B+E）的 −0.0186 是**基于加法假设**预测的（−0.01786 − 0.00066 − 0.00072），而 E6 恰恰证明了「加法假设不成立」。**所以 E7 的实际值可能偏离我的预测。**

E7 的 3 seed 实验会给出真实数字。如果它明显偏离预测，那本身就是「交互效应」的进一步证据，我会如实报告。

## 9. 结论

### 有效且可采纳

| 改动 | 收益 | 代价 | 采纳 |
|------|------|------|------|
| A 滑窗评估 | **−0.01786** | 评估耗时 ×7.4 | ✅ 采纳 |
| E LR 调优（MLP_LR↑） | −0.00072 | 无（artifact 反而变小）| ✅ 采纳 |
| B fp16 嵌入直传 | −0.00066 | +157KB（本地）/ 约+512KB（官方）| ✅ 本地采纳；官方需权衡 |

### 无效或有害，已剔除

| 改动 | 实测 | 处置 |
|------|------|------|
| C 并行残差 (start=7, 6层) | no-op（0 层启用）| ⚠️ 修正为 start=3 重测，见 E3b |
| D QK-gain=5.25 | **+0.00832（有害）** | ❌ 剔除，保留 1.5 |

### 最重要的一条元结论

> **上游榜单技术是有前置条件的。** QK-gain=5.25 在 11 层模型上单调改进，在我的 6 层模型上造成 +0.008 的真实退化。**照搬别人的超参数不是实验，是假设。**
>
> 如果我不做 E4，我会直接把 5.25 写进最终方案，**交出一个比 baseline 更差的成绩**，而且完全不知道原因。
