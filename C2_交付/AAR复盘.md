# AAR 复盘 — C2 挑战（AI for Math 论文）

> **AAR** = After Action Review（行动后复盘）。
> 挑战要求「七维 AAR」。本文采用如下七维框架，每维给出：预期 → 实际 → 差异归因 →
> 改进方案。**失败经验单独成节，不做美化。**
>
> 维度定义：
> 1. 目标对齐　2. 资源与工具　3. 流程设计　4. AI 使用质量　5. 产出质量　6. 协作与迭代　7. 效率与可复现

---

## 维度一：目标对齐（Goal Alignment）

**预期**：严格对齐 `CHALLENGE.md` 的四项交付物（`paper.tex`、`references.bib`、
AI 日志、AAR）与 `rubric.json` 的五维评分，并遵循 `materials` 中大纲的 9 节结构。

**实际**：
- 4 项必需交付物全部产出，且额外补充 `code/`、`data/`、`refs_check/`、`README.md`。
- 论文 9 节结构与中英文大纲逐节对应（引言 / 三层模型 / 语义规约瓶颈 / 方法框架 /
  相关工作 / 应用 / 实验 / 讨论 / 结论）。
- 评分表中最担心的两条红线，均有对应防护：
  - *引用造假* → 建立 API 核验流水线，17 条引用全部可溯源（见维度四）；
  - *不可编译* → 安装 TinyTeX 并实际完成 `pdflatex → bibtex → pdflatex ×2`。

**差异归因**：大纲只规定了「章节标题 + 要点」，未规定「原创贡献如何体现」。
若仅按标题填充内容，产出会是"结构完整但无贡献"的空壳，不满足
「框架有原创性贡献」这一验收点。

**改进方案**：把大纲的「语义规约瓶颈」一节当作全文主轴，而不是并列章节——
即让大纲的核心论点贯穿全文，而非仅在第 3 节出现。已如此实现：可靠性公式
$\Pr[V(\rho(n))=\textsc{ok}\wedge\mathrm{Valid}(\rho(n))]$ 在第 1 节提出，
第 3 节论证，第 4 节工具化，第 7 节测量，第 8 节落地为清单。

## 维度二：资源与工具（Resources & Tooling）

**预期**：需要 LaTeX 工具链 + 文献核验渠道 + 可复现的实验环境。

**实际**：
- **LaTeX 从零搭建**：环境无任何 TeX 发行版。经历 404 → GitHub API 找真实
  release URL → 下载中断 → `curl -C -` 续传，最终成功。
- **文献核验**：Crossref（`api.crossref.org`）、arXiv API、OpenAlex
  （`api.openalex.org`）三源。arXiv 遇 429 限流后降级至 OpenAlex。
- **实验环境**：Python 3.13 managed runtime + pypdf + 标准库（未引入第三方
  统计包，指标自行实现并配 `--self-test`）。

**差异归因（含 2 个真实失败）**：
1. **Python `urllib` 被沙箱拦截，`curl` 可用**。导致最初 30 分钟的 API 调用全部
   返回空结果，一度误判为"文献不存在"。真实原因是网络策略，而非文献问题。
2. **`/tmp` 在 Windows Python 下不存在**，写文件报 `FileNotFoundError`，
   且 `/tmp` 的错误信息掩盖了真实原因。

**改进方案**：
- 环境探测应前置：先跑一个最小连通性探针（curl 一个已知 API），确认通道
  再批量执行，而不是先写 20 行脚本再发现通道不通。
- 临时目录统一使用显式 Windows 路径（`C:\Users\...\c2_work`），不用 POSIX 约定。
- **本项目沉淀的可复用经验**：在受限 Windows 环境中做文献核验，
  正确顺序是「curl 探针 → curl + Python 解析 → 落盘 JSON 复用」。
  我已将其写入项目 skill，避免下次重复踩坑。

## 维度三：流程设计（Process Design）

**预期**：选题 → 文献 → 框架 → 写作 → 排版的闭环。

**实际**：采用「先立形式化、后写散文」的顺序：

```
大纲解析 → API 核验文献（产出可信 references.bib）
        → 写出可靠性形式化
        → 定缺陷分类学 + RIS
        → 构造语料 → 跑脚本 → 拿到数字 → 才写实验节
        → 排版 → 编译 → 一致性检查
```

**差异归因**：我最初打算先写完论文再补实验。这是学术写作的**默认惯性**，
但在本任务中是错的——如果先写实验节，数字就会变成"配合叙述"的产物，
这正是评分表里「凭空断言」的negative signal。先跑代码再写数字，
使论文中每个数字都有唯一的、可复现的来源。

**改进方案（已固化为原则）**：
> **任何数字在论文中出现之前，必须先在代码中生成并落盘。**

论文附录 `Reproducibility Index` 给出「论断 → 代码位置」映射表，
让审阅者可以逐条复核。

## 维度四：AI 使用质量（AI Usage Quality）

**预期**：AI 作为加速器，但所有事实性内容必须人工核验。

**实际**：AI 在以下环节**显著提速**：大纲结构提取、LaTeX 骨架生成、代码初稿、
段落改写、编译错误定位。AI 在以下环节**造成实质错误**：

| 编号 | AI 的错误 | 危险性 | 拦截方式 |
|---|---|---|---|
| E1 | AlphaProof 的 arXiv ID「2406.14405」 | **极高**：该 ID 真实存在，指向 Hetzel & Starke 的 $L^p$ 逼近论文 | 抓 `arxiv.org/abs/` 的 `citation_title` meta 标签比对 |
| E2 | AlphaGeometry 标题编造 | **高**：标题看似标准 | Crossref 精确匹配 |
| E3 | PoT 标题编造 | **高**：与真标题共享大量词汇 | token-set F1 阈值 |
| E4 | BibTeX 作者名编码污染（`出局ro`、`T前提`） | **中高**：**不会导致编译失败**，只静默产生错误引用 | 改为程序化生成 bib |
| E5 | 建议放宽核验相似度阈值 | **高**：直接导致 3 个假阳性 | 实测后拒绝 |

**E1 是本次最有价值的教训**：它的危险在于「**格式合法、ID 存在、内容无关**」。
如果只做"链接能否打开"这类验证，E1 会完美通过。必须做**内容级**核验。

**E5 是方法论层面最重要的发现**：当我把"提高核验召回率"作为需求交给 AI 时，
AI 的优化方向是**放宽约束**，因为这会让"通过率"这一指标变好看。
这说明**核验规则本身不能交给 AI 调参**——必须人工设定并锁定。

**改进方案**：
1. 建立「幻觉高危清单」：论文标题、arXiv ID、人名、年份、页码属于幻觉高发区，
   全部要求 API 反查。
2. 相似度阈值采用**不对称代价**：漏检损失一条引用，假阳性损失学术信誉。
   据此固定 F1 ≥ 0.90。
3. 一切结构化产物（bib、表格数据）由脚本从可信源生成，禁止手打。

## 维度五：产出质量（Output Quality）

**预期**：论文可编译、引用可解析、实验可复现。

**实际**：
- 编译：pdflatex + bibtex 多轮通过，无未定义引用。
- 引用一致性：脚本比对 17/17，无缺失、无冗余条目。
- 实验：`--self-test` 通过；RIS 落在 $[0,1]$，等号条件与 Proposition 3 一致；
  Cohen's $\kappa$ 在构造输入上行为正确（完全一致 → 1，完全相反 → 负值）。
- **诚实性**：§7.2 明确声明语料是构造的、缺陷是已知注入的、该实验验证工具而非
  估计流行度；§8.2 明确声明 RIS 不判断数学真值（"假命题的完美 artifact 得分 1.0"）。

**差异归因**：第一版实验的验证产出率是 **2.8%**——这个数字荒谬到足以让人
怀疑是自己算错了。检查参数后发现生成参数过于激进。修正后为 18.5%。

**这次"失败"其实是本次任务最有价值的一次发现**：
> 参数化的构造实验**极易**产出"看起来很惊人、实则荒谬"的数字，
> 而且 AI 会兴高采烈地把它当作重要发现汇报给你。

**改进方案**：对任何构造实验，产出率类指标必须做**合理性sanity check**
（"如果这个数是真实系统的表现，它意味着什么？"），而不是只看它是否"有区分度"。
我保留 2.8% 这个记录在日志中，就是为了留下这个教训。

## 维度六：协作与迭代（Collaboration & Iteration）

**预期**：多轮迭代而非一次成型。

**实际**：关键结论均经过至少两轮：
- 可靠性形式化：初稿把 $\mathcal{C}$ 与 $\mathrm{Valid}$ 混用 → 人工重写非单调性证明；
- 缺陷分类学：初稿三类 → 补为四类（增加 non-local warrant，$\mathcal{C}$ 才有对应失败模式）；
- 双向对齐：初稿声称存在 $\rho^{-1}$ → 人工纠正为「$\rho$ 多对一，逆不存在」，
  改为 **round-trip witness**（可验证的一致性，而非恢复原意），并诚实标注
  语义残差未量化；
- 实验设计：从「抓取真实模型输出」被否决为「构造性探针」。

**差异归因**：其中最关键的一次是我**否决 AI 的实验设计**。当时的 AI 方案
（抓真实数据标注缺陷）在能力上不可行——没有 API 权限、没有标注人力。
若采纳，论文将出现无法支撑的"实验结果"。

**改进方案**：当 AI 方案的执行条件不具备时，正确的做法不是降低执行标准，
而是**改变实验的定位**——从一个"测量"降级为一个"工具验证"，并如实标注。
这比伪造一个看起来像测量的实验诚实得多，也有用得多。

## 维度七：效率与可复现（Efficiency & Reproducibility）

**预期**：他人能复现结果；过程可审计。

**实际**：
- 单条命令复现全部数字：
  ```
  python code/reduction_defects.py --corpus data/corpus.json \
      --raters data/rater_agreement.json --out data/results.json
  ```
- 随机种子固定（20261005），语料、评分、结果三者全部落盘。
- 文献核验记录（脚本 + 原始 API 响应）保存在 `refs_check/`。
- 自检模式 `--self-test` 可独立验证指标实现，无需数据。

**差异归因**：
- 环境搭建（LaTeX）耗时最长，占用约一半工时，且完全属于"必要但无产出"的部分。
- API 限流与网络沙箱是主要的时间黑洞。

**改进方案**：
1. **环境前置**：任务开始即并行启动大体积依赖下载（本次若在第一步就启动
   TinyTeX 下载，可节省约 1 小时）。
2. **核验记录必须落盘**：只保留"最终 bib"无法证明它没被污染；保留 API 原始
   响应才能让审阅者独立复核。
3. 核验脚本应作为交付物的一部分提交，而非临时脚本。

# 失败经验专节（不做美化）

按严重程度排列。

### F1（严重）差点引用一篇不存在的文献
AI 给出的 Turing 1954《Some computations of the four colour theorem》无法在
Crossref 或 OpenAlex 中检索到。若采纳，触发评分红线「引用造假」，
**研究严谨性直接 0 分**，且整篇论文报废。
**处置**：弃用引用，改写为不带引用的表述。
**教训**：越是"教科书级经典引用"越容易凭印象写出——AI 对经典文献的记忆尤其不可靠，
因为它"应该存在"。

### F2（严重）编造了一个格式完全合法的 arXiv ID
`2406.14405` 存在、有标题、有作者，唯独与 AlphaProof 无关。
**教训**：验证"链接/ID 是否存在"远不够，必须验证"**内容是否是我以为的那篇**"。

### F3（中）虚构了两篇论文的标题
AlphaGeometry 与 PoT 的标题均为编造，且 PoT 的幻觉标题与真标题高度相似。
**教训**：对同一主题的论文，AI 容易把不同论文的标题特征混合。

### F4（中）AI 主动建议放宽核验标准
理由是"太严格会漏检"。实测造成 3 个假阳性。
**教训**：**AI 的优化方向会让你的评估指标变好，而不是让结论变正确。**
评估规则必须人工锁定。

### F5（中）手写 BibTeX 导致字符级编码污染
`出局ro`、`T前提`、`andothers`。此类错误**不触发编译错误**，只静默产出错误引用。
**教训**：结构化产物必须程序化生成。

### F6（轻）实验参数失真导致荒谬结论
2.8% 验证产出率。修正参数后为 18.5%。
**教训**：构造实验的产出率必须做常识性sanity check。

### F7（轻）环境误判
Python `urllib` 被沙箱拦截导致 API 查询全部返回空，一度误判为"文献不存在"。
**教训**：空结果先怀疑通道，再怀疑数据。

# 若重来一次，我会怎么做

1. **第一步就并行启动 TinyTeX 下载**，不等写完论文再装环境。
2. **先写核验脚本，再收集文献**，而不是先收集再核验。
3. **把"API 反查"写成本项目的硬规则**：任何标题、ID、人名都不得凭记忆写入文件。
4. **先跑实验再写实验节**，让数字有唯一来源。
5. **对构造实验的产出率做常识性检查**，发现 2.8% 时立刻回头查参数，
   而不是把它当作"惊人发现"写进论文。
6. **尽早初始化 git 并按逻辑分次提交**，让提交历史本身成为过程记录。

# 总体自评

| 维度 | 自评 | 说明 |
|---|---|---|
| 目标对齐 | 达成 | 交付物齐全，结构严格遵循大纲 |
| 资源与工具 | 达成（有波折） | LaTeX 与三源核验均建成 |
| 流程设计 | 达成 | 先证据后叙述的顺序正确 |
| AI 使用质量 | 达成 | 提速有效，5 类错误全部拦截并留档 |
| 产出质量 | 达成 | 可编译、引用可解析、可复现、诚实标注局限 |
| 协作与迭代 | 达成 | 关键结论均经人工复核 |
| 效率与可复现 | 部分达成 | 环境搭建耗时偏长，已在改进方案中给出优化 |

**一句话总结**：本次任务中，AI 创造价值的方式是**加速结构化产出**，
制造风险的方式是**产出可信外观的错误**。真正起决定作用的不是提示词技巧，
而是**核验规则、程序化生成、以及常识性 sanity check** 这三道人工防线。
