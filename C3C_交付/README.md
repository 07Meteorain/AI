# C3C · 双人协作与技能迁移 —— `duolog`

> **不是两个人各做一半，是两个人各自把自己不会的那一段，教到对方能独立写出来。**
>
> 这个仓库把这个「教没教成」变成了可复算的数字：`duolog` 读两份协作者日志，
> 合并成一份带冲突裁决的协作记录，再从日志里把**技能迁移的边**抽出来。
> 工具的分析对象，就是造它的这场协作本身。

## 快速开始（不需要 `pip install`）

```bash
cd C3C_交付

# 1. 自检：内置样例跑通 解析→合并→裁决→渲染，不读任何外部文件
python -m duolog selfcheck
# → selfcheck: ok 38e8e32a4d6548a92dfda03a26863234ead153f19ca4c542d171db2a8df48bd2

# 2. 合并真实协作日志，产出协作记录与报告
python -m duolog merge --a logs/Aster.md --b logs/Bramble.md \
       --author-a Aster --author-b Bramble \
       --out logs/合并记录.md --report logs/协作报告.md

# 3. 看某一条争议事件的完整溯源（谁说了什么、凭什么这么裁）
python -m duolog explain --a logs/Aster.md --b logs/Bramble.md \
       --author-a Aster --author-b Bramble --eid E-021

# 4. 跑测试
python -m unittest discover -s tests
```

退出码是有契约的：`0` 成功、`1` 有存疑条目（配 `--strict`）或解析出错、`2` 用法/读文件错误。
可以直接当 CI 门禁：`python -m duolog merge ... --strict || exit 1`。

## 这个工具解决什么问题

两个人的协作日志天然会打架：同一件事两人都记了（该合并还是删一条？）、
同一件事记得不一样（谁对？）、只有一个人记了（另一条是不是漏了？）。

`duolog` 的立场是**不替人做它做不了的判断**，只做三件事：

1. **按事件编号归并**，让"两人独立记了同一件事"这件事本身成为证据（双重确认）；
2. **冲突按固定规则裁决**，每条裁决都写明用了哪条规则、为什么；
3. **拿不准就说拿不准**——R3 会把两种说法并排留着，标 `needs_review`，让人来判。

## 五条裁决规则（这是协作双方共同设计的）

| 代号 | 条件 | 结果 |
| --- | --- | --- |
| `R0` | 各版本正文（规范化后）完全相同 | 双重确认，取最长原文 |
| `R1` | 恰好一个版本带 `类型:决策` | 决策优先（强语义证据 > 时钟） |
| `R2` | 某版本 clock 严格最大 | 时钟较新（弱证据，但可用） |
| `R4` | 一方正文按行完整包含另一方 | 补充合并（是补充不是反驳，取更完整者） |
| `R3` | 其余 | 无法裁决，两说并排，`needs_review` |

执行顺序 `R0 → R1 → R2 → R4 → R3`。**注意 R4 在 R2 之后**，这意味着只要两版时钟不等，
R4 就轮不到——它实际是"并列时钟"的补位规则。这一点是集成实测才发现的，已写进
[`任务契约.md`](任务契约.md) 与 [`07Meteorain_C3C_AAR.md`](07Meteorain_C3C_AAR.md)。

## 技能迁移是怎么被"算"出来的

日志里每条带 `技能:SEL-1` / `技能:SEL-2` 标签。技能有**原拥有者**：

- `SEL-1`（确定性合并与冲突裁决）归 Aster；
- `SEL-2`（零依赖 CLI 工程化与终端渲染）归 Bramble。

**一条迁移边 = 某人的日志里出现了别人拥有的技能标签**。判定按单条原始条目算，
不看合并后的并集标签——否则"两人共同确认的分工条目"会伪造成一次迁移。

本仓库实测输出：

```
技能迁移
  SEL-1  Aster → Bramble  证据：E-011、E-012
  SEL-2  Bramble → Aster  证据：E-013、E-014、E-015
```

## 已知局限（如实记录）

- **R4 是补位规则**：只要两版时钟不等，R2 先命中，R4 轮不到。想让它承担"补充合并"主语义，
  就得把它移到 R2 之前，但那会让"时钟更新但内容更短"的版本输给更长的旧版本——权衡后没改。
- **空行参与行匹配**：R4 用规范化正文判包含，一个多出段落空行的版本会赢 R4。
  要修需要成对修 R0/R4（只改 R4 会把它推进 R3），本轮未修。
- **explain 固定 72 列**：不随终端宽度变化。这是拿"输出可复现"换的——同一个输入永远同一份字节。
- **`winner=None` 有三种含义**：`single` / `confirmed` / `needs_review` 的 winner 都是 None，
  判据是 `status` 字段。下游不要用 `winner is None` 反推是否待复核。
- **逻辑时钟跨人不可比**：`clock` 是各自作者的计数器，不是墙上时间。R2 因此只是弱证据。
- **两位协作者是 AI agent**：详见 [`07Meteorain_C3C_协作记录.md`](07Meteorain_C3C_协作记录.md) §0。
