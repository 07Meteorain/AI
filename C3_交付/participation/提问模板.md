# 提问模板：六要素 + 三档对照

> 目标不是"写得长"，而是**让对方读完第一屏就能动手**。
> 写完先跑 `python linter/question_lint.py 草稿.md --min 70`，低于 70 分不发。

---

## 一、六要素骨架（复制这段填）

```markdown
# 【求助】一句话说清现象（含关键错误码）

## 环境
- 系统 / 版本：
- 语言 / 框架 / 依赖版本：
- 是否只在某台机器/某个网络下复现：

## 我在做什么（目标）
（一句话：我想让 X 做到 Y）

## 现象
（粘贴完整错误的第一行 + 最后一行；给出退出码/状态码）

## 已尝试（每条都带结果）
1. 做法 → 结果
2. 做法 → 结果
3. 做法 → 结果

## 证据
（最小复现步骤 / 代码块 / 日志 / 截图）

## 期望 vs 实际
- 期望：
- 实际：

## 我想问的问题
1. （一个可以用"是/否"或"二选一"回答的问题）
2. （一个能帮我排除方向的对照实验建议）
```

## 二、三档对照（同一件事的三种问法）

### ❌ 差：把成本转嫁给别人

> 大佬们救命，我的代码报错了，怎么办？？？

体检器得分 **0 / 100**。问题不是"不礼貌"，而是**信息量为零**：
没人知道你在做什么、跑了什么、期望什么。每一个想帮你的人都得先问你 4 个问题。

### ⚠️ 中：能看出问题，但对方还得动手猜

> 我用 Python 读一个文件，路径里带中文，一直报错。我试过加 r 前缀，还是报错。
> `FileNotFoundError: [Errno 2] No such file or directory` 怎么回事？

体检器得分 **33 / 100**。三个致命缺口：
1. 没有环境（Windows 还是 Linux？Python 几点几？路径分隔符问题只在某些平台出现）；
2. 没有期望 vs 实际（"读不到"和"读到了但内容乱码"是两条完全不同的排查线）；
3. "怎么回事"是个开放问句，回答者必须先替你把它翻译成具体假设。

### ✅ 好：对方读完第一屏就能动手

见 [`../linter/cases/good_01.md`](../linter/cases/good_01.md)（0xC0000142 的真实提问稿），
体检器得分 **100 / 100**。它的做法是：

| 做法 | 效果 |
| --- | --- |
| 标题带错误码 | 会答的人一眼认领，不会答的人不浪费时间 |
| 已尝试写满 5 条，每条带结果 | 排除法已经做完一半，对方不用重复问 |
| 贴了能直接跑的 20 行复现 | 对方在自己机器上花 30 秒就能验证 |
| 问题落到"用哪个工具、为什么两条路径不同" | 是可回答的问题，不是情绪 |

## 三、发帖前 30 秒自检（不跑程序也能做）

| # | 自问 | 不通过怎么办 |
| --- | --- | --- |
| 1 | 我把"已试过的方案"写下来了吗？ | 回看命令行历史，抄 3 条 |
| 2 | 对方能在自己机器上复现吗？ | 抽出最小可运行片段 |
| 3 | 我的问题能用"是/否"回答吗？ | 把"怎么办"换成"是 A 还是 B" |
| 4 | 我搜过吗？搜到什么了？ | 把搜索关键词 + 结论写进去（这也算已尝试） |
| 5 | 我是不是在问一个已经有官方文档答案的问题？ | 先读文档，把不懂的那**一句**摘出来问 |

## 四、常见反模式（我都犯过）

| 反模式 | 为什么有害 | 替换写法 |
| --- | --- | --- |
| "RTFM"/"自己查" 式追问 | 把关系搞僵，且暴露没搜 | "我读了文档第 X 节，卡在这句话的 Y 上" |
| 截图贴整个屏幕 | 对方要眯着眼找报错 | 截图只留错误块 + 上下文 10 行 |
| 一次问 5 个问题 | 每个都答不深 | 一次一个，其余排队 |
| 只说"不行" | 无法判断是环境、版本还是用法 | 给出"期望 / 实际 / 已试"三行 |
| 深夜发、第二天催 | 消耗好感 | 发完自己先做一轮排查，把结论补在楼下 |
