# 结论沉淀卡：把一次讨论变成别人能复用的东西

> 讨论结束不等于闭环。**没有沉淀的讨论，第二次遇到还要再问一遍。**
> 一张卡控制在 200 字内，能直接贴回群里。

---

## 模板

```markdown
【结论卡】<一句话结论，带可搜索的关键词>

- 现象：<可被搜索到的症状，含错误码>
- 根因：<已确认 / 候选，注明置信度>
- 解法：<可执行步骤，编号>
- 边界：<什么情况下这个解法不成立>
- 反例：<我试过但没用的一条，避免别人重复>
- 出处：<谁提的、哪条消息、文档链接>
```

---

## 示例（本次真实案例）

```markdown
【结论卡】所有子进程秒退 0xC0000142（STATUS_DLL_INIT_FAILED）→ 别改代码

- 现象：任何子进程调用都在 0.1s 内返回 3221225794，stdout/stderr 全空
- 根因：进程创建层被干预（候选：终端安全软件/DLP 注入、沙箱作业对象限制）
- 解法：1) 跑 cmd.exe /c echo hi 确认"全挂" 2) stdio 换 pipe 看是否变 EPERM
        3) 提权终端重跑，由红转绿即环境问题
- 边界：若只有某个程序挂、或事件日志有 SideBySide 错误，改查 VC 运行库
- 反例：换命令、换绝对路径、重装 git —— 全部无效，浪费 40 分钟
- 出处：本人 2026-11-06 实测，证据见 case_0xC0000142/
```

---

## 什么时候该发结论卡

| 场景 | 发不发 | 理由 |
| --- | --- | --- |
| 问题解决了，群里 3 人以上参与 | 发 | 参与者有权知道结果 |
| 有人给了关键线索 | 发，并 @ 他 | 让贡献被看见，这是社群的燃料 |
| 是自己查文档解决的 | 发 | 下一个遇到的人会搜到 |
| 结论还不确定 | 发"阶段性结论 + 待验证项" | 半成品也比没有强，标注清楚即可 |

---

> 一句话：**提问是把成本交给别人，结论卡是把成本还回去。**
