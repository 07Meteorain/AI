# Meteorain_C4A_教学说明

> 面向两类读者：**助教/老师**（怎么用它评C4）、**同学**（怎么用它自检）。
> 读完这一篇你应该能独立完成一次完整评审。

---

## 一、30 秒上手

```bash
# 1装依赖（唯一必需项）
pip install pyyaml

# 2. 跑起来
python scripts/c4a_evaluator.py "<你的 C4 提交文件夹>" --outdir ./reports
```

**输入**：一个装着大家提交文件的本地文件夹（怎么弄到本地的不重要）
**输出**：一个 `reports/` 文件夹，里面有 Markdown 报告、JSON 数据、Excel 详表

完事。**建议第一次运行时加 `--strict`**（会额外解析 PDF/Word 正文，更准但更慢）。

## 二、安装

### 2.1 依赖

| 包 | 必需 | 用途 | 缺失后果 |
|---|---|---|---|
| `pyyaml` | ✅ | 读评审标准 | **无法启动**，程序会明确报错 |
| `openpyxl` | ❌ | 生成 Excel | 跳过 Excel，MD/JSON 照常 |
| `pypdf` | ❌ | 解析 PDF 正文 | PDF 只按文件名判定 |
| `python-docx` | ❌ | 解析 Word 正文 | Word 只按文件名判定 |

```bash
pip install pyyaml openpyxl pypdf python-docx   # 一次装全，推荐
```

### 2.2 三种安装方式

**方式 A：作为 Skill 安装（推荐给用 Claude Code / Cursor 的同学）**

`.skill` 文件本质是 tar.gz，解压到你的skills 目录即可：

```bash
tar -xzf Meteorain_C4A_skill-evaluator.skill -C ~/.claude/skills/
```

装完直接说「帮我评审一下 C4 提交，文件夹在 xxx」就能触发。

**方式 B：直接用源码（推荐给只要跑一次的老师）**

```bash
git clone <本仓库>
cd C4A_交付
python skill/c4a-skill-evaluator/scripts/c4a_evaluator.py <文件夹> --outdir reports
```

**方式 C：自测（确认安装正常）**

```bash
python tests/test_evaluator.py --accuracy
# 期望输出：Ran 26 tests ... OK / 人机一致率 : 100.0%
```

## 三、怎么把文件从微信弄到本地

C4A 原文件怎么来的。这部分**本技能不关心**——
技能只接受本地文件夹路径，怎么弄到本地是你的事。常见三种：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **手动下载**（最省事） | 群文件逐个保存到一个文件夹 | 只评 5~10 份 |
| **微信桌面端同步** | PC 版微信 → 设置 → 文件管理 → 找到同步目录 | 评整班 |
| **导出工具** | 调研群文件导出工具 | 量大且愿意折腾 |

**如果你用的是微信同步目录**，注意它通常按 `msg.attach` 组织，文件名带哈希。
评审器能处理（会退回到元数据识别作者），但作者识别准确率会下降。
**建议下载后重命名为 `姓名拼音_C4_内容描述.扩展名`**，识别率最高。

## 四、评审自己的 C4 提交（同学视角）

这是本技能最实用的功能：**提交前先自检**。

```bash
python scripts/c4a_evaluator.py ./我的C4提交 --outdir ./自检结果
```

然后打开 `自检结果/Meteorain_C4A_评审报告.md`，重点看两处：

### 4.1 五个必须文件齐了吗

| 必须文件 | 最稳妥的命名 |
|---|---|
| Skill 说明文档 | `姓名_C4_skill说明.md` |
| 可执行内容 | `姓名_C4_技能名.py` 或 `.skill` |
| Demo | `姓名_C4_demo.png` |
| 教学说明 | `姓名_C4_教学说明.md` |
| AI 日志 | `姓名_C4_AI日志.md` |

> **为什么文件名这么重要**：评审器判定"文件存在"时，
> **优先看文件名强信号，其次才看正文关键词**——
> 因为人主动命名的文件名，比程序猜测的正文命中更可信。
> 命名规范的同学，报告更准，老师也更容易找到你的文件。

### 4.2 四个条件过了吗

报告里每条判定都带**文件行号证据**。比如看到：

```
| 可复用 | ❌ | 57% | 🚫 否决证据：L20「路径是 /Users/lm/Desktop/meeting_summary/summary.py」|
```

意思是：**你的 skill 说明第 20 行写了写死的本地路径**，
这份技能别人拿去跑不起来，所以「可复用」直接判❌。

**修复方式**：把绝对路径改成命令行参数或环境变量。

```python
# 改前——别人跑不了
p = Path("C:/Users/lm/Desktop/meeting_notes.txt")

# 改后——任何人跑都能用
ap.add_argument("--input", required=True)
p = Path(args.input)
```

### 4.3 特别提醒：置信度为 `low` 的结论

报告里带`[low]` 或 `🚩 需人工复核` 的结论，
意思是**评审器自己不确定**，它把判断权交回给你。

这种结论通常来自单个关键词命中——比如你在正文里恰好写了"安装"两个字，
评审器就认为"有安装说明"，但你可能根本没写安装步骤。
**这时候不要跟报告较劲，去看它引用的那行原文。**

## 五、评审全班（老师视角）

### 5.1 一次完整评审

```bash
python scripts/c4a_evaluator.py "/path/to/微信群C4文件" \
    --outdir ./reports \
    --strict \
    --md 评审报告.md --json evaluation.json --xlsx 评审详表.xlsx
```

### 5.2 先看哪个文件

| 顺序 | 文件 | 回答什么问题 |
|---|---|---|
| 1 | `*_评审仪表板.html`（或MD 报告） | 全班整体什么水平？ |
| 2 | MD 报告的「四、班级共性问题」 | 下次该强调什么？ |
| 3 | Excel「逐项评审明细」 | 具体谁有哪个问题？ |

### 5.3 用 Excel 快速定位问题人群

打开 `评审详表.xlsx` 的「逐项评审明细」sheet，按 `项ID` 筛选：

| 筛这个 | 得到什么 | 该说什么 |
|---|---|---|
| `R2` + `❌` | 所有写了硬编码路径的人 | "路径不能写死，改成参数" |
| `E4` + `❌` | 代码解析失败的人 | "你的 .py 有语法错误" |
| `V2` + `❌` | 没定义预期输出的人 | "补一段'预期结果长什么样'" |
| `I1` + `❌` | 没有 IO 一句话描述的人 | "开头加一句'输入X，输出Y'" |

**这一步是本技能最省时间的用法**——不用逐份打开文档，筛一次就拿到名单。

### 5.4 ⚠️ 排名要慎用

报告底部我写了这句话，这里再强调一次：

> **排名仅作参考——C4 的评分核心是「被使用次数」，不是机器打分。**

C4 原文：
> 注意：不是谁的技能"最厉害"谁赢——而是谁的技能**被最多人用了**。

本评审器评的是**提交材料的完整性**，不是技能的实际影响力。
一份材料齐全但没人用的技能，会排在中上；一份材料潦草但被 20 人用过的技能，
应该拿最高分。**用机器报告定位问题，用使用次数决定排名。**

## 六、常见坑

### 坑 1：作者识别成 `Unknown`

**现象**：报告里出现 `Unknown` 作者
**原因**：文件名不规范、目录名不像人名、元数据为空、文档头没写作者
**解决**：报告里已把这些文件单列在「未识别作者」区（不参与排名）。
让 TA 把文件重命名为 `姓名_C4_xxx` 再跑一次。

### 坑 2：明明写了对，为什么判❌

**排查顺序**：
1. 看报告里那条❌引用的**行号和原文**——很可能是误判
2. 检查该文件是不是太大（> 50MB 会被跳过正文解析，只看文件名）
3. 检查是不是编码问题（GBK 存的中文可能读出来是乱码）

如果是真误判，说明该检查项的关键词表需要扩充——改
`references/c4_rubric.yaml` 就行，**不用改代码**。

### 坑 3：`.skill` 包被判为损坏

`.skill` 必须是 **tar.gz** 格式（标准 `tar -czf` 打包）。
用 `zip` 打的包能打开但不符合规范。
评审器会尝试 `tarfile` → `zipfile` 两种方式，尽量兼容。

### 坑 4：中文文件名乱码

Windows 下用 GBK 存的文档，`errors="replace"` 会产生乱码。
**解决**：统一用 UTF-8 保存。

### 坑 5：Excel 生成了但打不开

`openpyxl` 缺失时会跳过 Excel 并在终端提示。
如果你需要 Excel，`pip install openpyxl`。

### 坑 6：运行很慢

- 先不加 `--strict`（跳过 PDF/Word 解析，快很多）
- 大文件夹可以先手动分层，逐目录跑

## 七、修改评审标准

**所有判据都在 `references/c4_rubric.yaml`，改它不用改代码。**

### 7.1 加一个检查项

比如想在「可执行」里加一条"有 README":

```yaml
  executable:
    label_cn: "可执行"
    check_items:
      # ... 已有的 E1~E5 ...
      - id: E6                # 编号不重复即可
        name: "有 README"
        type: keyword# keyword / regex / structural / io_pattern / veto
        positive: ["README", "readme.md", "说明文件"]
        weight: 0.8           # 权重 0~2，重要项给大
```

### 7.2 加一个否决项

```yaml
      - id: E7
        name: "无未替换的 TODO"
        type: veto
        positive: []
        negative: ["TODO", "FIXME", "待实现"]
        weight: 1.5
```

**注意**：如果是 `type: structural` 的新检查项，
必须在 `c4a_evaluator.py` 的 `_structural_facts()` 里补对应事实，
否则程序会**抛 KeyError**（这是刻意设计的——宁可报错也不静默判错）。

### 7.3 改权重

```yaml
scoring:
  criterion:
    pass_threshold: 0.70     # ≥0.70 判 ✅
    partial_threshold: 0.35   # ≥0.35 判 ⚠️，否则 ❌
  composite:
    w_completeness: 0.40      # 完整性权重
    w_quality: 0.60           # 质量权重
```

改完**立刻跑一次自测**确认没破坏判据：

```bash
python tests/test_evaluator.py --accuracy
```

## 八、常见问题

**Q：能不能只用命令行，不装成 Skill？**
能。`c4a_evaluator.py` 是独立脚本，不依赖任何 Skill 机制。

**Q：会读我的文件内容吗？**
会读取提交文件的正文用于评审，但全部在本机处理，不上传任何地方。

**Q：能评审别的挑战吗？**
能。换一个 `c4_rubric.yaml` 就能评C1/C2 或任何"提交型作业"——
因为 `required_deliverables`（必交文件）和 `quality_criteria`（质量维度）
是两个独立配置块。

**Q：为什么不用 LLM 判？**
因为 C4 四条件是**客观可判定信号**，用规则能给出**可复现、可追溯、免费**的结论。
详见方案设计 §2。LLM 的位置我预留了（`confidence` 字段），但本版未接入——
如果规则层连自己的误判率都测不出来，加 LLM 只会让问题更难定位。

**Q：误判率 100% 是真的吗？**
在这3 份标注样本上是 100%，但：
- 样本量小，统计意义有限
- ground truth 是我自己标的，可能有共同偏差
- 剩余风险集中在 `low` 置信度的结论上，报告会主动提示人工复核

**不能外推到任意班级**。详见方案设计 §5.3。
