## 二、文章内容摘要

**标题**：我用 AI 造了一个公众号排版技能，然后发现 starter kit 有两个致命 Bug

**核心观点**：能跑通和能交付之间，隔着两个没人告诉你的 Bug。

**文章结构**：

1. **五分钟跑通，十分钟发现问题** —— 交代「我以为可以交差了」的心路转折
2. **坑一：代码块缩进被 HTML 吃掉** —— 根因是 HTML 折叠 `<p>` 内换行
3. **坑二：引用块加粗变纯文本** —— 根因是 `get_text()` 拍平子树
4. **BeautifulSoup 的三个分片陷阱** —— 自挖的坑，`new_tag` / 二次转义 / `<p>` 嵌套
5. **eval 驱动的 4 轮迭代** —— 30→34→36→37，6 个失败里有 3 个是我以为修好的
6. **从脚本到技能** —— 从跑通到可交付还差什么
7. **AI 与人的分工** —— 时间分配 5% / 40% / 50%

**为什么这篇值得发**：它不是「我做了个工具」的流水账，
而是「工具教会我什么」的复盘，附3 个真实的 BeautifulSoup 陷阱——
这些坑任何用Python 处理 HTML 的人都会遇到。

## 五、发布 SOP（照做即可，5 分钟）

### 步骤 1：准备（0–2 分钟）

```bash
# 生成可粘贴片段
python scripts/wechat_publisher.py \
  Meteorain_C4B_文章源文件.md \
  Meteorain_C4B_output.html \
  --theme accent --toc \
  --fragment-out Meteorain_C4B_粘贴片段.html
```

### 步骤 2：填公众号后台（2–4 分钟）

打开 mp.weixin.qq.com → 新建图文：

| 字段 | 填什么 |
|------|--------|
| 标题 | 我用 AI 造了一个公众号排版技能，然后发现 starter kit 有两个致命 Bug |
| 作者 | Meteorain |
| 封面 | 建议 2.35:1 比例，突出「两个 Bug」 |
| 摘要 | 见 front matter 里的 `abstract` |

### 步骤 3：粘贴正文（30 秒）

1. 浏览器打开 `Meteorain_C4B_粘贴片段.html`
2. 全选复制
3. 粘贴到公众号正文区

> **用片段文件，不要用预览版。** 预览版 `<body>` 里有页面宽度约束，
> 粘进公众号会带进多余样式。

### 步骤 4：核验（1 分钟）

逐项确认：

- [ ] 3 个 callout 框有底色和左边框
- [ ] 代码块有灰色底、深色左边框、**且缩进正确**
- [ ] 目录在顶部，条目清晰
- [ ] 元数据块在标题下方
- [ ] 底部有版权声明和分隔线
- [ ] 引用块里的**加粗还在**

最后一项是重点——它正是 BUG-2 的修复验证点。

### 步骤 5：手机预览 → 发布

公众号后台「预览」发送到手机，确认无误后点「群发」或「发布」。
