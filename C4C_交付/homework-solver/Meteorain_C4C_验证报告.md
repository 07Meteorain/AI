## 一、验证方法说明

本项目的每个答案都经过四层验证，验证结果**直接印在 PDF 里**
（绿色`✓ 已验证` / 橙色 `⚠ 验证存疑`徽章）：

| 层 | 方法 | 检查内容 |
|----|------|---------|
| L1 形式检查 | `form_check` | 空答案、NaN、zoo、未解占位符；量级合理性 |
| L2 数值代入 | `substitution_check` | 答案代回原方程，残差应< 1e-9 |
| L3 交叉检验 | `cross_check_limit` / `cross_check_eigen` / `identity_check` | 符号算法 vs 数值逼近，两条独立路径互验 |
| L4 量纲/形状 | `dimension_check` / `matrix_shape_check` | 物理量量纲、矩阵阶数 |

**验证不修改答案，只打标签。** 这与「自动改答案」是两回事——
自动改会掩盖求解器本身的缺陷；打标签能把缺陷暴露在报告里。

## 四、验证模块抓到的真实错误

这一节记录**验证模块实际发挥作用**的案例——它们证明验证不是装饰。

### 4.1 SymPy 静默误算（最严重）

```python
n = Symbol('n', positive=True, integer=True)
limit(n*sin(2*pi/n)/2, n, oo)    # → 0     ❌ 正确答案 π
limit(n*sin(2*pi/n)/2, n, oo)    # → π    ✓（去掉 integer=True）
```

带 `integer=True` 假设时 SymPy 的 Gruntz 算法给出**错误结果 0，且不报错**。

**影响**：WS4 的 AP3（圆内接正 n 边形面积）被算成 0而不是 π。

**发现方式**：`cross_check_limit` 的符号/数值交叉检验报警。

**修正（双保险）**：
1. 求解器侧去掉 `integer=True`，并加解析值 $\pi R^2$ 交叉核对
2. 验证侧独立数值逼近，符号与数值不一致时报「⚠ 存疑」

### 4.2 分数被解析成乘法

`_find_matching_brace` 的起点算错一格，
使 `\frac{x^2+2x-24}{x-4}` 被解析成 `(x-4)(x²+2x-24)`。

**影响**：AP1(a) 给出 -11520（正确 -20）。

**发现方式**：逐题核对标准答案时发现（随机测试很难碰到）。

### 4.3 领域求解器失败后静默给出错误答案

早期版本中，物理求解器未识别题型时会 fall through 到通用求解器，
通用求解器从题面抓第一个数字当答案——「两个点电荷求库仑力」输出 `3.0`。

**修正**：领域求解器一旦命中，**要么给答案，要么明确报未解**，
绝不退回通用求解器。这条原则后来写进了代码注释。

### 4.4 Gram-Schmidt 验证误报

验证器原本检查 $Q^TQ = I$，但 Gram-Schmidt（未归一化）得到的是
**正交**而非**标准正交**组，$Q^TQ$ 是对角阵而非单位阵。

**修正**：分别判定「非对角元全 0」（正交，通过）与
「对角元全为 1」（标准正交），避免对正确结果误报。


### 5.2 量纲检查是启发式而非严格量纲代数

SymPy 无内置物理量纲系统。当前实现检查：
- 答案是否为裸数值（缺单位）
- 是否含 `nan`/`zoo`
- 解题步骤里是否显式声明了量纲核对

**未实现**完整的量纲代数（如 $\mathrm{kg}\cdot\mathrm{m/s^2} = \mathrm{N}$ 的自动推导）。
要严格做需要引入 `pint` 库。

### 5.3 求解率 100% 的边界

44/44 是**在这四个测试集上**的结果。测试集是我自己构造的
（线性代数和物理作业），可能存在**过拟合**——
即我实现的求解器恰好覆盖了这些题型。

Berkeley 两个测试集是 starter kit 提供的真实试卷，未过拟合，
其 18/18 的结果可信度更高。
