**一句话**：把「这次作业交得怎么样」从一句感觉，变成一张**能追问、能复核、能被推翻**的表。

它做四件具体的事：

1. **把口径写死** —— 10 个指标每个都有公式、分母、边界情况；同一个「提交率」在这份数据上能报 89.6% / 80.3% / 72.2% 三个值，看板把三个都摆出来，并说明各自的分母；
2. **把脏数据摊开** —— 611 行原始导出里 5 类问题（撤回、重复提交、UTC 时区、总分对不上、姓名带空格），逐步清洗到 511 行，处理规则可复跑、可被测试覆盖；
3. **把结论和证据绑在一起** —— 7 条洞察，每条带数字、带「注意」（什么情况下不成立）、带「该做什么」，点一下就推回看板筛选；
4. **把「不能下结论」也写清楚** —— 班级均分差 6.0 分，但评审人之间就差 7.2 分且和班级 88% 绑定，所以这一页明确写着：**班差暂时不能当学情差**。

全部在浏览器本地跑：**没有后端、没有网络请求、没有账号、没有埋点**。

## 数据：两层，互不冒充

这个挑战最难的不是画图，是**「所有人的作业」这份数据从哪来**。平台没有导出接口，所以我把数据分成两层，界面上分区呈现，任何一层都不假装成另一层：

| 层 | 内容 | 规模 | 性质 | 用在哪 |
| --- | --- | --- | --- | --- |
| 班级全景 | 106 位在读（另有 12 位退课/免修）× 6 个挑战的提交、评审、交付物完整性 | 611 行原始 → 511 份有效提交 | **合成**，seed=20260717，人物学号均虚构 | 总览 / 洞察 / 学生 / 口径 |
| 本人真实 | 13 个交付目录的 commit 时间、文件数、体积 | 93 条 commit / 1320 个文件 | **真实**，GitHub API 拉取，可逐条核对 | 真实数据页 |

为什么不是「全真实」：只看我自己的 13 次提交，做不出「管理所有人作业」的看板——班级对比、评审人效应、未交名单都无从谈起。

为什么不是「全合成」：那就没有任何东西能被核对。留一层真实数据，既证明抓取链路可用，也顺手证明了本项目最想讲的那件事——**git 的 commit 时间是推送时间，不是完成时间**（C2G 的 50 条 commit 全挤在 1.84 小时内）。

数据血缘：

```
data/raw/submissions_export.csv   611 行（平台字段原样：含撤回、重复、UTC、脏姓名、错误总分）
        │  clean()：剔除撤回 → 去重取最后一条 → 时区归一 → 按分项重算总分 → trim
        ▼
data/clean/submissions_clean.csv  511 行
        │  build_metrics()：只实现 DICTIONARY 里写过的口径
        ▼
data/metrics.json  +  app/js/data.js（看板直接读，离线可用）

data/real/self_commits.json       真实快照（fetch_real.py 生成，随仓库提交）
```

## 七个洞察（全部由数据算出，页面不做二次判断）

| # | 结论 | 关键数字 | 该做什么 |
| --- | --- | --- | --- |
| I1 | 作业挤在截止前 24 小时 | 48.5% 落在最后 24h；峰值 2026-10-25 一天 52 份 | 截止前 48h 推自检清单；评审从「截止后集中 3 天」改成按提交日滚动 |
| I2 | 同一批数据，提交率能报三个数 | 89.6% / 80.3% / 72.2%；均分 74.4，待评审记 0 则 69.3 | 报表固定写「分子/分母/口径」三件套 |
| I3 | 班级差异其实是评审人差异 | 班级极差 6.0 分，评审人极差 7.2 分，同评审人跨班只差 2.5 分 | 班间比较前先看 reviewer 分布；下期随机交叉分派、双评 |
| I4 | 迟交和低分几乎不相关 | 按时中位 74.0 vs 迟交 74.9，提前量与总分 r = 0.02 | 迟交按「是否影响排期」处理，别当质量信号 |
| I5 | C5 复盘维度分裂成两簇 | 41.9% 在 80+，52.3% 卡在 55–80，中位 65.5 | 补 3 个锚定样例，该维度双评取均值 |
| I6 | 缺 demo 是完整性最大缺口 | 24.3% 没交 demo；缺 demo 组产物完整性 70.9，齐备组 76.9 | 提交模板把 demo 设为必填，评审端直接标红旗 |
| I7 | AI 使用质量是唯一低分集中的维度 | 中位 66.6，27.9% 低于 60 分；与对话轮数 r = 0.69 | 给 AI 日志模板（目标/试了什么/错在哪/怎么改），抽 2 份人工复核 |

> 每条洞察都能在「洞察」页点「应用到看板」下钻到对应筛选，学生表与图表会立刻重算。

## 快速开始

**只想看** → 双击 `app/index.html`。不需要 Python、不需要 `npm install`、不需要联网。

**想跑本地服务**（某些浏览器对 `file://` 的 `fetch` 更严格，本项目已把数据编成 JS，所以不跑也行）：

```bash
python -m http.server 8000 --directory app
# 打开 http://localhost:8000/
```

**想复跑整条数据管线**（Python ≥ 3.10，零第三方依赖）：

```bash
cd C6A_交付
python data/build_dataset.py            # 重新生成 raw / clean / metrics.json / app/js/data.js
python data/build_dataset.py --check    # 只打印产物指纹，用于核对是否与种子一致
```

**想刷新真实数据**（需要网络；匿名 GitHub API 限额 60 次/小时）：

```bash
python data/fetch_real.py               # 有 token 时：GITHUB_TOKEN=xxx python data/fetch_real.py
```

**想跑测试**：

```bash
python -m unittest discover -s tests -v
```

## 技术选择：为什么是零依赖

| 选择 | 替代方案 | 为什么不用替代方案 |
| --- | --- | --- |
| 手写 SVG 图表 | ECharts / Chart.js / D3 | 三个库任一都能画得更好看，但会把「clone 下来双击就能开」变成「先联网下载」。这个项目的读者是评审，不是开发者 |
| 数据编译成 `data.js` | `fetch('metrics.json')` | `file://` 下 `fetch` 会被 CORS 拦，直接双击就打不开——这是最常见的交付事故 |
| 原生 JS + hash 路由 | React / Vue + 构建 | 单页 5 个视图，无需构建链；深链（`#students?c=C6&k=A&open=…`）靠 hash 就够了 |
| 深色为主、浅色可选 | 只做深色 | 投影仪/打印场景需要浅色；两套主题只换 CSS 变量，成本极低 |
| Python 标准库 | pandas / numpy | 数据只有 611 行，标准库够；换来「CI 里 pip 都不用装」 |

## 边界：这页不做什么

- **不把合成数据当学情结论。** 班级数据是合成的，任何「B 班更差」的读法都是错的；页面在页脚、徽标、口径页三处声明，且在 I3 里明确写出这个混淆。
- **不做账号与权限。** 单人本地看板，没有后端也就没有越权面；代价是不能多人协作。
- **不做实时。** 数据是快照（2026-11-15），刷新要重跑管线；实时化需要平台提供接口，不在本次范围。
- **不评价学生。** 分数是评审人给的，看板只做汇总与归因；「该做什么」一律指向流程改进，不指向个人。
