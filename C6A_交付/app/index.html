    口径

    C2G 的 50 条 commit 全部落在 1.8 小时内——这不是「迭代 50 次」，而是一次性推上去的。

    git 时间为什么不能当提交时间

    • 推送 ≠ 完成。本地写一周，最后 push 一次，commit 时间只记录最后一次。
    • 改写历史会重写时间。rebase / squash 之后，时间线是假的。
    • 时区差 8 小时。GitHub 返回 UTC，直接和本地 23:59 的截止时间比，会把「按时」判成「迟交」。

    所以班级看板的提交时间一律取自平台「提交事件」，而不是 git——这一条写在口径页第 3 个坑里。
