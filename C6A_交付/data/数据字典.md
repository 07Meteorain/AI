## 二、清洗规则（`clean()` 的六步）

| 步骤 | 规则 | 本次命中 | 为什么 |
| --- | --- | --- | --- |
| 1 | 剔除 `status == "withdrawn"` | 18 | 撤回不算已交，也不算未交 |
| 2 | 只保留在册在读学生 | 0（生成时已排除） | 退课/免修不进分母 |
| 3 | UTC 时间统一换算到 +08:00 | 2 | 差 8 小时能翻转迟交判定 |
| 4 | 姓名 `strip()` | 3 | 否则按姓名搜索会漏 |
| 5 | 同 (学生, 挑战) 保留 `attempt_no` 最大的一条（并列取最晚） | 82 | 平台导出是一行一次事件，直接 count 会把「改了三遍」算成三份 |
| 6 | 总分与分项不符时按分项重算 | 3 | 平台历史权重与现行 rubric 不一致 |

611 − 18（撤回）− 82（重复） = **511**（净数据）。每一步都在 `meta.log` 里计数，可核对。

## 三、指标定义（10 条）

> 约定：`submitted` 指「有效提交」（净数据行），`roster` 指在册在读学生。

### 1. 应交份数 expected

- **公式**：`len(roster) × len(challenges)` = 106 × 6 = **636**
- **分母**：它本身就是分母
- **边界**：退课/免修不计入；跨班重修只算一次
- **为什么不换**：分母写死，提交率才能跨挑战比较

```python
expected = sum(1 for s in students if s["status"] == "在读") * len(CHALLENGES)
# pandas: (df_roster.query("status == '在读'").student_id.nunique()) * df_challenges.challenge_id.nunique()
```

### 2. 有效提交 submitted

- **公式**：`count(clean_rows)` = **511**
- **边界**：撤回剔除；重复只留最后一条；`attempt_no` 用于算迭代，不参与计数
- **口径影响**：直接用原始 611 行会把提交率报到 96.1%

```python
submitted = len(clean_rows)
# pandas: len(df.sort_values("attempt_no").drop_duplicates(["student_id", "challenge_id"], keep="last"))
```

### 3. 提交率 rate

- **公式**：`submitted / expected` = 511 / 636 = **80.3%**
- **分母**：636（在册在读 × 6）
- **边界**：进行中的 C6 也在分母里，所以它天然低于「只算已截止」的 89.6%
- **替代口径**：只算 C1–C5 → **89.6%**；分母含退课 → **72.2%**

```python
rate = submitted / expected
```

### 4. 按时提交 onTime

- **公式**：`submitted_at <= deadline(challenge)`，**两侧都必须带 +08:00 时区**
- **边界**：UTC 记录先换算；`23:59:59` 算按时，`次日 00:00:00` 算迟交
- **本次**：409 份，占应交 **64.3%**

```python
from datetime import datetime
on_time = sum(1 for r in clean if datetime.fromisoformat(r["submitted_at"]) <= deadline[r["challenge_id"]])
# pandas: (df.submitted_at <= df.deadline).sum()
```

### 5. 迟交 late

- **公式**：`submitted_at > deadline` → **102** 份（占已交 20.0%）
- **边界**：迟交仍算已交；**不能并入未交**（否则完成率从 80.3% 掉到 64.3%）
- **小时数**：`late_hours = (submitted_at - deadline) / 3600`

```python
late = [r for r in clean if datetime.fromisoformat(r["submitted_at"]) > deadline[r["challenge_id"]]]
```

### 6. 平均分 avg

- **公式**：`mean(total)`，**分母 = 已评审份数（476）** → **74.4**
- **边界**：待评审（35 份）不进分母；未交更不是 0 分
- **反例**：待评审按 0 分计入 → 69.3（−5.1 分）

```python
scores = [r["total"] for r in clean if r["total"] is not None]
avg = sum(scores) / len(scores)
# pandas: df.loc[df.total.notna(), "total"].mean()
```

### 7. 中位分 median

- **公式**：`median(total)` = **74.1**
- **边界**：偶数个取中间两值均值；子群体样本 < 20 时中位数不稳定，需标注 n
- **为什么主用**：C5 复盘维度是双峰（41.9% 在 80+、52.3% 在 55–80），均值会落在「谁都不在」的位置

```python
import statistics
median = statistics.median(scores)
```

### 8. 红旗 redFlag

- **公式**：`缺 README / 缺 demo / 缺数据 / 缺 AI 日志`，任一命中计 1 份 → **254 份（49.7%）**
- **边界**：同一份可命中多条，红旗率按「份」计不按「条」计
- **分布**：缺 demo 24.3%、缺 AI 日志 20.4%、缺数据 11.0%、缺 README 3.9%

```python
flags = []
if not r["has_demo"]: flags.append("缺 demo")
# 四项同理；flag_count = len(flags)
```

### 9. 一次通过率 passRate

- **公式**：`从未被退回的记录数 / 有效提交` = **86.5%**
- **边界**：被退回后重交成功，仍算「非一次通过」
- **为什么不用提交率代替**：它衡量返工成本，提交率衡量参与度

```python
one_pass = sum(1 for r in clean if r["attempts"] == 1 and r["status"] != "returned")
pass_rate = one_pass / submitted
```

### 10. 评审人效应 reviewerEffect

- **公式**：按 `reviewer` 分组的总分均值差；本次极差 **7.2 分**（77.1 / 69.9 / 75.9）
- **边界**：评审人与班级约 88% 绑定 → 班级差（6.0）与评审人差（7.2）不可分；同一评审人跨班极差仅 **2.5 分**
- **识别策略**：需要随机交叉分派 + 双评，观察性数据只能给「不能下结论」的结论

```python
by_reviewer = {}
for r in clean:
    if r["total"] is not None:
        by_reviewer.setdefault(r["reviewer"], []).append(r["total"])
spread = max(map(statistics.fmean, by_reviewer.values())) - min(map(statistics.fmean, by_reviewer.values()))
# pandas: df.groupby("reviewer").total.mean()
```

## 四、真实数据（`self_commits.json`）字段

| 字段 | 含义 | 口径注意 |
| --- | --- | --- |
| `folder` | 仓库一级目录 | 13 个交付 + `.github` |
| `commits` | 该目录的 commit 数（≤100） | 是推送次数，不是迭代次数 |
| `first_commit` / `last_commit` | 首/末 commit 时间（+08:00） | GitHub 原始为 UTC，已换算 |
| `span_hours` | 末 − 首（小时） | 用于识别「一次性推送」 |
| `files` / `kb` | 文件数与体积 | 来自 git tree，非估算 |
| `squashed` | `commits ≥ 5 且 span ≤ 4h` | 启发式判定，不是事实断言 |
