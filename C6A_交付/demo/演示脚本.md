# 演示脚本 · 3 分钟带看

> 用途：评审自看、或录屏/会议带看。
> 时长：约 3 分（按下面的节奏念）。所有截图在 [截图/](截图/)，动态版本见 [walkthrough.gif](walkthrough.gif)。
> 开场白一句：**「这次不讲我做了什么图，讲这张表能回答哪七个问题、每个数字怎么来的。」**

---

## 场景 0 ｜ 打开（10 秒）

- **动作**：双击 `app/index.html`（或说：不需要装任何东西，数据已经编进页面）。
- **画面**：深色首屏，六个 KPI，右上角「合成数据 · seed 20260717」。
- **台词**：「先说数据的性质：班级这层是合成的，seed 固定，谁重跑都一样；真的一层在最后一页。」

对应截图：[01-总览.png](截图/01-总览.png)

---

## 场景 1 ｜ 首屏六个数字（25 秒）

- **动作**：鼠标依次划过「提交率」「按时率」「迟交」「待评审」的问号。
- **画面**：悬停提示里出现分子/分母。
- **台词**：「提交率 80.3%，分母是 106 位在读 × 6 个挑战 = 636。按时率 64.3% 用的是同一个分母，所以两个数可以直接比。迟交 102 份，占已交的 20%，但它既不算未交、也不算按时，是第三种状态。待评审 35 份不进均分——缺失不是 0 分。」

**如果只能记住一句**：这个看板里每个比率都带分母。

---

## 场景 2 ｜ 时间线：作业是怎么堆到截止日的（30 秒）

- **动作**：指时间线，再指「各挑战完成度」。
- **画面**：五个尖峰正好压在 C1–C5 的红色虚线上；10/25 那天 52 份。
- **台词**：「48.5% 的提交落在截止前 24 小时。这不是学生懒，是评审流量的形状问题——如果评审排班是『截止后集中三天』，那三天要看的量是平时的十几倍。所以第一条建议是排期，不是催交。」

对应截图：[01-总览.png](截图/01-总览.png)

## 场景 3 ｜ 洞察：结论怎么被证据绑住（45 秒）

- **动作**：切到「洞察」，停在 I3。
- **画面**：卡片三段式：证据格（6.0 / 7.2 / 2.5）、注意、该做什么。
- **台词**：「A/B/C 班均分差 6.0 分，很容易写成『B 班最差』。但三位评审人的均分本身就差 7.2 分，而同一位评审人打三个班只差 2.5 分——班差基本被评审人的宽严解释掉了。所以这条的结论是『不能下结论』，措施是下期随机交叉分派、双评。」
- **动作**：点卡片右下角「应用到看板 →」。
- **画面**：跳回总览，筛选栏变成「挑战 C5」。
- **台词**：「结论不是死的，点一下就回到数据里。」

对应截图：[02-洞察.png](截图/02-洞察.png)

## 场景 4 ｜ 下钻到一个人（30 秒）

- **动作**：切「学生」，默认按总分升序；点第一行「详情」。
- **画面**：右侧抽屉：6 个挑战的状态与分数、5 个维度对比班级中位、自动生成的建议。
- **台词**：「列表默认把最低分放最前，因为管理场景关心的是『先找谁』。抽屉里能看到这个人哪次迟交、缺了什么、哪一维低于班中位。建议只写流程动作——补 demo、改排期——不写『该生需要加强 XX』，那不是看板该下的判断。」

## 场景 5 ｜ 口径页：这一页才是骨架（35 秒）

- **动作**：切「口径」，从上往下扫。
- **画面**：10 个指标表 → 三种分母并排 → 五类脏数据 → 6 个坑。
- **台词**：「同一批数据，提交率可以报 89.6、80.3、72.2，差别全在分母。右边这张表是 611 行到 511 行：18 条撤回、82 条重复、2 条时区、3 条总分对不上、3 条姓名带空格。每一步都有计数，重跑一次还是这些数。」
- **补一句**：「下面六条坑是这次真踩过的，包括 git 时间不能当提交时间、时区能翻转迟交判定。」

## 场景 6 ｜ 真实数据收尾（20 秒）

- **动作**：切「真实数据」。
- **画面**：13 个交付目录、93 条 commit、1320 个文件；C2G 那一行标着「疑似一次性推送」。
- **台词**：「这层是真的，可以在 GitHub 上逐条核对。C2G 的 50 条 commit 全挤在 1.84 小时内——这就是为什么我们不用 git 时间判迟交：那是推送时间，不是完成时间。」

## 收尾（10 秒）

- **动作**：按 `T` 切浅色，再按 `1` 回总览。
- **台词**：「浅色给投影用，键盘 1–5 切页、`/` 搜索。整套东西零依赖、无后端、无埋点，clone 下来双击就能开。」

## 常见追问与回答

| 追问 | 回答 |
| --- | --- |
| 数据是真的吗？ | 班级层是合成的（seed 20260717，人物虚构），真实层是本人仓库的 13 个目录，可在 GitHub 核对。两层在界面上分区，不混算。 |
| 为什么不用 ECharts？ | 为了「双击即开」：任何 CDN 或本地库都会把交付变成「先装环境」。8 张图不需要复杂交互，手写 SVG 够用。 |
| 班级差的结论可靠吗？ | 不可靠，所以 I3 写的是「不能下结论」——评审人与班级 88% 绑定，需要随机交叉分派才能识别。 |
| 迟交真的不影响分数？ | 在「不扣分」的前提下不相关（r=0.02）。如果课程按天扣分，结论会变——这条写进了敏感性分析。 |
| 为什么学生表默认升序？ | 管理场景先找需要干预的人；想看优秀的有筛选和排序。 |
