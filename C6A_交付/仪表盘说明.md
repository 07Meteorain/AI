# 仪表盘说明 · 为什么长这样

> 这份文件讲设计，不讲功能清单。功能见 [README](../README.md)，口径见 [口径与陷阱](口径与陷阱.md)。
> 一句话主张：**看板的每个像素都该回答一个问题，否则就该删掉。**

---

## 一、信息架构：五个视图，一条动线

```
总览  →  出了什么事（6 个 KPI + 8 张图，10 秒内能看出哪里不对）
洞察  →  为什么、能信吗、该做什么（7 条结论，每条带证据/注意/行动）
学生  →  是谁（可排序、可筛选、可下钻到个人）
口径  →  这些数字怎么算的（10 个指标 + 三种分母 + 五类脏数据 + 6 个坑）
真实数据 →  哪一层是真的（本人 13 个交付目录，可逐条核对）
```

这个顺序是刻意的：**先结论、再归因、再个体、最后方法，真实数据压轴**。评审读前三个视图需要 3 分钟，读完后两个才知道该不该信。

另一条动线是**横向的**：任何一张图都能点、任何一条洞察都能「应用到看板」、任何一个学生都能开抽屉。三者共用同一个 `state`，筛选是全局的，不存在「图变了但表没变」。

## 二、八张图，各自回答一个问题

| 图 | 回答的问题 | 为什么用这个形式 | 被否掉的形式 |
| --- | --- | --- | --- |
| 提交时间线（堆叠柱） | 什么时候交的？峰值在哪？ | 时间是连续的，柱高＝当天量；按时/迟交堆叠，一眼看出「截止日尖峰」 | 折线图（会掩盖单日尖峰）、饼图（时间不能用饼） |
| 各挑战完成度（横条）+ 分母 | 哪个挑战掉队了？ | 6 个分类、标签是文字，横条最省空间；条上标 `38/106` 与 `%` | 竖向柱（类别名要斜着放）、仪表盘（信息密度太低） |
| 总分分布（直方图） | 分数是正态还是偏？ | 看形状；这里是右偏（60–69 有 140 份，90+ 只有 10 份） | 只给均值（会掩盖双峰） |
| 五维度（中位 + IQR） | 哪个维度整体偏弱？ | 中位＋四分位区间，比均值更能抵抗长尾；条上标权重 | 雷达图（面积会骗人，5 维也不适合雷达） |
| 交付物缺口（横条） | 缺什么最要命？ | 4 个缺件项、按份计；比例条 | 堆叠 100%（缺件可叠加，堆叠会误导） |
| 班级 × 评审人（柱 + 菱形） | 班差是真的吗？ | 柱是班级均分，菱形是该班主评审人均分——两者贴合＝班差其实是笔差 | 只画班级柱（会把评审人效应藏起来） |
| 迟交 vs 按时（分组柱） | 迟交真的更差吗？ | 五个维度两组对比；两组几乎同高，视觉上直接否定「迟交＝差」 | 只报「迟交组均分」（一个数字说不清） |
| 三种分母（横条） | 同一个数能报几个版本？ | 89.6 / 80.3 / 72.2 并排，落差本身就是论据 | 文字叙述（读者感受不到 17pp 的差） |

**共同约定**：所有图的纵轴从 0 开始（分数图从 40 起，但明确标注，且只用于形状比较）；不使用双 Y 轴；不用 3D；颜色只表达三件事——青＝按时/正常、琥珀＝迟交/警告、红＝未交/红旗。

## 三、口径不是一个页面，是一层设计

大多数看板把「数据字典」放在文档里，读者看不到。这里把它做成三处：

1. **KPI 的问号**：悬停即见分子、分母、边界；
2. **图表的「口径」角标**：每张图右上角的虚线小标签；
3. **口径页**：10 个指标 × 4 列（公式/分母/边界/为什么），加上三种分母对照、五类脏数据处理、6 个坑。

为什么值得花这么多版面：**分母换一层，结论就能反过来**。这份数据里提交率可以是 89.6%、80.3%、72.2%，均分可以是 74.4 或 69.3——不写清楚，看板就是在制造幻觉。

## 四、交互：三条原则

| 原则 | 做法 | 反例（刻意没做） |
| --- | --- | --- |
| 筛选是全局的 | 挑战 / 班级 / 状态 / 搜索四组条件共用一份 `state`，任何视图都跟着变 | 每个图各带一套筛选器（容易互相对不上） |
| 结论能下钻 | 洞察卡片上的「应用到看板」把筛选推回总览；点挑战条＝按该挑战筛选 | 洞察只是静态文字 |
| 不打断阅读 | 抽屉从右侧滑出，列表不跳位；`Esc` 关闭；不弹模态框 | 点击行后整页跳转（丢失上下文） |

另外做了三件小事：深链（`#students?c=C6&k=A&s=late&open=2025…&theme=light`，截图脚本与复现都靠它）、CSV 导出（当前视图，带 BOM，Excel 直接开）、键盘（`1`–`5` 切页、`/` 搜索、`T` 切主题、`Esc` 关闭）。

## 五、为什么手写 SVG

三个候选：ECharts（好看但 1MB＋，要 CDN）、Chart.js（要 canvas，导出/无障碍都更麻烦）、手写（~300 行工具函数）。

选第三个的理由不是「炫技」，是三条硬约束：

1. **双击即开**：数据编进 `data.js`，图表是 DOM，`file://` 下不触发任何跨域限制；
2. **可主题化**：SVG 的 `fill` 直接吃 CSS 变量，深浅主题只改 `:root`，不用重绘；
3. **可被读屏与测试**：图表元素带 `data-tip`，鼠标与触屏都能拿到同样的信息；`svg` 有 `role="img"`。

代价是动画与交互要自己写（tooltip、hover、点击），换来的是一份没有任何依赖的交付物——评审不需要 `npm install` 就能看到全部效果。

## 六、视觉系统

- **两套主题**：深色为主（长时间看数据不刺眼），浅色用于投影/打印；只换 CSS 变量，不换结构。
- **数字字体**：所有数字用 `tabular-nums` 等宽对齐，表格与 KPI 不会因位数不同而跳动。
- **层级**：一屏内最多两级对比（KPI 数值 > 图表 > 注释），注释一律 11.5px 灰字。
- **状态色只用于状态**：青/琥珀/红只表示按时/迟交/未交与红旗，不用来做装饰；紫色只用于「分布类」图表（直方图、维度条），避免和状态色混淆。
- **响应式**：≤1280px 时 6 列 KPI 降为 3 列、两栏图表变单栏；≤760px 时 KPI 两列、搜索框占满整行。

## 七、可访问性与性能

- 跳转链接（skip link）、`aria-live` 的作用域描述、`aria-pressed` 的筛选按钮、抽屉的 `aria-hidden` 同步；
- 焦点可见（`focus-visible` 描边），`prefers-reduced-motion` 下关闭全部过渡；
- 首屏无网络请求；`data.js` 约 300KB（511 行 × 24 字段），DOM 只渲染当前页 25 行，切换视图不重排全表；
- 图表在窗口 resize 时防抖 160ms 重绘。

## 八、明确没做的

| 没做 | 原因 |
| --- | --- |
| 登录 / 权限 | 单机看板，没有后端也就没有数据边界问题；真实场景下这会是第一优先级 |
| 实时刷新 | 需要平台接口；当前是快照，刷新＝重跑管线 |
| 预测（谁会迟交） | 511 行、6 个挑战，做预测只会过拟合；先把口径和归因做扎实 |
| 动画过渡 | 数据看板里动效多数时候是干扰；只在抽屉与提示上保留 120–220ms 的位移 |
