# 演示脚本 · PromptGate

> 目标：**3 分钟内**让人相信这是一个能用的产品，而不是一个能跑的 demo。
> 全程只用一个浏览器窗口，不需要装任何东西。

---

## 0. 准备

- 打开 <https://07meteorain.github.io/AI/>
- 或者双击 `app/index.html`（离线、`file://` 都能跑）
- 屏幕宽度建议 ≥ 1200px；想顺便看响应式，把窗口拖到 480px

---

## 1. 首屏：先看「正常态」（20 秒）

**操作**：什么都不做，先看 3 秒。

**看到**：
- 左上角 `PROMPT 16 行 · 764 字符 · ~505 token`… 不，首屏是**合格样例**，统计栏显示的是这段样例的行数与 token
- 右上角绿色 **✓ PASS** + `100/100` + 「没有发现问题，可以上线」
- 左侧编辑器：`# 角色 / # 任务 / # 输出格式 / # 示例 / # 边界`，`{{ticket_text}}` 被 `<<< >>>` 包住
- 底部变量条：`{{ticket_text}} ×1` + 「渲染预览」

**话术**：一个检查工具最容易被忽略的是「合格长什么样」。首屏直接给一份通过的样例，用户才知道合格线在哪。

---

## 2. 反面教材：让 17 条问题一次出现（60 秒）

**操作**：点右上「模板」→ 选「反面教材：17 条命中，覆盖 13 条规则」。

**看到**：
- 徽章瞬间变红 **✗ FAIL**，健康分 `0/100`，文案「门禁未通过：5 个 error / 9 个 warning」
- 右侧筛选条：`全部 17 / error 5 / warning 9 / info 3 / 已忽略 0`
- 问题卡片按行号排好：第 3 行命中两处凭据、第 6 行两条互斥指令、第 7 行注入短语、第 12 行超长单行、第 15 行未闭合围栏
- 左侧行号槽：命中的行带红/黄/蓝小圆点，**扫一眼就知道问题集中在哪几行**

**点一下**「第 3 行 ↑」：
- 编辑器光标跳到第 3 行并选中整行
- 这就是「报告」和「编辑器」之间的最短路径，不需要自己数行号

**展开**某条问题的「为什么这是问题」：
- 说明为什么这是问题（不是复述规则名），并给出改法

---

## 3. 改一行，看门禁翻转（30 秒）

**操作**：把第 3 行 `api_key = sk-live-2f9a8…` 改成 `api_key = {{api_key}}`。

**看到**：
- error 从 5 降到 3（PG004 的两条命中消失）
- 顶部文案实时变化（150ms 防抖，不是每敲一个字都重算）

**再操作**：点「规则」页 → 关掉 `PG004`。

**看到**：
- 顶部立刻回到 PASS？不一定 —— 但「已忽略」计数 +1，点进去能看到 `PG004 已被加入基线/规则已关闭`。
- **重点**：被关掉的规则不是消失了，而是被记录成「主动排除」。这是 review 时最需要的信息。

---

## 4. 预算：一个 prompt 的月度成本差 24 倍（30 秒）

**操作**：点「预算」。

**看到**：
- `GPT-4o mini` 一行标绿「最省」：单次 `$0.00056`，月度 `$3.33`
- `Claude Sonnet 4.5` 月度 `$81.09`，「最贵差 24.3 倍」
- 假设可改：每次输出 token、每天调用次数、计费天数
- 勾「允许编辑价格」→ 价格变成输入框，可以填自己谈的折扣价
- 下方「token 花在哪里」按小节降序列出；本工程的「诚实边界」也在这一页最底部

**话术**：成本是产品决策，不是账单问题。写 prompt 的时候就知道「换一个模型能省 24 倍」，比月底看账单有用。

---

## 5. 版本 + diff：让「改好了」有证据（30 秒）

**操作**：
1. 在编辑器里随意改两行
2. 按 `Ctrl/⌘+S`（或到「版本」页点「保存版本」），输入说明「加上输出格式约束」
3. 再改一处，再存一版
4. 点第一版的「对比当前」

**看到**：
- 版本列表：每版带 `PASS/FAIL` 徽章、时间、token 数、`5e/9w` 计数
- diff 视图只有改动附近的行，`+`/`-` 着色，行号对齐

---

## 6. 导出：产物是给机器吃的（20 秒）

**操作**：点「导出 ▾」→ `Markdown 报告`。

**看到**：下载 `promptgate-YYYYMMDD-HHMM.md`，内含：

| 段落 | 内容 |
| --- | --- |
| 结论表 | 结论、健康分、各级计数、变量数、规模、生成时间、工具版本 |
| 命中问题 | 级别 / 规则号 / 行号 / 问题 / 建议（竖线已转义，不会破表） |
| 已忽略 | 哪些被基线或开关排除，原因是什么 |
| 变量契约 | 每个变量的出现次数与行号 |
| 成本预算 | 8 个模型的单次/月度成本 + 价格快照日期 |

再点一次 `SARIF 2.1.0`：这是 GitHub Code Scanning 能直接上传的格式，不是自娱自乐的 JSON。

---

## 7. 命令行：同一套引擎（20 秒）

```bash
node tools/promptgate-cli.js app/js/core/samples.js
node tools/promptgate-cli.js prompt.md --fail-on warning --format sarif --out report.sarif
echo "总结这份会议记录。" | node tools/promptgate-cli.js -
```

完整实跑记录见 [cli-演示输出.txt](cli-演示输出.txt)，退出码语义：

| 退出码 | 含义 |
| --- | --- |
| 0 | 通过 |
| 1 | 被门禁拦下 |
| 2 | 用法/IO 错误 |

**为什么要区分 2 和 1**：CI 里「工具挂了」和「代码不合格」是两件事，混在一起会让人开始忽略红灯。

**复现截图**（Windows）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\shots.ps1
```

脚本会把 `app/` 复制到 `%TEMP%` 的 ASCII 路径再截图，原因有两个，都写进了脚本注释：

1. headless 浏览器对含中文的 `file://` 路径传参会失败（实测 Edge 会直接不加载页面）；
2. 复制到干净目录才能保证每次都是空 `localStorage`，截图可复现。

> 另一个实测坑：Windows 上 headless Edge 的 `--window-size` 有最小宽度（约 474 CSS px），
> 传 430 会得到一张「右侧被裁」的图。所以窄屏截图统一用 474px，而不是 390px。

## 一句话收尾

> 这个产品的价值不在「发现 17 个问题」，而在**把 17 个问题变成 17 条可定位、可解释、可导出、可回归的记录**。
> 没有这套东西，prompt review 就是两个人对着一屏文字说「我觉得还行」。
