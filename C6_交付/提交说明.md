## 四、评分维度自评（对应 rubric）

> 自评只写「证据在哪」，不写「应该给我多少分」。

### 产品完成度（25）

- **完整闭环**：贴入 → 体检 → 定位 → 修复建议 → 导出报告 → 存版本，没有断点。
- **有正常态**：首屏是 PASS 的合格样例，不是一个空编辑器。空态也有解释文案。
- **有防错**：清空/恢复/载入模板都会 confirm；存储不可用会提示；配额满会退回内存而不是丢数据。
- **有亮点**：变量渲染预览、成本预算（8 模型可改价）、基线指纹不含行号、SARIF 导出、PWA 离线。
- 截图见 [demo/截图/](demo/截图/)。

### 技术实现（20）

- 11 个 core 模块全是纯函数，`report.buildReport()` 是唯一结论入口，UI 只做渲染。
- 131 项测试零依赖（`node:test`），含 XSS 回归、文档漂移、资源存在性、CLI 退出码。
- 零第三方依赖、零构建步骤：`git clone` 后双击即用。
- Git 提交按主题拆分（core 引擎 → UI → 测试 → 文档 → 部署），见仓库提交历史。

### 产物完整性（15）

- 本文件 + [README](README.md) + [AI日志](AI日志.md) + [AAR](AAR复盘.md) + [拿来说明](拿来说明.md) + [CHANGELOG](CHANGELOG.md) + [规则手册](docs/rules.md)。
- 三种入口（file:// / http / CLI）都验证过；线上 app 链接可访问。
- 演示脚本写的是「点哪里、看到什么」，不是「功能介绍」。

### AI 使用质量（20）

- [AI日志.md](AI日志.md) 记录了 12 轮，包含：每轮 Prompt 原文、AI 给出的方案、我为什么改、改完的结果。
- [AI日志.md](AI日志.md) 逐条记录了 **17 处 AI 出错**（BOM 事故、类名冲突、window-size 误判、storage 回退 bug、CLI `-` 参数、exit 截断、规则重复、SINGLE_BRACE 误算、空 prompt 噪音、忽略按钮静默失效……），其中 **12 处是自动化验证先发现的**，不是我看代码看出来的。
- 工作流是设计过的：**先纯逻辑 → 再测试 → 再 UI → 截图回归 → 文档自动生成**，不是一次性生成。

### 复盘质量（20）

- AAR 四段齐全（预期/实际、做对了什么、失败经验 F1–F8、改进方案），F 项有三条明确写「未解决」。
- 有一个「五个为什么」的分诊实例（为什么移动端截图右侧被裁），最后定位到测量方法错误而不是布局错误。
- 改进方案带可验证指标（例如「误报率 < 5%」「首屏 LCP < 1s」），不是「以后注意」。

## 六、已知缺口（主动申报）

1. **没有真实用户**。所有体验判断来自自用；上线后第一件事应该是加埋点（AAR §5 有具体指标）。
2. **规则靠关键词**，PG002/003/012/013/014 会漏检也会误报，边界写在 `docs/rules.md` 末尾。
3. **token 是估算**（±20%），价格是 2026-11-01 快照。
4. **版本只存本地**，不跨设备、上限 20 条。
5. **移动端隐藏行号槽**，牺牲了「点行号跳转」。
