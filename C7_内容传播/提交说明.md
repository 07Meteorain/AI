## 三、评审阅读顺序（约 15 分钟）

1. **先看结论**：`README.md` 的「30 秒验收」表（2 分钟）
2. **看内容**：双击 `app/index.html` → 「阅读」页（5 分钟，或直接读 `文章/正文.md`）
3. **看标题功夫**：`文章/标题库.md` §五「人工否决」（这是最能看出判断力的一段）
4. **看数据**：`数据/screenshots/` 6 张图 + `数据/指标口径.md`（哪些是实测、哪些是推演）
5. **看过程**：`AI日志.md` 的「失败与修正」列 + `AAR复盘.md` §3
6. **验一遍**：`node --test tests/*.test.js`（47 项）+ `python tools/*.py --check`

## 四、我做得不够的地方（不希望评审靠猜）

| 问题 | 现状 | 为什么没做 |
| --- | --- | --- |
| 没有线上传播数据 | 全部是推演值，参数公开 | 尚未发布；AAR 里给了回收模板与两次回收时点（24h / 7d） |
| 没做真正的 A/B | 只做了样本量测算，结论"做不了" | 860 曝光 vs 每臂 3,531 需求，只有 12%，硬做只能得到噪声 |
| 短视频/直播渠道缺失 | 明确写"不做" | 需要视频制作能力，不在本次范围，写清边界比硬凑诚实 |
| 截图是脚本画的，不是浏览器截屏 | 用 Pillow 手绘坐标系 | 要的是"可复算"，浏览器截图无法在 CI 里稳定复现；但这也意味着图不是"线上后台"的样子（图里已标注"推演"） |
| `app` 里的数据是编译时快照 | 改 CSV 要重跑 `gen_data_js.py` | `file://` 下 `fetch` 被拦，只能把数据编译进 JS；用 `--check` 兜住过期风险 |

## 五、复现全部产物（一条命令一位）

```bash
python tools/title_score.py     # 标题评分 → CSV / Markdown / JS fixture
python tools/chartgen.py        # 6 张数据截图 + 数据指纹
python tools/gen_data_js.py     # app 数据包
python tools/build_article.py   # 公众号 HTML + app 静态资源（依赖 C4B 的 wechat_publisher）
node --test tests/*.test.js     # 47 项
```

依赖：Python ≥ 3.10（标准库 + Pillow；`build_article.py` 复用 C4B 的转换器，需要 `markdown` `beautifulsoup4` `lxml`），Node ≥ 18（无第三方包）。
