# 文章标题

> 交付物之一。这里有 32 条候选、一套公开的评分规则、一个被否决的"最高分标题"，以及最终选择。

## 一、为什么标题要单独立项

公众号的点击发生在列表页：读者看到的只有一张封面和一行标题。正文写得再好，标题输了就是 0 阅读。

所以我没让 AI"想 5 个标题挑一个好看的"，而是做了一件更笨的事：

1. 先定 **5 种可命名的公式**（数字型 / 反差型 / 悬念型 / 身份型 / 方法论型），每种 6 条；
2. 把"好标题"拆成 **5 个可打分的维度**，写进 `数据/title_rubric.json`；
3. 用脚本给 32 条全量打分（`tools/title_score.py`）；
4. **人工评审有一票否决权**——这一条后面救了这篇文章。

## 二、五个公式

| 公式 | 它在赌什么 | 例子 |
| --- | --- | --- |
| A 数字型 | 具体数字 = 可信 + 可预期 | 「131 个测试里最重要的那一条叫「合格样例零命中」」 |
| B 反差型 | 反直觉 = 好奇心 | 「工具的第一版不是用来抓错的，是用来不冤枉人的」 |
| C 悬念型 | 提问 = 缺口效应 | 「AI 编的参考文献，格式为什么能一条不错？」 |
| D 身份型 | 明确人群 = 精准点击 | 「写给独立开发者：AI 交付的验收课」 |
| E 方法论型 | 可收藏 = 长尾 | 「验收的三层：能跑、能复算、能截图」 |

## 三、评分口径（满分 100）

| 维度 | 满分 | 它在量什么 |
| --- | ---: | --- |
| 钩子强度 | 25 | 数字、疑问、反差、强判断、代价词 |
| 具体性 | 20 | 数字密度、领域术语、具体产物 |
| 检索性 | 15 | 平台搜索与话题页能命中几个关键词 |
| 平台适配 | 20 | 公众号 16–24 字最佳；标题党词重扣 |
| 可信度 | 20 | 夸张承诺、绝对化、无依据倍数词扣分 |

**一票否决**：标题里出现「震惊 / 必看 / 99% / 绝对 / 史上最」这类词，总分直接封顶 40，评级强制为"弃用"——不给辩解空间，就像真实的编辑台。

规则全部在 [`数据/title_rubric.json`](../数据/title_rubric.json) 里，改规则不用改两套代码；Python 与 JS 两侧的一致性由 `tests/titlescore-parity.test.js` 逐条对齐（32 条候选，分数必须完全相同）。

## 五、最终发的不是第 1 名（这一节是本文最想让人看的部分）

**发布用的是第 5 名 A2（75 分），比第 1 名低 2 分。**

如果只看分数，这件事说不通。下面是四条否决理由，逐条对应"评分器量不到的东西"。

### ① 否掉 B1（第 2 名）：「90%」是我编的

B1 是全表钩子最强的一条（16/25，A2 只有 12），也最像会被点开的标题。

但这篇文章全篇在骂"AI 编了一个格式合法的数字"，而标题里的 90% 没有任何出处——我没有计时记录，也没有对照组。

> 用一个我抓了一整年的错误，去换一次点击，这篇文章就自我否定了。

评分器抓不到这个问题：`credibility` 维度是**词表匹配**，能识别"震惊 / 必看 / 99%"，识别不了"伪精确的百分比"。

### ② 否掉 E4（第 1 名）：标题承诺比正文多

「从 C1 到 C6：一个人怎么把 AI 协作做成流水线」——读者点进来期待的是**六关全景**，而正文只讲"验收"这一条线。

**标题承诺 > 正文供给，是最伤信任的错配。** 评分器没有"标题与正文一致性"这个维度，它只看标题本身。

### ③ 否掉 D6（第 3 名）：「3 个坑」把方法论降级成故事会

D6 钩子很强（16/25），但"我踩过的 3 个坑"承诺的是段子，正文真正想给的是可操作的方法（三层 + 12 条清单）。**形式吸引来的读者，会因为内容不是段子而走掉。**

### ④ 否掉 A6（第 4 名）：它承诺了一个我并没有的流程

「12 条验收清单，我每份交付物上线前都过一遍」——很具体、很有说服力，但这是**善意的谎言**：清单第 11 条（写清工具做不到什么）我自己也经常跳过。

> 夸张的标题会被读者发现，一句"我每次都做"的谎言会让读者发现得更晚、更伤。

### 为什么是 A2

| 判据 | A2 的表现 |
| --- | --- |
| 每个数字都能核验 | 127 次提交、464 项测试，都能在 `master@165f7d3` 上数出来 |
| 承诺与正文一一对应 | 「三条硬结论」= 正文第六节的三个结论（为了兑现这条，我把原来的结尾改写成显式的三条） |
| 没有不可兑现的自我标榜 | 不承诺"我每次都在做"，只承诺"这是我的结论" |
| 检索性 | 覆盖「验收」「测试」两个关键词，长尾可搜 |

**结论：评分器负责排序，人负责判断"这条我能不能兑现"。** 反过来（人排序、机器判断）两个都会更差——机器判断不了"我有没有这个流程"，人也排不出 32 条的可比分数。

## 六、A/B 实验：设计完了，但决定不做

原本计划 A2 与 B1 各投一半流量，测点击率。算完样本量之后放弃：

| 项目 | 数值 |
| --- | --- |
| 假设点击率 | A 9% / B 11% |
| 每臂所需样本（α=0.05，power=0.8） | 3,531 |
| 首篇可用曝光（每臂） | 430 |
| 结论 | 只有所需量的 12%，**不可判定** |

硬做的话，得到的最可能是一个 0.4 的 p 值和一个自我感觉良好的故事。所以换成：三条标题按周轮换、主指标改为转发率与收藏率。详见 [`数据/screenshots/04_AB显著性.png`](../数据/screenshots/04_AB显著性.png)。
