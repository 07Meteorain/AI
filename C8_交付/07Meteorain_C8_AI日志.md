## 第 1 轮：环境与输入勘察（AI 出错 3 次）

```text
$ pwsh -Command "echo hi"
[exit code: 3221225794]        # 0xC0000142，进程创建失败

$ pwsh -Command "echo hi"   # 提权到 danger-full-access 后
hi
```

| 事故 | 现象 | 处理 |
| --- | --- | --- |
| E1 | 沙箱模式下 `pwsh` 连续 4 次 `0xC0000142` | 判断是沙箱进程创建失败，改用全权限重试 → 成功。**没有把「命令跑不了」当成「命令错了」** |
| E2 | `git-credential-manager get <<< ...` 语法报错 | PowerShell 不支持 bash here-string，改用管道 `"...`n" | git credential fill` |
| E3 | 控制台中文输出乱码 | 编码是 GBK；每次命令前设 `[Console]::OutputEncoding = UTF8` + `PYTHONIOENCODING=utf-8` |

同时确认了三件事实（都不是猜的）：

- git 凭据可用：`git credential fill` 返回 `username=07Meteorain`，40 位 token；`git push --dry-run` 成功；
- 仓库是公开的、有 1331 个受版本控制的文件、13 个 `C*` 目录；
- 平台 11 份 `challenge.json` 里的 `required_deliverables` 有 **4 种写法**（星号模糊 / 精确文件名 / 中文 / 英文）。

## 第 3 轮：设计（三层结构，写下来再写代码）

```text
① 交付物层（客观）：平台 40 条要求 → 有没有文件、是不是 0 字节
② 维度层（启发式）：每维度拆 3–5 条可观察信号，每条带权重与证据路径
③ 红旗层（规则）  ：照抄平台三条红旗，命中即封顶，不做加权稀释
```

两个设计决定当场定下：

- **不用 LLM**：同一份仓库两次运行必须给出同样结论。LLM 做不到可复现，这条不能让步。
- **不生成分数排名**：分数只做「该补什么」的定位信号，报告里反复声明「不是成绩」。

## 可复用的 Prompt / 指令模板（沉淀）

```text
1) 开工前：「先不要写代码。列出这个任务的全部输入文件，读完再给我三个可能的方案和各自代价。」
2) 实现后：「在真实数据上跑一遍，把每一条结论对应的原始文件路径列出来。哪些结论你无法验证？」
3) 复核时：「找出你自己最有可能是错的 3 个判断，并给出反驳它的方法。」
4) 收尾时：「这份交付换一台机器、换一个人，第一步会卡在哪里？」
```

第 3 条是本次最有效的：**让 AI 主动列出自己可能错的地方**，比让它「再检查一遍」有效得多。
