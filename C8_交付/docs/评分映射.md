# 评分映射表（维度 → 证据 → 权重）

> 这张表是 [`submitgate/profiles.py`](../submitgate/profiles.py) 与 [`submitgate/checks.py`](../submitgate/checks.py) 的镜像。
> 权重是「同一维度内各信号的相对比重」，维度得分 = `max_points × Σ(通过权重) / Σ(计分权重)`，再按红旗封顶。
> 标记为「需人工」的维度不计 0 分、不进分子分母（覆盖率单列）。

## 一、23 个维度 id 的归属

| 维度 id | 中文 | 证据类别 | 为什么这样归 |
| --- | --- | --- | --- |
| `artifactCompleteness` | 产物完整性 | `artifact` | 必需交付物 + README + 可运行入口，全部可查 |
| `aiUsage` | AI使用质量 | `ai` | 日志存在性、轮次、prompt 原文、失败记录 |
| `reflectionQuality` | 复盘质量 | `reflection` | AAR 存在性、四问覆盖、数字、失败小节、改进方案 |
| `delivery` | 交付质量 | `delivery` | 必需交付物齐全 + 验收记录 + 提交说明 + 按时 |
| `problemSolving` | 问题解决 | `problem` | 测试/演示/证据 + 可复现命令 + 定位与修复记录 |
| `initiative` | 自驱力 | `docs` | 没有文件级代理指标（选题价值需人判断） |
| `participationQuality` | 参与质量 | `docs` | 群内参与只能看「有没有记录」，看不到真实性 |
| `substance` | 内容实质 | `docs` | 含金量需人读 |
| `collaboration` | 协作贡献 | `collab` | 协作记录 / 互评 / 迁移笔记 |
| `skillTransfer` | 技能迁移 | `transfer` | 迁移笔记 / 互教记录 / 互检 |
| `repoQuality` | 仓库质量 | `repo` | README / LICENSE / tests / CI / docs |
| `community` | 社区要素 | `community` | Issue 模板 / PR 模板 / 贡献指南 / 准则 / 安全 / CHANGELOG |
| `fundamentals` | 基础掌握 | `gitpractice` | Git 实战记录 + 证据文件 |
| `technicalExecution` | 技术实现 | `engineering` | 测试 / 入口 / 文档 / CI |
| `productQuality` | 产品完成度 | `product` | 应用入口 / 在线链接 / 演示 / 截图 |
| `dataInsight` | 数据洞察 | `data` | 数据文件 / 分析报告 / 看板 |
| `visualization` | 可视化 | `data` | 同上（看板与图表） |
| `contentQuality` | 内容质量 | `content` | 正文 / 选题标题 / 数据截图 |
| `distribution` | 传播设计 | `content` | 发布链接与截图 |
| `systemArchitecture` | 系统架构 | `docs` | 架构文档（文件名/标题点名） |
| `memorySystem` | 记忆系统 | `docs` | 同上 |
| `mastery` | 驾驭程度 | `docs` | 安装/配置文档 + 结论 |
| `integration` | 集成质量 | `docs` | 同上 |

未登记的维度：先按关键词兜底（完整性→artifact、复盘→reflection、仓库→repo…），仍无匹配 → `docs`。
`docs` 类若连「被点名的文档」都没有，该维度标 **需人工**。

## 二、各证据类别的检查项与权重

### `artifact`（产物完整性）

| 检查项 | 权重 | 判定 |
| --- | --- | --- |
| 必需交付物：`<名称>` | 2 / 条 | 命中且非 0 字节 |
| README 存在 | 2 | ≥400 字符 |
| README 有安装/使用小节 | 1 | 标题含 安装/使用/快速开始/验证/上手/运行/开发 |
| 有可运行入口 | 2 | 任一路径段为 `tests`/`test`，或存在 `__main__.py`/`pyproject.toml`/`package.json` 等 |
| 必需交付物总体量 | 1 | ≥4096 字节 |

> 若该挑战**没有** `delivery` 类维度，`acceptance`(1.5) / `submit_note`(1) / `on_time`(1) 并入本类别（权重减半）。

### `delivery`（交付质量）

| 检查项 | 权重 | 判定 |
| --- | --- | --- |
| 必需交付物齐全 | 4 | 全部命中 |
| 有验收记录 | 3 | 路径含 验收/acceptance 的文件或目录 |
| 有提交说明 | 2 | 文件名含 提交说明/交付说明/submission/提交清单 |
| 按时交付 | 2 | `git log -1 --format=%cI -- <目录>` ≤ deadline；无 git → 未验证 |

### `problem`（问题解决）

| 检查项 | 权重 | 判定 |
| --- | --- | --- |
| 验证证据 | 4 | `tests/` `demo/` `证据/` 或 测试结果/验证报告 类文件 |
| README 含可复现命令 | 3 | 代码块里出现 python/node/pip/git 等 |
| 记录了问题定位与修复 | 3 | 文档中「根因/定位/原因」≥1 且「修复/解决/修正」≥1 |

### `ai`（AI 使用）

| 检查项 | 权重 | 判定 |
| --- | --- | --- |
| AI 日志存在 | 3 | 文件名含 AI日志/AI使用日志/ailog |
| 有迭代证据 | 4 | 轮次 ≥3（含中文数字），或 prompt ≥2 且失败记录 ≥2 |
| 含 prompt 原文 | 3 | 代码块数或引用块数 ≥2 |
| 含失败/返工记录 | 3 | 命中 失败/出错/翻车/返工/纠正/bug/fail 等 ≥1 |
| 日志体量 | 2 | ≥2000 字符 |

### `reflection`（复盘）

| 检查项 | 权重 | 判定 |
| --- | --- | --- |
| AAR 存在 | 4 | 文件名含 aar/复盘/反思 |
| 覆盖复盘要素 | 4 | 预期/实际/做对/失败/改进/教训/根因 ≥3 类 |
| 含具体数字 | 2 | ≥3 个不同数字 |
| 有失败经验小节 | 2 | 标题含 失败/教训/做错/没达到/踩坑/fail/lesson |
| 有改进方案 | 3 | 标题含 改进/下一步/重来/清单/计划/下次/next/improve，且含列表或命令块 |

### 目录证据类（`repo` / `community` / `engineering` / `product` / `data` / `content` / `collab` / `transfer` / `gitpractice`）

每条证据项权重 1，按「找到/没找到」计：

| 类别 | 证据项 |
| --- | --- |
| `repo` | README、LICENSE、测试目录、CI 工作流、文档目录 |
| `community` | Issue 模板、PR 模板、贡献指南、行为准则、安全策略、变更日志 |
| `engineering` | 测试、入口或依赖清单、文档、CI 工作流 |
| `product` | 应用入口、在线链接、演示材料、截图 |
| `data` | 数据文件、分析报告、看板或图表 |
| `content` | 正文、选题或标题、数据截图 |
| `collab` | 协作记录、互评或评审、迁移或教学笔记 |
| `transfer` | 迁移笔记、互教或教学记录、评审或互检 |
| `gitpractice` | 实战记录、证据文件 |

> **CI 的例外**：GitHub 只认仓库根的 `.github/workflows/`，因此查找 CI 时会额外扫描仓库根，
> 按挑战编号前缀匹配（如 `c6-ci.yml`）。C6 的「技术实现」正是靠这条才没有被误判。

### `docs`（只能人工）

| 检查项 | 权重 | 判定 |
| --- | --- | --- |
| 相关文档被点名 | 1 | 文件名含维度关键词，或标题里命中 ≥2 个关键词 |
| 文档有实际内容 | 2 | ≥800 字符、模板痕迹（待填/TODO/占位）≤1、表格 ≥3 行或 ≥1500 字符 |

两条都无候选 → 该维度标「需人工」，不计分。

## 三、计分与封顶

```
维度得分 = round(max_points × Σ(通过权重) / Σ(计分权重))
若红旗命中且该维度得分 > maxScore：得分 = maxScore（capped = true）
挑战可验证分 = Σ(可验证维度得分)
挑战可验证满分 = Σ(可验证维度满分)
```

红旗 | 触发 | 封顶对象
--- | --- | ---
`missing_artifacts` | 任一必需交付物缺失/为空 | `artifactCompleteness` → 5
`no_ai_log` | 无任何 AI 日志 | `reflectionQuality` → 5
`one_shot_ai` | 迭代证据不足（轮次 <3 且（prompt <2 或失败 <2）），或 prompt <2 | `aiUsage` → 5

## 四、这张表的边界

1. 权重是**经验值**，来源是本次 10 个真实误判的调参过程，不是平台给的。
2. 证据类别只看「文件存在与命名」，不看内容质量。
3. 23 个 id 是硬编码的；平台新增维度需要加一行映射，否则落关键词兜底。
4. 本文与代码可能漂移：`tests/test_docs_consistency.py` 会检查每个维度 id 是否出现在本文件中。
