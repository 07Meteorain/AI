## 0. 一句话

**输入**一个装着 Markdown 笔记的文件夹，**输出**一个能每天告诉你「今天该复习哪几张」的本地卡组；
每张卡都能追到原文的文件与行号，且人在复习前有权逐张剔除。

---

## 1. 为什么是这个问题

### 1.1 个人证据（不是想象出来的需求）

- 本仓库已有 **33 篇**课程译文，约 **12.9 万字**（`C1_交付/translations/`）；
- 另有 C2–C6 六个挑战的交付文档，累计数十万字；
- 这些内容我「读过」，但被问到时经常只能复述标题。重读带来的是熟悉感，不是可提取的记忆；
- 手工做卡的成本实测：一篇 3,000 字文章做 15 张卡约 30 分钟。按 33 篇算，是 16 小时——
  一个几乎必然被放弃的投入。

### 1.2 真实需求的三条判据

1. **必须足够便宜**：从「想复习」到「开始复习」不能超过 1 分钟，否则不会发生；
2. **必须可追溯**：自动生成的东西如果不知道来自哪一句，错了我也不敢删；
3. **必须能否决**：机器判断「值得学」的准确率不可能 100%，人需要一条低成本的剔除路径。

### 1.3 为什么不是又一个「AI 总结器」

让 LLM 直接总结成问答对，看起来最省事，但它同时引入三个问题：
不可离线、不可回归（同样的输入两次输出不同）、不可追溯（答案可能不在原文里）。
Recall 选择确定性规则：**宁可少出，也不出无法核对来源的卡**。
LLM 在这个项目里的角色是「实现者」，不是「运行时依赖」。

## 2. 目标用户与场景

| 用户 | 场景 | 关键诉求 |
| --- | --- | --- |
| 主要：我自己 | 每周读完 3–5 篇技术文章后，把笔记变成 20 张卡 | 快、可审核、不装东西 |
| 次要：同学/自学者 | 课程资料太多，复习时不知道从哪开始 | 今天该复习什么，一页说清 |
| 再次：写技术笔记的人 | 已有 Markdown 笔记，想复用而不是重写 | 不绑定 Obsidian/Notion |

**非目标用户**：需要多端同步、协作、移动 App、Anki 生态插件的重度用户。
这些需求真实存在，但不在本次范围内——把边界写清楚，比假装全能更有用。

## 3. 现有方案与差异

| 方案 | 优点 | 对本场景的问题 |
| --- | --- | --- |
| Anki | 成熟、跨端、算法好 | 手工制卡；客户端重；卡片与笔记源脱节 |
| RemNote / Obsidian 插件 | 笔记与卡片同源 | 绑定编辑器；插件质量参差；需要学习成本 |
| LLM 一键生成问答 | 快 | 不可离线、不可回归、来源不可核；容易编造 |
| 自己写脚本 | 完全可控 | 每次重写；没有排程与审核闭环 |

**Recall 的差异点**：确定性抽取 + 行号溯源 + 审核闭环 + 零依赖离线。
它不试图替代 Anki 的生态，只解决「从笔记到第一版卡组」这段最容易被放弃的路。

## 4. 范围

### 做

- Markdown 解析：标题层级、段落、列表、引用、代码、表格；
- 五类卡片：标题提问、术语列表、行内定义、显式问答、填空；
- 质量门与拒绝原因统计；
- SQLite 存储、SM-2 排程、leech 暂停；
- CLI：build / review / stats / sample / apply / web / export / doctor / selfcheck；
- 离线 Web：复习、审核、统计；localStorage；决定导出；
- 128 项 Python 测试 + 120 项浏览器断言；
- 真实语料压测与 30 张抽样审核。

### 不做（明确划掉）

- PDF/HTML/Notion 导入；
- 云同步、账号、协作；
- LLM 运行时调用（不做「AI 自动判分」）；
- FSRS 参数拟合、移动端 App、Anki 导入导出；
- 多语言分词（只做中英文长度与术语判断）。

**没有达到的自我要求**（写在这里，不藏到 AAR 里）：

- 原计划「请一位人类同学抽检 20 张」。实际只由 AI 自己抽检 30 张，缺人类基线；
- 原计划「连续使用 7 天，记录每日到期曲线」。实际只有单日会话，没有长期留存数据；

这三条不是「忘了」，是时间与资源约束下的主动取舍；代价写在 AAR §3 与 §6。

## 9. 变更记录（提案 vs 实际）

| 变更 | 原计划 | 实际 | 原因 |
| --- | --- | --- | --- |
| 卡片类型 | 4 类 | 5 类（加「填空」） | C1 语料里加粗术语多，填空是最高性价比的补充 |
| 默认审核 | 全部 candidate | 默认 approved + 可剔除 | 开箱即用；审核变成「第二道闸」而非「第一道门槛」 |
| 诊断命令 | 无 | 增加 `doctor` | C1 只出 62 张（改规则前），需要解释「为什么」 |
| 调度算法 | 考虑 FSRS-5 | SM-2 | 无法确认权重来源与版本，宁可用可手算的公开规格 |
| 交付时间 | 计划 6 小时 | 约 2.5 小时 | 零依赖 + 先纯逻辑后界面，返工少 |
