# 3 分钟演示脚本

> 评审者可以按这个顺序看，不需要先读代码。

## 0:00–0:30｜它是什么

打开 [`../README.md`](../README.md) 前 40 行：

> 一条命令，把 Markdown 笔记编译成「可审核、可排程、可离线复习」的卡片。

看第一张图 [`截图/01-复习.png`](截图/01-复习.png)：问题、来源行号、翻面、四档评分。

## 0:30–1:10｜跑起来

```bash
cd C9_交付
python -m recall selfcheck
python -m recall build examples/notes --db /tmp/demo.db
python -m recall review --db /tmp/demo.db --limit 5 --script 4,3,2,4,3 --today 2026-11-15
```

预期：10 个 PASS、27 张卡、一轮复习摘要。
完整输出见 [`终端演示.txt`](终端演示.txt)。

## 1:10–1:40｜真实数据

```bash
python -m recall stats --db demo/c1.db --today 2026-11-15
```

> 107 张（标题提问 56 / 填空 51），来自 33 篇 / 12.9 万字。

然后看 [`c1-抽样审核.md`](c1-抽样审核.md) 最后 8 行：

> 可用 86.7%，但值得学只有 60.0%。

**这是整个项目最重要的一张表**：它解释了为什么产品必须是「候选 + 审核」。

## 1:40–2:20｜离线页面

```bash
python -m recall web --db demo/recall.db --out site
```

双击 `site/index.html`：

1. 复习页：空格翻面，1–4 评分，进度条；
2. 审核页：保留 / 剔除，导出决定；
3. 统计页：总量、到期、类型分布、未来 7 天。

截图：[复习](截图/01-复习.png) · [审核](截图/02-审核.png) · [统计](截图/03-统计.png) · [移动端](截图/04-移动端.png)。

## 2:20–2:50｜工程证据

```bash
python -m unittest discover -s tests        # 128 项
msedge --headless=new --virtual-time-budget=3000 \
  --dump-dom site/selftest.html | findstr data-result   # PASS，120/120
```

- Python 128 项，测试文件 7 个；
- 浏览器 120 条断言，验证 JS 与 Python 的 SM-2 逐字段一致；
- 16 处开发期缺陷，全部记录在 [AI日志](../07Meteorain_C9_AI日志.md) §3。

## 2:50–3:00｜边界

翻到 README 的「诚实边界」：

> 86.7% 可用，但只有 60% 值得学；没有人类基线；没有长期留存数据；输入形态敏感。

**如果只有 30 秒**：看 `01-复习.png` + `c1-抽样审核.md` 的最后 8 行。
