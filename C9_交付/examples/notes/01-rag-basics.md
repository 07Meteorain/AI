# 检索增强生成（RAG）入门

> 这是一篇用于演示 Recall 抽取规则的示例笔记，内容为原创。

## RAG 是什么？

RAG（Retrieval-Augmented Generation，检索增强生成）是一种把**外部知识检索**接进生成流程的做法：模型在回答之前，先从文档库里取回相关片段，再基于这些片段组织答案。它解决的不是「模型会不会说话」，而是「模型说的话有没有依据」。

与微调相比，RAG 的更新成本低得多：知识变了就重建索引，不需要重新训练模型。代价是系统多了一条检索链路，任何一个环节出错都会反映在最终答案里。

## 一条完整的 RAG 链路

- **切分（Chunking）**：把长文档拆成大小合适、语义完整的片段，片段太大噪音多，太小则丢上下文。
- **嵌入（Embedding）**：把每个片段映射成向量，使语义相近的文本在向量空间里距离更近。
- **召回（Retrieval）**：用问题向量在索引里找最相近的若干片段，常用余弦相似度排序。
- **重排（Rerank）**：用更贵的模型对候选片段重新打分，把真正相关的几条提到前面。
- **生成（Generation）**：把选中的片段和问题一起交给模型，要求它只依据给定材料回答。

## 为什么要做检索，而不是把文档全塞进上下文？

把全部文档塞进上下文看起来最省事，但会遇到三个硬约束：上下文窗口有上限；长上下文里的信息会被稀释，模型更容易漏掉关键句；每次请求都携带全部文档，成本和延迟都不可接受。检索的本质是**在有限预算内提高信息密度**。

## 常见失败模式

**召回失败**是指正确的片段根本没有被检索到。它通常不是模型的问题，而是切分粒度、嵌入模型或查询改写出了问题。

**上下文冲突**是指检索到的多个片段互相矛盾，模型却把它们都当成事实。这时需要在提示里要求模型指出冲突，或先做去重与时间过滤。

**引用错位**是指答案引用了并不支持该结论的片段。它比答错更危险，因为读者会以为答案有据可查。

## 如何评估一个 RAG 系统？

评估要拆成两段：先看检索，再看生成。检索段常用 Recall@k 与 MRR；生成段常用忠实度（答案是否只依据给定材料）与答案相关性。只看最终答案的「感觉对不对」，无法定位问题出在哪一段。

## 一个最小示例

```python
def retrieve(question: str, index, k: int = 5):
    vector = embed(question)
    return index.search(vector, k)
```

| 指标 | 衡量什么 | 典型阈值 |
| --- | --- | --- |
| Recall@5 | 正确片段是否进入前 5 | ≥ 0.8 |
| 忠实度 | 答案是否被材料支持 | ≥ 0.9 |

问：RAG 能解决模型幻觉吗？
答：不能完全解决。它让答案有材料可依据，从而降低幻觉概率，但检索失败或材料本身错误时，模型仍可能给出错误答案。
