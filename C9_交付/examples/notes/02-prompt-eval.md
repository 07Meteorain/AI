# Prompt 评测的最小闭环

## 为什么不能靠「感觉」改 prompt？

改完 prompt 觉得「好像更好了」，是最常见的自欺。模型的输出有随机性，一次变好可能只是采样运气；没有固定样本、固定评分标准和版本记录，改动就无法归因。评测闭环的作用是把「感觉」换成「同一批题、同一把尺子、可重复的分数」。

## 一个闭环由四件事组成

- **评测集**：一组有代表性的输入，覆盖正常路径与边界情况，并保留一份不参与调参的留出集。
- **评分器**：把输出变成分数的规则，可以是精确匹配、结构化断言，或另一个模型的判定。
- **基线**：当前线上版本的分数，没有基线就没有「变好」。
- **回归门**：新版本必须在评测集上不低于基线，才允许上线。

## 评分的三种粒度

**精确匹配**要求输出与标准答案逐字一致，适合分类、抽取、格式固定的任务，误判率低但对措辞敏感。

**结构化断言**检查输出是否满足可程序化的条件，例如必须包含某个字段、数值落在区间内、引用的文件真实存在。

**模型评审**让另一个模型按评分细则打分，适合开放式回答，但必须固定评审 prompt 与模型版本，否则分数本身会漂移。

## 样本量要多大？

样本量不是越多越好。先用 30 到 50 条覆盖主要失败模式，能稳定复现问题后再扩。把 200 条随机样本跑一遍却不分类，通常不如 30 条精心构造的边界样本有信息量。

问：评测集可以反复用来调 prompt 吗？
答：可以调，但必须留出。反复在同一个集合上试错，分数会虚高；留出集只在版本定稿时跑一次。

## 记录什么

每次实验至少记录四样东西：prompt 版本、评测集版本、评分器版本、分数。少任何一样，两周后就无法解释「为什么当时选了这个版本」。
